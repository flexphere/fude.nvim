## 目的
レビュー中に、コードや diff について AI（claude）に質問できる場所を Neovim の中に持つ。今は別のターミナルで claude を開き、対象のファイルや行を手で伝え直す必要がある。レビュー対象（PR / ローカルレビューのブランチ）ごとに会話が続き、エディタで選択した範囲をそのまま質問に添えられれば、うまくいったと言える。

## 利用者
fude.nvim でレビューする人（GitHub レビュー・ローカルレビューの両方）。diff を読みながら「この変更の意図は」「この関数の呼び出し元は」と尋ねる場面、選択したコードについて質問する場面で使う。

## スコープ外
- claude 以外のエージェント（設定で差し替えられる形にはしない。`chat.cmd` は claude 互換のコマンドのパスを変えるためのもの）
- ファイルを編集させること（既定では許可しない。設定で許可した場合の動作は保証しない）
- diff や開いているファイルの内容を自動で添付すること（必要なら claude が自分で読むか、`:FudeReviewChatAdd` で貼る）
- 1 つのレビュー対象に複数のセッションを持つこと、過去のセッションを選び直すこと
- AI の応答をレビューコメントとして投稿すること
- レビューモードの外でのチャット
- claude 自身のセッションログ（`~/.claude/projects/`）を読むこと

## 制約
- コマンドは `commands.lua` のレジストリに足す（`plugin/fude.lua` には足さない）。
- 純粋関数（引数の組み立て、stream-json の行のパース、貼り付けテキスト・プロンプトの作成、保存形式の変換）は副作用のあるコードと分け、命名規則（`build_*` / `parse_*` / `format_*` …）に従う。
- 変更する状態は `config.state` に置き、CLAUDE.md の State Dependencies 表を更新する（`make check-state-deps`）。
- 外部プロセスは `vim.system()` で非同期に起動し、UI の更新は `vim.schedule()` を通す。コールバックは起動時の `config.state` と一致するかを確かめ、止めたあとのセッションに触れない。
- スピナーはバッファを書き換えずに描く（overview の `draw_spinner_frames` と同じ理由）。
- パネルのウィンドウは side panel と共存する（両方開ける）。side panel の「最後の通常ウィンドウ」判定や `files.open_file` のソースウィンドウ選びが、チャットのウィンドウを通常のウィンドウと見なさない。
- 下書き（`drafts.json`）の形式と既存コマンドの挙動は変えない。
- 依存は増やさない（Neovim >= 0.10 と claude CLI だけ）。
- テストは実際の claude を呼ばない（実行関数を差し替える）。
- README.md・doc/fude.txt・CLAUDE.md を更新する（`make check-docs`）。

## 確認方法
- 固定のテスト: `make all`
- この開発で足すテスト・手で確かめること:
  - Unit: 引数の組み立て、stream-json のパース、貼り付けテキスト、プロンプト、保存と復元
  - 結合: パネルの開閉と toggle、送信から逐次表示まで、キャンセル、失敗、レビュー停止時の後始末
  - 手動: 実際の claude で、質問 → 応答 → 再起動 → 継続、選択範囲の貼り付け、編集を頼んでも書き換わらないこと
