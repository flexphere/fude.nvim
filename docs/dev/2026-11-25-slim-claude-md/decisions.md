# 判断の記録: CLAUDE.md のスリム化と肥大化の再発防止

判断したその場で追記する。後から妥当性を検証できるように書く。

## D-001 詳細は消さずに docs/architecture/ へ移し、CLAUDE.md は要約にする

- 日時: 2026-11-25
- 段階: ヒアリング
- 重要度: 中（理由: 今後の全開発でのドキュメントの置き場所が変わる）
- 決めた人: ユーザー
- 背景: Module Responsibilities の約 135k 文字が上限超過の原因
- 選べた案:
  1. 要約＋詳細を別ファイルへ — 情報を失わない。置き場所が 2 つになる
  2. 要約のみ（詳細は削除） — 保守が最も軽いが「なぜ」の情報を失う
  3. すべて別ファイルへ（CLAUDE.md は索引のみ） — 最小だが全体像が CLAUDE.md だけでは分からない
- 決めたこと: 案 1
- 理由: 情報を保ったままコンテキストを減らせる
- 影響: CLAUDE.md、docs/architecture/、ドキュメント更新の規則
- 見直すきっかけ: docs/architecture/ が更新されず古くなっていく、または参照されない
- 関連: AC2, AC3

- 関連: AC1, AC5

## D-003 規則の書き換えと文字数検査の両方で再発を防ぐ

- 日時: 2026-11-25
- 段階: ヒアリング
- 重要度: 中（理由: make all / pre-commit / CI に検査が増える）
- 決めた人: ユーザー
- 背景: 「CLAUDE.md の Architecture を更新」の規則が肥大化の原因
- 選べた案: 1. ルール＋サイズ検査 2. ルールのみ 3. 何もしない
- 決めたこと: 案 1
- 理由: 規則だけでは守られなかった実績がある
- 影響: Makefile、pre-commit、CI、スキル群
- 見直すきっかけ: 検査が開発の妨げになる
- 関連: AC5, AC6
