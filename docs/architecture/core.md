# Core: commands, palette, lifecycle, config, util

Module details for `lua/fude/commands.lua`, `palette.lua`, `init.lua`, `config.lua`, `util.lua`. Moved verbatim from the former "Module Responsibilities" section of `CLAUDE.md`; update this file when these modules change.

Related details in other files: `drafts.lua` (the `:FudeReviewSubmit` body draft) is in `comments.md`; `overview.prefetch` is in `overview.md`; `scope.lua` / `stack.lua` / `files.lua`, which `init.lua` calls, are in `navigation.md`; the local session `init.stop()` delegates to is in `local-review.md`.

- **`commands.lua`** — Command registry, the single source of truth for every `:FudeXxx` user command. `M.list` holds one entry per command: `name`, `desc` (used as the command `desc` and the palette text), `category` (one of `M.CATEGORIES`: Session / Comments / Files / Scope / Review / View / PR), `available(state)` (whether the palette lists it for the given `config.state`: inactive → Start/Local/PR helpers (Create/Edit/EditReviewers/EditLabels/ChangePRState/URL commands), GitHub mode → also StackSwitch/Submit/Overview/React (`reactions.react_at_cursor`; local review comments have no reactions), local mode → also LocalScope/LocalBase, both review modes → Resolve (dispatched by `comments.toggle_resolve`) and Scope/ScopeNext/ScopePrev, since `scope.lua` dispatches them to the local session; `FudeReviewStop` covers both modes since `init.stop()` delegates to the local session, so there is no separate local stop command), `run(opts)` (the user-command callback), and optional `range`/`nargs`/`complete`/`palette` (`palette = false` hides an entry from `:FudeCommandPalette` while keeping it registered — used for the two Toggle commands, which Start/Stop already cover)/`repeatable` (`false` keeps the entry out of `:FudeCommandRepeat` — only the repeat itself). `register_all()` wraps every `run` so that `record(cmd, opts)` first stores `{ name, fargs, bang }` in the module-local `last_command` (not `config.state`, so it survives a review stop / start; `get_last()`, `_reset_last()` for tests); `:FudeCommandRepeat` (`range = true`, available always) runs `repeat_last(opts)`, which builds the `vim.cmd` table with the pure `build_repeat_cmd(last, range, takes_range)` — the range is never recorded, and the repeat's own range is forwarded only to an entry with `range = true` (looked up by `find(name)`) — and INFO-notifies when nothing ran yet. Command bodies that were inlined in `plugin/fude.lua` (`FudeReviewSubmit` flow, `get_pr_url`, the two display toggles) live here as local functions. The `FudeReviewSubmit` body input persists a local draft (kind `review`): it is prefilled from the draft, "Save draft & close" saves without submitting the review, "Discard & close" drops the draft and submits without a body (as `q` always did), closing an unedited restored draft (`cancel`, no prompt since it is not dirty) keeps it and does not submit — submitting would send the review without the saved body and then delete it — and a successful submit removes the draft via `drafts.remove_if_unchanged` (the input is closed by then, so a draft re-saved from a new `:FudeReviewSubmit` while the request is in flight survives). `register_all()` registers every entry with `nvim_create_user_command`. `scripts/check_docs.lua` extracts command names from this file (`name = "FudeXxx"`) in addition to `plugin/fude.lua`.
- **`palette.lua`** — `:FudeCommandPalette` command palette. Pure helpers: `rhs_invokes_command(rhs, name)` (does a mapping rhs run the command as its *first* Ex command — the rhs must start with an optional `<Esc>`, then `<Cmd>` or `:`, optional `<C-u>` / `'<,'>`, then the name followed by a non-identifier character; the wrapper is matched case-insensitively but the name exactly, since user commands are case-sensitive. Anchoring at the start, rather than scanning the rhs, is what rules out names inside string literals or after a `|` separator without an Ex parser; a mapping that runs the command only after `|` is deliberately not reported), `find_keymap_for_command(keymaps, name)` (first matching lhs; Lua-callback mappings have no rhs and are skipped), `build_palette_entries(cmds, state, keymaps, category_order?)` (filters by `available(state)` and `palette ~= false`, attaches the key, orders by category then registry order), `calculate_palette_widths(entries)` / `format_palette_entry(entry, widths)` (aligned `[Category]  desc  :Name  key` line for `vim.ui.select`; in Telescope/snacks the category is `Title`, the description normal, the name `Comment`, the key `Special`), `calculate_palette_layout(widths, count, columns, lines)` (absolute window size: widest row + padding, `count + 5` rows, clamped to the editor — Telescope uses it through `themes.get_dropdown`, snacks through the `select` preset, both without a preview pane so the palette stays a compact centered menu regardless of the user's picker defaults), `format_key_lhs(lhs, mapleader)` (restores the `<leader>` token that `nvim_get_keymap` expands). Side effects: `collect_keymaps(modes, buf)` (buffer-local then global mappings with lhs passed through `format_key_lhs`, skipping a global mapping whose lhs is shadowed by a buffer-local one; `x` mode is included when the palette was opened with a range), `execute(entry, ctx)` (runs the command via `vim.cmd({ cmd = name, range = ... })` from the window the palette was opened in, forwarding `ctx.range` only to `range = true` commands), `resolve_visual_range()` (when visual mode is still active — a `<Cmd>FudeCommandPalette<CR>` mapping passes no range — leaves visual mode and returns the `'<`/`'>` line range), `open(opts)` (`opts.range = { line1, line2 }` from `:'<,'>FudeCommandPalette`, else derived via `resolve_visual_range`; routes to `show_telescope` / `show_snacks` / `show_vim_select` by `file_list_mode`, with the same missing-plugin fallbacks as `scope.lua`).
- **`init.lua`** — Plugin lifecycle (`start`/`stop`/`toggle`/`reload`). On start: detects PR via `gh`, fetches changed files, comments, PR commits (for scope selection), and authenticated user (for edit/delete ownership), saves original HEAD SHA, sets up `BufLeave` (saves source views through `files.save_view`)/`BufEnter`/`WinClosed`/`GitSignsUpdate` autocmds, integrates with gitsigns (per-buffer base selection), applies diffopt settings, sets buffer-local keymaps (`]c`/`[c` for comment navigation, `]F`/`[F` for unviewed-file navigation — declared together in the module-local `BUF_KEYMAPS` table so `setup_buf_keymaps`/`clear_buf_keymaps` stay in step, each one skipped when its `config.opts.keymaps` entry is `false`; teardown deletes a mapping only when its callback is one of the `BUF_KEYMAPS` functions, not by the configured lhs or by `desc`, so a same-key mapping owned by an ftplugin in a buffer review mode never entered survives even if it copies fude's description text), starts the `overview.prefetch({ pr_info, on_ready })` background fetch of the `:FudeReviewOverview` data right after the PR info is set — the PR lookup (`gh.get_pr_info(cb, { with_overview = true })`) already asked for the overview's body fields on a branch, so its result is handed over as the body and no second `gh pr view` runs — and calls the `on_overview_ready({ pr_number, pr_url })` hook (scheduled, so after the rest of the start setup; once, on success, while the session is active) as soon as that body is cached, usually well before `on_review_start`, loads the review comments outside the start barrier (so `on_review_start` — and an overview it opens — does not wait for them; the side panel is refreshed when they land), and starts auto-reload timer if configured. `reload` re-fetches comments, changed files, viewed states, and PR commits in parallel with a completion barrier, and calls `overview.prefetch()` outside that barrier (its failure is silent and must not hold the reload). On stop: stops auto-reload timer, restores original HEAD if in commit scope — including a commit switch whose checkout ran but whose gh callback is still in flight (`scope.has_pending_commit_checkout()`), cancelling that switch via `scope.cancel_pending_switch()` so its late callback cannot act — tears everything down, removes buffer-local keymaps, and restores original state. `start()` refuses via `stack.refuse_while_switching()` while a `:FudeReviewStackSwitch` checkout is in flight. Exports helpers: `apply_gitsigns_base_for_buffer()` sets per-buffer gitsigns base (the full PR scope uses `merge_base_sha` for every file — added files too, since GitHub reports a file as added against the merge-base while the base branch tip may hold it, as for a merged PR — and `base_ref` only when no merge-base was computed, skipped when `gitsigns_reset` is true; in local review mode every file uses `merge_base_sha`, since each local scope resolves to one SHA and `base_ref` is the base *branch*, which may be nil or hold a same-named file; the buffer is mapped with `local/session.relative_path`, so a `:cd` out of the worktree does not skip every buffer); `compute_merge_base(base_ref)` computes and caches the merge-base SHA from two candidates — the merge-base with `state.base_sha` (the PR's `base.sha`, frozen at merge time once merged) and the one with `base_ref` — picked by the pure `find_fork_point(from_base_sha, from_base_ref, head_sha, is_ancestor)`: the later of the two (`diff.is_ancestor`), since `base.sha` may lag behind a base branch merged into the PR while a stale local base branch lags the other way, except that a `base_ref` merge-base equal to HEAD is dropped (the base branch already contains the PR — merged with a merge commit — and would empty every diff); a `base.sha` not available locally leaves only the `base_ref` one; `update_gitsigns_base(base_ref)` sets global gitsigns base (used for commit scope); `toggle_gitsigns()` toggles gitsigns between PR base and HEAD; `restore_gitsigns_base()` restores gitsigns to PR base display.
- **`config.lua`** — Holds `defaults`, merged `opts`, and mutable `state` (active flag, PR metadata, window/buffer handles, comments, pending_comments, pending_review_id, pr_node_id, viewed_files, github_user, namespace ID). `reset_state()` preserves the namespace ID.
- **`util.lua`** — Shared utility functions. `is_null(v)` checks for both `nil` and `vim.NIL` (JSON null compatibility across Neovim 0.11/0.12). `null_to(v, default)` replaces a JSON null with `default` (use it instead of the `and-or` idiom, which cannot map null to nil). `path_less(a, b)` compares paths byte by byte, the order git and the GitHub PR file list use (explicit loop, since PUC Lua's `<` uses locale-dependent `strcoll`); used by `local/session.build_changed_files`. `all_comments_resolved(comments)` checks whether every comment in a list is resolved (false for empty lists); shared by `comments/data.lua`, `ui/format.lua`, and `ui/extmarks.lua` so the "all resolved" rule stays consistent. `copy_to_clipboard(text)` sets `"` and, with a clipboard provider, `+` (never reading `+` back, which may block under OSC 52); returns whether `+` was set. Used by the side panel's `copy_path` and `pr.lua`'s error float `c`. `reset_selection_on_prompt_change(picker)` wraps a Telescope picker's `_do_selection` so that a refresh whose prompt differs from the previous one (`should_reset_selection(prompt, last_prompt)`, pure) selects the first row (`get_reset_row`) whatever `selection_strategy` is in effect, while a refresh with the same prompt keeps the picker's own strategy (the toggle picker's `follow`); every fude Telescope picker (files, scope, palette, stack, the `pr.lua` pickers, the toggle picker) goes through it before `:find()` — snacks.picker already starts again from the top on a new pattern (its matcher clears the list). `open_url(url, reason)` opens a URL with `vim.ui.open` (ERROR on failure) or, when `url` is nil, shows `reason` as an INFO, so a `url, reason` pair from `data.find_comment_url` / `sidepanel.build_scope_url` passes straight through; every `o` (open on GitHub) key uses it.
