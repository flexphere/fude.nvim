# lua/fude/reactions.lua

Comment reactions. Pure: `CONTENTS` (= `ui/format.REACTIONS`, GitHub's eight in web-UI order), `find_reaction_target(comment, ctx, repo_api_path)` → `path|nil, reason` (`<repo>/pulls/comments/<id>/reactions` for a comment with a `path`, else `issues/comments/<id>/reactions`; refused for no comment, local review (`ctx.is_local`), the viewer's pending review comments (`pull_request_review_id == ctx.pending_review_id`), review summaries and a non-numeric id), `build_rollup(list)` (a reactions listing → the REST `reactions` rollup shape), `find_pr_reaction_target(pr_info, ctx, repo_api_path)` (the PR itself: `<repo>/issues/<n>/reactions`; refused in local review and without a numeric number), `find_user_reactions(list, login)` (content → reaction id), `format_reaction_users(logins, limit?)` (`@a, @b, @c +2`, the first `DETAIL_USERS` (3) then `+N`), `format_reaction_detail(count, on, logins)` (`2 · @me, @alice · <Tab>: remove` / `<Tab>: add`, so every row says who reacted and what `<Tab>` does), `build_reaction_users(list)` (content → `find_reaction_users`), `build_reaction_items(counts, mine, users)` (`ui/toggle_picker` items `{ text = "👍 +1", on, value = content, detail }`, the detail re-read from the caller's live `counts` / `users` tables on every render, both refreshed by each re-list). `pick(comment, ctx, on_done)` (ctx from `ui.capture_open_context()`, repo from `drafts.repo_slug(ctx.pr_url)`) and `pick_pr(pr_info, ctx, on_done)` (repo from `pr_info.url`) both run the module-local `open_picker(path, target, on_done)`, which lists the reactions with `gh.get_reactions` and opens `ui/toggle_picker` (title `Reactions` with `confirm_label = "who reacted"`, so `(<Tab> toggle, <CR> who reacted)` is appended; the toggle picker's spinner marks a row while its request is in flight), whose `on_toggle` sends `gh.add_reaction` / `gh.remove_reaction` (the viewer's reaction id; `state.github_user` identifies it), then re-lists — updating `counts` and the viewer's ids in place, replacing `target.reactions` (the comment, or `pr_info`) with the fresh rollup (so `state.comments` and the overview cache follow) — before `done(true)` and `on_done(target)`; a failed add/remove reports `done(false)` so the row's mark comes back. Its `on_confirm` (`<CR>`) runs the module-local `show_people(item)` through `M.show_people(logins, title, on_pick, on_cancel)` — routed by `file_list_mode` (Telescope dropdown / snacks.picker `select` layout with `auto_confirm = false`, so a single user is shown rather than picked / `vim.ui.select` kind `fude_reaction_people`, also when the plugin is missing), `on_pick` for `<CR>` and `on_cancel` once for any other close (Telescope prompt `BufWipeout`, snacks `on_close`), both scheduled; title from the pure `build_people_prompt(text, count)` naming `<CR> copy username, <Esc> back to reactions` over the pure `find_reaction_users(list, content)` of the latest listing (kept current by each re-list); a pick copies the login with `util.copy_to_clipboard`, and a cancel — or a reaction nobody used — reopens the reaction picker with the same items. `+` is bound in the comment viewer (redraws the float in place via a local `rerender`), the comment browser's thread pane (`update_right_panes` when the entry is still shown) and the overview (a comment under the cursor → `pick` + `handle.set_comments`; anywhere else in the left pane and the whole right pane → `pick_pr` + `handle.refresh_left`, which rewrites the left pane from line 0 through the same module-local `rewrite_left(start)` as `set_comments`). `:FudeReviewReact` runs `react_at_cursor()`: a buffer registered with `set_buffer_handler(buf, fn)` (module-local `buffer_handlers`, dropped on `BufWipeout`) runs that function — the comment viewer, the browser's thread pane and both overview panes register the very function their `+` runs, so the command reuses the `open_ctx` and redraw those UIs captured when drawn; any other buffer needs an active session (else WARN) and takes the cursor line's comments (`diff.to_repo_relative` + `comments.get_comments_at`) through the pure `find_line_targets(comments, ctx)` → `comments|nil, reason` (only those `find_reaction_target` accepts; none → `No comments on this line` or the first comment's reason, INFO like `+`), opening `pick` at once for one and asking through `vim.ui.select` (kind `fude_reaction_target`, rows from the pure `format_comment_choice(comment)`: `@login: ` plus the first non-blank body line cut at `CHOICE_BODY_WIDTH`) for several. The PR's own reactions come from `reactionGroups` (in `gh.PR_OVERVIEW_FIELDS`), converted by the pure `ui/format.build_rollup_from_reaction_groups(groups)` (`THUMBS_UP` → `+1`, … via `REACTION_GROUP_CONTENTS`); `format.find_pr_reactions(pr_info)` prefers `pr_info.reactions` once `pick_pr` set it, and `build_overview_left_lines` shows them under the body. The reactions line itself comes from `ui/format.format_reactions(rollup)` (`👍 2  ❤️ 1`, nil without any), appended after each body by `format_comments_for_display`, `format_reply_comments_for_display` and `build_overview_left_lines` (blank line + reactions line in `REACTIONS_HL`, inside the comment's `comment_ranges`).
