# PR creation, editing and state changes

Module details for `lua/fude/pr.lua`. Moved verbatim from the former "Module Responsibilities" section of `CLAUDE.md`; update this file when these modules change.

Related details in other files: `drafts.lua` (kinds `pr_create` / `pr_edit`) and `completion/init.lua` (`attach_pr`) are in `comments.md`; the git helpers (`get_push_target`, `push_branch`, `get_remote_branches`, `get_ancestor_branches`, `get_gh_stack_parent`) are in `git.md`; the `gh.lua` calls are in `gh.md`; `ui.prompt_close_decision` is in `ui.md`; `util.copy_to_clipboard` / `reset_selection_on_prompt_change` are in `core.md`.

- **`pr.lua`** — PR creation, editing and state changes. `M.create()` creates draft PRs from templates: first shows a base branch picker (`select_base_branch`, entries from the pure `build_base_branch_entries(branches, default_branch, { current_branch, stack_parent, ancestors })` — default branch first with a `(default)` marker so a fresh `<CR>` accepts it (only when it is on the remote, or when there are no remote branches at all — `diff.get_default_branch` may fall back to a local-only `main`/`master`), then related branches (`(stack parent)` from `diff.get_gh_stack_parent`, then `(ancestor)` from `diff.get_ancestor_branches`; only those present on the remote, deduplicated), then the rest of `diff.get_remote_branches()` (newest commit first); the current branch is never listed; skipped with `base = nil` when there are no candidates, cancel aborts), then searches for `PULL_REQUEST_TEMPLATE` files in standard GitHub locations, shows Telescope picker when multiple templates exist (`select_template`; all pickers share the module-local `pick_entry`, Telescope when available else `vim.ui.select`, with the template preview passed lazily via `make_previewer`; the base branch and stack pickers pass `compact = true` for a dropdown sized by the pure `calculate_compact_picker_height`), and opens a two-pane float (title + body) for composing the PR. The chosen base decides the default title (`diff.get_first_commit_subject(base)`, which tries `origin/<base>` before the local ref so a stale local branch of the same name does not shift the commit range), is shown in the footer built by the pure `build_footer_text(mode, from_draft, base, stack)` (`<CR> create draft → main | q cancel`), and is forwarded as `opts.base` to `gh.create_draft_pr(title, body, attachments, base, cb)` (`--base` only when non-nil). Picking the default base asks nothing; any other base asks `confirm_stack(base, cb)` (a Yes/No picker through the shared `pick_entry`, entries from the pure `build_stack_choices()` with Yes first so a bare `<CR>` accepts it; cancel aborts); a Yes runs the module-local `resolve_stack` before the float opens: `gh.get_open_pr_stack(base)` (one GraphQL query for the open PRs of the branch ref, `repository.ref("refs/heads/<base>").associatedPullRequests` — the repo's own ref, so fork PRs sharing the branch name never appear and no result limit can hide the parent — and its `stack`, parsed by `gh.parse_open_pr_stack`; "no PR" is an empty result, not an error string; only explicit JSON null means no stack, while missing/partial stack membership yields a parse error propagated by `get_open_pr_stack`) — a parent PR at the top of a stack is stacked directly (below the top — decided from `stackEntry.position` vs `stack.size`, since a stack only grows at its top — asks `confirm_non_top_stack(base, top_branch, stack_number, cb)`, a compact picker from the pure `build_non_top_choices`: an ordinary PR on `base`, or a stacked PR on the stack's top branch from `gh.parse_stack_top`, which replaces `base`; cancel aborts), one in no stack starts a new stack without asking again (the user already answered Yes), and no open parent PR, a failed lookup, or incomplete parent/stack metadata aborts through `show_stack_error(err, pr_url?)` instead of creating an ordinary PR. On submit, the module-local `check_stack_target` runs `gh.check_stack_available(cb)` (`gh stack link --help`, then a read-only `GET /repos/{owner}/{repo}/stacks?per_page=1` capability probe, not an enumeration) and re-fetches the selected parent's PR/stack to reject a changed parent URL, parent base for a new stack, stack membership or top position before `gh.create_draft_pr`. A failed preflight keeps the saved creation draft and makes no PR mutation. Stacking sets `opts.stack = { parent_url, new_stack }`, which adds `(stacked)` or `(new stack)` to the footer and, after a successful create, runs the module-local `link_to_stack`: `gh.link_stack(refs, base, cb)` (`gh stack link`, independent of gh-stack's local tracking) with `{ <stack number>, new_url }` for an existing stack (append mode — without a stack number gh-stack's update mode requires every PR already in the stack and fails otherwise) or `{ parent_url, new_url }` plus `--base <parent's baseRefName>` for a new stack (gh-stack otherwise retargets the bottom PR to the default branch). The parent is passed as its PR URL, never a branch name, because `gh stack link` would push a branch argument and open a PR for it; a link failure calls `show_stack_error` with the created PR URL and does not close or delete the PR. The read-only error float distinguishes pre-creation cancellation from a failed link after creation, includes the error and (after creation) the PR URL plus a reminder to check GitHub before retrying, and shows a `q close | c copy | o open PR` footer when the URL is available (`o` calls `vim.ui.open` without dismissing the float). Pre-creation failures and successful create commands that returned no usable PR URL show only `q close | c copy`; the latter are reported as post-create failures instead of silently skipping the link or claiming success. It enters normal mode, uses clamped `float.width`/`float.height` and a visible border even for none/shadow, wraps long errors, and wipes its scratch buffer on close. Successful PR creation still clears only the submitted draft snapshot, even if the subsequent link fails, so retrying does not offer that PR as a new draft. Submits via `gh pr create --draft`. gh decides whether the branch is pushed: run without a terminal it aborts with "you must first push the current branch" when no remote-tracking ref is at HEAD, which the pure `is_unpushed_branch_error(err)` recognises. fude reacts to that error instead of predicting it, so the two never disagree. On it, the module-local `create_pr(retried)` reads `diff.get_push_target()` and, when `config.opts.pr.push_before_create` is true (default false, so nothing is pushed unless the user opts in), runs `push_and_retry`: `diff.push_branch`, then `create_pr(true)` once — a second unpushed error is reported like any other; a failed push opens `show_push_error(err, branch, remote, true)` and creates nothing, keeping the session draft. With the option false it opens `show_push_error(err, branch, nil, false)` (gh's error plus a pointer to the option). Any other gh error — auth, network, `--attach` on an old gh — and a detached HEAD (no push target) keep the ERROR notification with the `format_attach_error` hint. Both floats come from the pure `build_push_error_lines(err, branch, remote, push_enabled)` → `lines, highlights, title` and the module-local `open_error_float(lines, highlights, title, pr_url?)`, which `show_stack_error` also uses; `highlights` maps 1-based lines to `M.ERROR_HL` (`DiagnosticError`, the lines under the `Original Error:` header added by the module-local `append_error`) and `M.SUGGESTION_HL` (`DiagnosticWarn`, fude's what-to-do-next line), drawn as extmarks in the `fude_error_float` namespace. The float's footer comes from the pure `build_error_footer(can_open_pr)` (`q close | c copy`, plus `| o open PR` with a URL); `c` copies every line of the float to the unnamed register and, when `has("clipboard")`, to `+` — never reading `+` back, since with the OSC 52 provider that read is a terminal query that may block — and otherwise WARNs that only the unnamed register was set. When stacking, `check_stack_target` runs before the first `gh pr create`, so a failed preflight never reaches the push. `M.change_state()` (`:FudeChangePRState`) fetches the PR via `gh.get_pr_state` (the review session's PR when active, else the current branch's) and shows the shared `pick_entry` compact picker with only the transitions the pure `build_state_actions(state, is_draft)` allows (open draft → ready/close, open → draft/close, closed → reopen, merged/unknown → none, reported with an INFO instead of a picker), prompting with the pure `format_pr_state(state, is_draft)` (`open (draft)`), then applies the pick with `gh.set_pr_state`; refused with a WARN in the local commit scope (HEAD is detached onto a past commit, so the commit-based lookup could pick another PR containing it); no PR (`gh.is_no_pr_error`) is a WARN, any other lookup failure an ERROR. `M.edit()` edits existing PR title/body: uses `state.pr_number` when review mode is active, otherwise detects via `gh pr view`. `create`, `edit` and `change_state` are independent of review mode (`state.active`). Cancel confirmation: pressing `q` with unsaved title/body changes (dirty = `ui.should_confirm_discard` on either pane against the lines the float opened with) shows `ui.prompt_close_decision` with PR wording ("Unsaved PR:" / "Discard changes?"); create mode saves through `save_draft`/`get_draft`/`clear_draft`/`draft_revision` (each taking an optional key; `save_draft(title_lines, body_lines, key, target)` also stores the float's `{ base, stack }` as the entry's `meta` via `drafts.set`, read back by `get_draft` into `draft.target` through the pure `parse_create_draft_target(meta)`, which drops a malformed target as a whole so a resume never loses only the stack) to `drafts.json` under kind `pr_create`, keyed by the pure `build_create_draft_key(common_dir, branch)` (`git:<common git dir>:#<branch>:pr_create` — the common dir from `diff.get_git_common_dir` is shared by worktrees, and a PR is opened from a head branch) which `create()` resolves once and passes down as `opts.draft_key`, so the async submit cleanup targets the branch the flow started on; without a key (detached HEAD) or with drafts disabled it falls back to a session-local table; submit saves the input before `gh.create_draft_pr` so a failed creation (e.g. unpushed branch) keeps it; when the branch has a draft, `M.create()` asks via `confirm_draft_resume(draft, cb)` (compact `pick_entry`, entries from the pure `build_draft_resume_choices(draft)`) *before* the base picker whether to resume it with the saved target (`resume`, only when `draft.target` exists — straight into the float, `check_stack_target` still rechecks the stack on submit), resume it through the base picker (`rebase`: the module-local `create_from_base_picker` runs the base/stack pickers, then `create_with_base` opens the draft instead of a template; also the way out when the saved base or stack fails), or discard it and run the normal flow; the callback aborts with a WARN when `draft_revision` changed while the picker was open (an in-flight create may have cleared or replaced the draft); the template picker no longer lists the draft; on an unedited float opened from a draft (`from_draft` + `on_discard_draft` + `allow_draft`, create and edit mode alike) `q` asks with `RESTORED_DRAFT_CLOSE_CHOICES` (Keep draft & close / Discard draft & close / Keep editing) so a restored draft can be discarded without editing it first; edit mode persists to `drafts.json` via kind `pr_edit` (key from `drafts.make_draft_key` + `repo_slug` of the PR url fetched by `gh.get_pr_title_body` — state-independent; no slug → Yes/No fallback), serialized by the pure helpers `serialize_edit_draft(title_lines, body_lines)` (title on line 1, space-joined like `parse_pr_buffer`) / `parse_edit_draft(text)`, prefilled on the next `M.edit()` (footer shows "draft restored", dirty baseline = the restored draft) and removed on successful `gh.edit_pr` — unless a draft was explicitly saved while the request was in flight (the float stays open during the request; a flag, not content comparison, so re-saving identical content also survives). The create success path guards `clear_draft` the same way, comparing `draft_revision` before and after the request (the `drafts.revision` of the entry, or the fallback table's reference). Closing a float window directly (`:q` etc.) still discards without confirmation (WinClosed path). Body attachments: on submit, `parse_body_attachments(body, expand_fn)` (pure) extracts `file://`-scheme paths from inline markdown link/image destinations — bare or angle-bracket form (skipping ```/~~~ fenced code blocks via a fence-marker tracker that closes only on a bare same-marker line; paths may contain spaces and parentheses, while a path containing `#` — gh's alt-text separator — or `<`/`>` is left untouched), strips the `file://` prefix from the body, rewrites paths with spaces or parentheses in the CommonMark `<...>` destination form (gh's CommonMark parser cannot match a bare destination with those characters and would append instead of rewrite), rewrites different spellings of the same file to the first-seen spelling, and the resulting deduplicated paths are passed to `gh` as repeated `--attach` flags (gh >= 2.99.0; gh rewrites matching body references to uploaded URLs). A local `expand_home` expands a leading `~/` via `vim.uv.os_homedir()` (deliberately not `vim.fn.expand`, which executes backticks/globs) so the body reference and `--attach` argument stay identical. `format_attach_error(err)` replaces `unknown flag: --attach` usage dumps with a concise gh-upgrade hint; `format_attach_suffix(count)` builds the "(N files attached)" suffix for success notifications. Paste conversion: while the float is open, `vim.paste` is wrapped (restored in `close_all`; there is no paste autocmd event) so a local media path pasted into the body pane becomes `![](file://path)` — pure helpers `clean_pasted_path` (strips quotes/escaped spaces), `is_local_media_path` (prefix + extension check), and `transform_media_paste(lines, before_cursor)` (context-aware: bare path after `file://`, `file://`+path after `](`); streamed paste phases are accumulated before deciding.
