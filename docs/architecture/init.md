# lua/fude/init.lua

Plugin lifecycle (`start`/`stop`/`toggle`/`reload`). On start: detects PR via `gh`, fetches changed files, comments, PR commits (for scope selection), and authenticated user (for edit/delete ownership), saves original HEAD SHA, records the repository root resolved before the PR lookup as `state.repo_root` (the chat's working directory, so a later `:cd` cannot move it), sets up `BufLeave` (saves source views through `files.save_view`)/`BufEnter`/`WinClosed`/`GitSignsUpdate` autocmds, integrates with gitsigns (per-buffer base selection), applies diffopt settings, sets buffer-local keymaps (`]c`/`[c` for comment navigation, `]F`/`[F` for unviewed-file navigation — declared together in the module-local `BUF_KEYMAPS` table so `setup_buf_keymaps`/`clear_buf_keymaps` stay in step, each one skipped when its `config.opts.keymaps` entry is `false`; teardown deletes a mapping only when its callback is one of the `BUF_KEYMAPS` functions, not by the configured lhs or by `desc`, so a same-key mapping owned by an ftplugin in a buffer review mode never entered survives even if it copies fude's description text), starts the `overview.prefetch({ pr_info, on_ready })` background fetch of the `:FudeReviewOverview` data right after the PR info is set — the PR lookup (`gh.get_pr_info(cb, { with_overview = true })`) already asked for the overview's body fields on a branch, so its result is handed over as the body and no second `gh pr view` runs — and calls the `on_overview_ready({ pr_number, pr_url })` hook (scheduled, so after the rest of the start setup; once, on success, while the session is active) as soon as that body is cached, usually well before `on_review_start`, loads the review comments outside the start barrier (so `on_review_start` — and an overview it opens — does not wait for them; the side panel is refreshed when they land), and starts auto-reload timer if configured. `reload` re-fetches comments, changed files, viewed states, and PR commits in parallel with a completion barrier, and calls `overview.prefetch()` outside that barrier (its failure is silent and must not hold the reload). On stop: stops auto-reload timer, restores original HEAD if in commit scope — including a commit switch whose checkout ran but whose gh callback is still in flight (`scope.has_pending_commit_checkout()`), cancelling that switch via `scope.cancel_pending_switch()` so its late callback cannot act — tears everything down (`ui/chat_panel.teardown()` only after the HEAD restore succeeded, so a stop that fails there and keeps the session also keeps the chat and an answer in flight: it stops a running claude, which stores what had arrived, and closes the chat panel while `config.state` is still this session's), removes buffer-local keymaps, and restores original state. `start()` refuses via `stack.refuse_while_switching()` while a `:FudeReviewStackSwitch` checkout is in flight. Exports helpers: `apply_gitsigns_base_for_buffer()` sets per-buffer gitsigns base (the full PR scope uses `merge_base_sha` for every file — added files too, since GitHub reports a file as added against the merge-base while the base branch tip may hold it, as for a merged PR — and `base_ref` only when no merge-base was computed, skipped when `gitsigns_reset` is true; in local review mode every file uses `merge_base_sha`, since each local scope resolves to one SHA and `base_ref` is the base *branch*, which may be nil or hold a same-named file; the buffer is mapped with `local/session.relative_path`, so a `:cd` out of the worktree does not skip every buffer); `compute_merge_base(base_ref)` computes and caches the merge-base SHA from two candidates — the merge-base with `state.base_sha` (the PR's `base.sha`, frozen at merge time once merged) and the one with `base_ref` — picked by the pure `find_fork_point(from_base_sha, from_base_ref, head_sha, is_ancestor)`: the later of the two (`diff.is_ancestor`), since `base.sha` may lag behind a base branch merged into the PR while a stale local base branch lags the other way, except that a `base_ref` merge-base equal to HEAD is dropped (the base branch already contains the PR — merged with a merge commit — and would empty every diff); a `base.sha` not available locally leaves only the `base_ref` one; `update_gitsigns_base(base_ref)` sets global gitsigns base (used for commit scope); `toggle_gitsigns()` toggles gitsigns between PR base and HEAD; `restore_gitsigns_base()` restores gitsigns to PR base display.
