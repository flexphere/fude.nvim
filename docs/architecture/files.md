# `lua/fude/files.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Changed files display via Telescope picker, snacks.picker, or quickfix list. Shared file opening: `open_file(filename, entry?)` checks buffer existence before editing, updates an existing diff preview synchronously, then centers only new buffers via `center_first_hunk`/`parse_first_hunk_line` and `resolve_patch`. The parser skips leading context lines and returns the first changed new-file position; deletions use the surviving boundary (the header anchor for a zero-context deletion), clamped to the buffer by the caller. Other existing buffers restore the cursor/scroll/fold settings recorded by `save_view(buf)` in `state.file_views` on BufLeave (cleared on session reset); folds hiding previously visible rows are reopened. Sidepanel selection, scope auto-open, next/previous commands, and picker confirmation all use this path; explicit comment/draft line jumps do not. Quickfix has a list-context-guarded Enter mapping; native quickfix commands keep their usual behavior. Buffers newly registered by the quickfix list have a buffer-local `fude_quickfix_unopened` marker, consumed on the first BufReadPre/BufNewFile even outside fude; buffer-local one-shot autocmds expire on read or wipe. Buffer lookup prefers an exact absolute path before falling back to a resolved alias, and the post-edit guard compares the opened buffer's resolved path directly with the target. All pickers show diff preview and viewed state toggle via `<Tab>`. Shows GitHub viewed status for each file. Exports `apply_viewed_state(path, new_state, on_done)` as the picker-agnostic state mutator for the viewed state: it invokes gh GraphQL mark/unmark (or `local_sync.set_viewed` in local mode), updates `state.viewed_files`, refreshes the sidepanel (a no-op when closed — the single place every viewed mutation re-renders the panel, so `:FudeReviewViewed`/`Unviewed`, the picker `<Tab>` toggles and the panel's own `<Tab>` all keep the mark and the "Reviewed: n/m" header in sync without a reload), and calls `on_done` with the updated display fields; a backend error is notified and `on_done` is not called, and a callback arriving after `reset_state()` is dropped (captured-state identity check). `apply_viewed_toggle(path, on_done)` is the thin flip wrapper over it; the Telescope adapter `toggle_viewed_in_telescope`, the snacks adapter `toggle_viewed_in_snacks(picker, item)` and `ui/sidepanel.toggle_file_viewed` delegate to the toggle, while `init.mark_viewed`/`unmark_viewed` (via the module-local `set_current_file_viewed`, which maps the buffer with `local/session.relative_path`) call `apply_viewed_state` directly since they set rather than flip. `show()` routes to `show_telescope` / `show_snacks` / `show_quickfix` based on `config.opts.file_list_mode`; snacks falls back to quickfix when snacks.nvim is missing. `open_first_file()` opens the first non-removed file in navigation order (leaving the side panel, the preview, a floating window, or a non-empty-`buftype` buffer for a source window first, `pcall`-guarded, then `sidepanel.reveal_file`); used after `:FudeReviewScopeNext`/`Prev`. Also exports `next_file()` / `prev_file()` for jumping between changed files (used by `:FudeReviewNextFile` / `:FudeReviewPrevFile`); both wrap around at the edges and fall back to the first/last entry when the current buffer is not part of the PR. After a successful edit, they call `sidepanel.reveal_file` to expand the target file's collapsed ancestors, guarded by session identity in case edit autocmds stopped/restarted the session. Navigation order follows the sidepanel file list: when the sidepanel is in tree mode (panel open → its current `file_tree_mode`, panel closed → `config.opts.sidepanel.file_tree`) the full tree render order (including collapsed descendants) is used, otherwise the flat `changed_files` order. The pure helpers `find_adjacent_file_index(changed_files, current_path, direction)` computes the target index; `build_navigation_order(changed_files, tree_mode)` returns the navigation-ordered file list, reusing `ui/sidepanel/tree.lua` (`build_tree`/`collapse_singleton_chains`/`flatten_tree`) for tree order; `count_viewed(viewed_files, changed_files)` counts files with VIEWED state (used by sidepanel header). `next_unviewed_file()` / `prev_unviewed_file()` (`:FudeReviewNextUnviewedFile` / `:FudeReviewPrevUnviewedFile`, bound to `]F`/`[F`) walk the same navigation order but stop only on files that are neither marked `VIEWED` in `state.viewed_files` nor `status == "removed"` (a deleted file cannot be opened and is rarely viewed, so it would otherwise be hit on every wrap-around — `ui/sidepanel.find_first_file_entry` skips removed entries for the same reason). The pure helper `find_adjacent_unviewed_index(files, current_path, direction, viewed_files)` reaches the current file last, so it is returned only when it is the sole unviewed target, and returns nil when there is none; `has_unviewed_target(changed_files, viewed_files)` answers the same question without an ordering, and `goto_adjacent` calls it *before* switching away from the side panel so an empty result does not move the user out of the panel just to report it.
