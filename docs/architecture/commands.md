# `lua/fude/commands.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Command registry, the single source of truth for every `:FudeXxx` user command. `M.list` holds one entry per command: `name`, `desc` (used as the command `desc` and the palette text), `category` (one of `M.CATEGORIES`: Session / Comments / Files / Scope / Review / View / PR), `available(state)` (whether the palette lists it for the given `config.state`: inactive → Start/Local/PR helpers (Create/Edit/EditReviewers/EditLabels/ChangePRState/URL commands), GitHub mode → also StackSwitch/Submit/Overview/React (`reactions.react_at_cursor`; local review comments have no reactions), local mode → also LocalScope/LocalBase, both review modes → Resolve (dispatched by `comments.toggle_resolve`) and Scope/ScopeNext/ScopePrev, since `scope.lua` dispatches them to the local session; `FudeReviewStop` covers both modes since `init.stop()` delegates to the local session, so there is no separate local stop command), `run(opts)` (the user-command callback), and optional `range`/`nargs`/`complete`/`palette` (`palette = false` hides an entry from `:FudeCommandPalette` while keeping it registered — used for the two Toggle commands, which Start/Stop already cover)/`repeatable` (`false` keeps the entry out of `:FudeCommandRepeat` — only the repeat itself). `register_all()` wraps every `run` so that `record(cmd, opts)` first stores `{ name, fargs, bang }` in the module-local `last_command` (not `config.state`, so it survives a review stop / start; `get_last()`, `_reset_last()` for tests); `:FudeCommandRepeat` (`range = true`, available always) runs `repeat_last(opts)`, which builds the `vim.cmd` table with the pure `build_repeat_cmd(last, range, takes_range)` — the range is never recorded, and the repeat's own range is forwarded only to an entry with `range = true` (looked up by `find(name)`) — and INFO-notifies when nothing ran yet. Command bodies that were inlined in `plugin/fude.lua` (`FudeReviewSubmit` flow, `get_pr_url`, the two display toggles) live here as local functions. The `FudeReviewSubmit` body input persists a local draft (kind `review`): it is prefilled from the draft, "Save draft & close" saves without submitting the review, "Discard & close" drops the draft and submits without a body (as `q` always did), closing an unedited restored draft (`cancel`, no prompt since it is not dirty) keeps it and does not submit — submitting would send the review without the saved body and then delete it — and a successful submit removes the draft via `drafts.remove_if_unchanged` (the input is closed by then, so a draft re-saved from a new `:FudeReviewSubmit` while the request is in flight survives). `register_all()` registers every entry with `nvim_create_user_command`. `scripts/check_docs.lua` extracts command names from this file (`name = "FudeXxx"`) in addition to `plugin/fude.lua`.
