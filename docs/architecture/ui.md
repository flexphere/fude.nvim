# `lua/fude/ui.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Facade module re-exporting `ui/format.lua` and `ui/extmarks.lua`. Contains floating window UI: comment input editor, comment viewer (`show_comments_float`: `r` reply, `e` edit, `d` delete, `R` toggle the resolved state of the thread of the comment under the cursor via `comments.toggle_resolve(id)`, `o` open the comment under the cursor on GitHub via `open_comment_in_browser(comment, ctx)` — `data.find_comment_url` + `util.open_url` — leaving the float open; `ctx` comes from `capture_open_context()` (`pending_review_id`, local mode, `pr_url`) taken when the UI rendered the comments, because the viewer, browser and overview can stay open across `:FudeReviewStop`, whose `reset_state()` would otherwise turn an unpublished pending comment into one `o` opens; unlike `e`/`d`/`R`, which fall back to the last comment, `o` on a separator line opens nothing), PR overview window (`show_overview_float(pr_info, issue_comments, opts)` returns `{ is_open, set_comments(comments), set_reviewers(), set_checks(checks, failed) }` for the sections that load after the body: nil `issue_comments` gives COMMENTS a spinner row (`build_overview_left_lines`' `loading_row`; the section and the footer end the left pane from `comments_start`, so `set_comments` rewrites only that part and the `'c` mark, section list and refs), `pr_info.reviewers_loading` gives REVIEWERS one (`reviewers_loading_row`; `set_reviewers` rebuilds the whole right pane from `pr_info` — REVIEWERS comes first — re-placing the reviewer avatars after `ui/avatars.clear`), and a nil `pr_info.statusCheckRollup` gives CI STATUS one (the end of the right pane from `ci_start`, rewritten in place by `set_checks`, which refills the `gx` check URL table); one `start_spinner` timer advances every loading row through `draw_spinner_frames` (the rows keep the first frame as text) and stops when none is left, each setter redrawing the frames where the remaining loading rows now are; `pr_info.checks_failed` / `reviewers_failed` show their failure rows at once; `]c`/`[c` and `o` read the current comment positions, so they work once the comments arrive; `o` opens the issue comment under the cursor — mapped through `build_overview_left_lines`'s `comment_ranges` — and the PR anywhere else, including the right pane; `overview.keymaps.toggle_right_pane` (`S`, both panes, `false` unmaps) hides the right window with `nvim_win_set_config({ hide = true })` — hidden rather than closed, since closing either pane closes the overview through its `WinClosed` — and widens the left one to the pure `format.calculate_overview_full_width(layout)` (the right pane plus the two border columns between them), moving the cursor to the left pane first; `<Tab>` does nothing while it is hidden, and the next `S` restores both) with the author / reviewer avatars placed by `ui/avatars.place` into both panes right after the buffers are filled and its loading placeholder (`open_overview_loading()` → `{ close, is_open, is_spinning }`, a spinner centred in each pane — `OVERVIEW_LOADING_TEXT` on the left, `OVERVIEW_LOADING_RIGHT_TEXT` on the right — written once as text, with every later frame drawn over its mark by the module-local `draw_spinner_frames(bufs, rows, mark)` — an overlay extmark in the `fude_spinner` namespace, never a buffer change, since rewriting the line every frame fires `on_lines` that other plugins answer by scheduling work (e.g. a treesitter parse) on a buffer `q` wipes before it runs — and advanced by the module-local `start_spinner(on_frame)` → `stop`: the two panes at the position and size of the module-local `overview_layout()` shared with `show_overview_float`, which sizes the overview by the layout alone — never by the content, so a short PR does not shrink it, `OVERVIEW_LOADING_TEXT` after a spinner frame (`toggle_picker.format_loading_mark`, `LOADING_HL`) centred in the left one by the pure `format.build_centered_lines(text, text_width, width, height)`, a `vim.uv` timer advancing the frame every `toggle_picker.LOADING_INTERVAL_MS` until close, closed together by `q`/`<Esc>` or by a `WinClosed` of either), reply window, edit window, and review event selector. `require("fude.ui")` is the public interface. `open_comment_input(callback, opts)` accepts `opts.pick_submit_kind(cb)`: called on `<CR>` with a non-empty body before the float closes; `cb(kind)` closes it and passes `kind` as the callback action, `cb(nil)` keeps editing. Also exports `close_comment_ui()` (closes the reply/edit window, the comment browser, every viewer float — `show_comments_float` marks its buffer `b:fude_comment_view`, listed by `comment_view_buffers()` — and every single-pane input float in any tab — the UIs that hold or take comments — when the local commit scope is entered), `comment_input_buffers()` (loaded `b:fude_comment` buffers shown in some window of any tabpage, via `win_findbuf` since `bufwinid` only searches the current tab), `has_unsent_comment_input()` (true while any of those, the reply/edit lower pane or the browser's lower pane holds non-blank text; `local/session.checkout_blocker` refuses the commit scope on it so the teardown cannot wipe unsent text), `should_confirm_discard(current_lines, original_lines)` (pure), `prompt_close_decision(allow_draft, on_save, on_discard, prompts?)` (the 3-way save-draft/discard/keep-editing `vim.ui.select` — or Yes/No fallback when `allow_draft` is false — with comment-specific default prompt texts overridable via `prompts.unsaved`/`prompts.discard`; `pr.lua`'s two-pane float uses it directly with PR wording), and `confirm_close_with_draft(buf, original_lines, opts)` (side-effect) used to guard close/cancel actions on comment input buffers: when the buffer is dirty it shows the 3-way prompt via `opts.on_save_draft`/`opts.on_discard`/`opts.on_close`, falling back to the plain Yes/No discard confirmation when `opts.allow_draft` is false.
