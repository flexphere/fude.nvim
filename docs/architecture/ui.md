# UI: floats, formatting, extmarks, comment browser

Module details for `lua/fude/ui.lua`, `ui/format.lua`, `ui/inline.lua`, `ui/comment_browser.lua`, `ui/extmarks.lua`. Moved verbatim from the former "Module Responsibilities" section of `CLAUDE.md`; update this file when these modules change.

Related details in other files: the overview metadata (frontmatter) contract that binds `ui/format.build_overview_left_lines` and `ui.show_overview_float`, and the overview's fetch / part-delivery flow, are in `overview.md`; the "Comment browser thread identity" rules that bind `ui/format.format_comment_browser_thread` and `ui/comment_browser.lua`, and `drafts.lua` / `reactions.lua`, are in `comments.md`; `ui/avatars.lua` and `ui/toggle_picker.lua` are in `ui-components.md`; `ui/sidepanel.lua` is in `sidepanel.md`; the shared `util.lua` helpers (`open_url`, `all_comments_resolved`, `reset_selection_on_prompt_change`) are in `core.md`.

- **`ui.lua`** — Facade module re-exporting `ui/format.lua` and `ui/extmarks.lua`. Contains floating window UI: comment input editor, comment viewer (`show_comments_float`: `r` reply, `e` edit, `d` delete, `R` toggle the resolved state of the thread of the comment under the cursor via `comments.toggle_resolve(id)`, `o` open the comment under the cursor on GitHub via `open_comment_in_browser(comment, ctx)` — `data.find_comment_url` + `util.open_url` — leaving the float open; `ctx` comes from `capture_open_context()` (`pending_review_id`, local mode, `pr_url`) taken when the UI rendered the comments, because the viewer, browser and overview can stay open across `:FudeReviewStop`, whose `reset_state()` would otherwise turn an unpublished pending comment into one `o` opens; unlike `e`/`d`/`R`, which fall back to the last comment, `o` on a separator line opens nothing), PR overview window (`show_overview_float(pr_info, issue_comments, opts)` returns `{ is_open, set_comments(comments), set_reviewers(), set_checks(checks, failed) }` for the sections that load after the body: nil `issue_comments` gives COMMENTS a spinner row (`build_overview_left_lines`' `loading_row`; the section and the footer end the left pane from `comments_start`, so `set_comments` rewrites only that part and the `'c` mark, section list and refs), `pr_info.reviewers_loading` gives REVIEWERS one (`reviewers_loading_row`; `set_reviewers` rebuilds the whole right pane from `pr_info` — REVIEWERS comes first — re-placing the reviewer avatars after `ui/avatars.clear`), and a nil `pr_info.statusCheckRollup` gives CI STATUS one (the end of the right pane from `ci_start`, rewritten in place by `set_checks`, which refills the `gx` check URL table); one `start_spinner` timer advances every loading row through `draw_spinner_frames` (the rows keep the first frame as text) and stops when none is left, each setter redrawing the frames where the remaining loading rows now are; `pr_info.checks_failed` / `reviewers_failed` show their failure rows at once; `]c`/`[c` and `o` read the current comment positions, so they work once the comments arrive; `o` opens the issue comment under the cursor — mapped through `build_overview_left_lines`'s `comment_ranges` — and the PR anywhere else, including the right pane; `overview.keymaps.toggle_right_pane` (`S`, both panes, `false` unmaps) hides the right window with `nvim_win_set_config({ hide = true })` — hidden rather than closed, since closing either pane closes the overview through its `WinClosed` — and widens the left one to the pure `format.calculate_overview_full_width(layout)` (the right pane plus the two border columns between them), moving the cursor to the left pane first; `<Tab>` does nothing while it is hidden, and the next `S` restores both) with the author / reviewer avatars placed by `ui/avatars.place` into both panes right after the buffers are filled and its loading placeholder (`open_overview_loading()` → `{ close, is_open, is_spinning }`, a spinner centred in each pane — `OVERVIEW_LOADING_TEXT` on the left, `OVERVIEW_LOADING_RIGHT_TEXT` on the right — written once as text, with every later frame drawn over its mark by the module-local `draw_spinner_frames(bufs, rows, mark)` — an overlay extmark in the `fude_spinner` namespace, never a buffer change, since rewriting the line every frame fires `on_lines` that other plugins answer by scheduling work (e.g. a treesitter parse) on a buffer `q` wipes before it runs — and advanced by the module-local `start_spinner(on_frame)` → `stop`: the two panes at the position and size of the module-local `overview_layout()` shared with `show_overview_float`, which sizes the overview by the layout alone — never by the content, so a short PR does not shrink it, `OVERVIEW_LOADING_TEXT` after a spinner frame (`toggle_picker.format_loading_mark`, `LOADING_HL`) centred in the left one by the pure `format.build_centered_lines(text, text_width, width, height)`, a `vim.uv` timer advancing the frame every `toggle_picker.LOADING_INTERVAL_MS` until close, closed together by `q`/`<Esc>` or by a `WinClosed` of either), reply window, edit window, and review event selector. `require("fude.ui")` is the public interface. `open_comment_input(callback, opts)` accepts `opts.pick_submit_kind(cb)`: called on `<CR>` with a non-empty body before the float closes; `cb(kind)` closes it and passes `kind` as the callback action, `cb(nil)` keeps editing. Also exports `close_comment_ui()` (closes the reply/edit window, the comment browser, every viewer float — `show_comments_float` marks its buffer `b:fude_comment_view`, listed by `comment_view_buffers()` — and every single-pane input float in any tab — the UIs that hold or take comments — when the local commit scope is entered), `comment_input_buffers()` (loaded `b:fude_comment` buffers shown in some window of any tabpage, via `win_findbuf` since `bufwinid` only searches the current tab), `has_unsent_comment_input()` (true while any of those, the reply/edit lower pane or the browser's lower pane holds non-blank text; `local/session.checkout_blocker` refuses the commit scope on it so the teardown cannot wipe unsent text), `should_confirm_discard(current_lines, original_lines)` (pure), `prompt_close_decision(allow_draft, on_save, on_discard, prompts?)` (the 3-way save-draft/discard/keep-editing `vim.ui.select` — or Yes/No fallback when `allow_draft` is false — with comment-specific default prompt texts overridable via `prompts.unsaved`/`prompts.discard`; `pr.lua`'s two-pane float uses it directly with PR wording), and `confirm_close_with_draft(buf, original_lines, opts)` (side-effect) used to guard close/cancel actions on comment input buffers: when the buffer is dirty it shows the 3-way prompt via `opts.on_save_draft`/`opts.on_discard`/`opts.on_close`, falling back to the plain Yes/No discard confirmation when `opts.allow_draft` is false.
  - **`ui/format.lua`** — Pure format/calculation functions with no state or vim API side effects: `calculate_float_dimensions`, `format_line_range(start_line, end_line)` (`L20-L29`, nil for a single line), `build_range_start_marker(start_line, end_line)` (`↓ comment L20-L29`, "" for a single line), `build_comment_separator(width?)` (the `---` line between comments; `format_comments_for_display`, `format_reply_comments_for_display` and `format_comment_browser_thread` take an optional trailing `separator_width` that callers set to the window width so the line spans it, falling back to `DEFAULT_SEPARATOR_WIDTH` (40)), `format_comments_for_display`, `build_comments_float_title`, `normalize_check`, `format_check_status`, `deduplicate_checks`, `sort_checks`, `build_checks_summary`, `format_review_status`, `build_reviewers_list`, `build_re_request_candidates` (the `r` candidates, Copilot included under its REST login), `build_reviewer_entries(collaborators, review_requests, latest_reviews, author_login)` (overview reviewer picker rows `{ login, requested, review_state }`: ordered approved, changes requested, commented, dismissed, requested, then the rest, each by the name shown; author, bots, teams, non-collaborator reviewers and PENDING reviews excluded — except Copilot (`COPILOT_REVIEWER`: GraphQL login `copilot-pull-request-reviewer`, REST `api_login` `copilot-pull-request-reviewer[bot]`, shown as `@copilot` via `reviewer_display_name(login)`; `is_copilot_login` accepts both forms), which can be requested unlike other bots and is always listed, since nothing tells in advance whether Copilot code review is enabled (GitHub refuses the request otherwise); entry `login` is the REST form, which `edit_reviewers` sends and shows through the display name — as are collaborators whose `permissions.push` is false, indexed before either list is read so a read-only member who reviewed is excluded too, while a requested user is always kept so the request can be removed), `format_reviewer_detail(requested, review_state)` (`review requested, last review: dismissed` — the request and the latest review stated separately), `format_review_state_label(state)` (`CHANGES_REQUESTED` → `changes requested`), `build_label_entries(repo_labels, pr_labels)` (`{ name, description, applied }`, applied first; a PR label missing from the repository listing is kept so it can be removed), `format_toggle_mark(on)` (label rows: `●`/`○`), `format_reviewer_mark(requested, review_state)` (reviewer rows, GitHub web UI marks: requested `●` DiagnosticWarn — wins over the previous review —, approved `✓` with the name in DiagnosticOk, changes requested `✗`, commented `COMMENTED_MARK` (the Nerd Font `nf-oct-comment` glyph, one cell like the other marks), dismissed `↻`, else `○`; every other user without a pending request except a dismissed one gets a `Comment` (grey) name; returns `mark, mark_hl, text_hl`), `format_toggle_entry(text, mark, detail)`, `build_reviewers_summary`, `build_centered_lines(text, text_width, width, height)` (one line of text in the middle of a window; returns the lines plus the 0-based row and byte column of the text), `calculate_overview_layout`, `calculate_overview_full_width(layout)` (the left pane's width with the right pane hidden), `calculate_comments_height`, `calculate_reply_window_dimensions`, `format_reply_comments_for_display` (also returns 0-indexed `comment_ranges`, like `format_comments_for_display`), `find_comment_index_at_line(comment_ranges, line)` (the comment a 0-indexed line belongs to; separators/headings/footers belong to none — used by the `o` keys), `build_overview_left_lines` (also returns 0-indexed `comment_ranges` over the issue comments, and `avatar_positions` — the `author:` line and the byte column after `author: `, kind `author`, and each comment heading after `### `, kind `comments`; `set_comments` re-places the left pane's avatars after `ui/avatars.clear`), `build_overview_right_lines(pr_info, opts)` (also `avatar_positions`: each reviewer line, after its status symbol, kind `reviewers`, and each assignee line at column 0, kind `assignees`; each label is a one-line pill from `build_label_pill(name, name_hl, cap_hl, display_width)` (`LABEL_PILL_LEFT .. pad .. name .. pad .. LABEL_PILL_RIGHT` — Nerd Font round ends, `LABEL_PILL_PADDING` inside — with `width` in display cells by `opts.display_width`, `strdisplaywidth` from `ui.show_overview_float`), laid out side by side, in the PR page order (the reverse of gh's), by `pack_label_pills(pills, width)` (`LABEL_PILL_GAP` between them, a new row once `opts.labels_width` — the right pane's width — would be exceeded); a label with a valid `color` is highlighted with the `build_label_hl_names(hex)` groups `ReviewLabel_<rrggbb>` (the padded name: text on the fill, bold) / `ReviewLabelCap_<rrggbb>` (the ends: the fill colour as foreground), and `label_colors` lists those colours once each so `ui.show_overview_float` can define the groups (module-local `define_label_hls`, also on `set_reviewers`) from `calculate_label_colors(hex, base_bg, background)` → `{ fg, bg }`: dark fills with the label colour at `LABEL_FILL_ALPHA` (0.6) over `base_bg` (`NormalFloat`, else `Normal`, else black/white) via `blend_colors` and takes Primer's label text colour (HSL lightness raised by `(0.6 - perceived) * 100` points below perceived lightness 0.6) mixed `LABEL_TEXT_WHITEN` (0.5) toward white; light fills with the label colour and uses black/white text by perceived lightness 0.453, as GitHub's light theme; `parse_hex_color` parses `rrggbb`/`#rrggbb`; a label without a valid colour gets a pill without highlights; `ci_start`/`loading_row` of the CI STATUS section, built by `build_overview_ci_lines(checks, start_line, opts)` — nil `checks` gives the spinner row (`opts.loading_mark`/`loading_hl`, `CHECKS_LOADING_TEXT`) or, with `opts.checks_failed`, `CHECKS_FAILED_TEXT`; line numbers absolute), `calculate_comment_browser_layout`, `format_comment_browser_list`, `format_comment_browser_thread`, `parse_markdown_line`, `build_highlighted_chunks`, `apply_markdown_highlight_to_line`, `normalize_newlines`. Purity is enforced by `scripts/check_purity.lua` (`make check-purity`).
  - **`ui/inline.lua`** — Inline (virt_lines) comment box rendering. `format_comments_for_inline(comments, format_date_fn, opts)` builds bordered comment boxes for use as `nvim_buf_set_extmark` `virt_lines`. The box border label shows `[pending]` for pending comments, else `[resolved thread]` for a resolved thread's head comment only (the oldest one, with no `in_reply_to_id`) — since resolved state is thread-level and propagated to every comment, the label is not repeated on replies. A multi-line thread head is titled with its range (`Comment L20-L29 [pending]`, via `data.get_comment_line_range` + `format.format_line_range`) under the same head-only rule. Reads the current window's text width via `vim.api`/`vim.fn` to size boxes, which is why it lives outside the pure `ui/format.lua`.
  - **`ui/comment_browser.lua`** — 3-pane floating comment browser for `FudeReviewListComments`. Left pane: comment list (review + PR-level, time-descending; the PR-level entry holds issue comments and submitted review bodies from `sync.fetch_pr_level_comments`, the bodies headed with a `[approved]`-style badge from `format.comment_badges`, and `e`/`d` pick their target via `data.find_editable_comment` so a review body is never edited or deleted), including local drafts via `merge_draft_entries` (existing entries get a `✎draft` marker; new line/suggest/issue drafts appear as `[draft]` rows). Selecting a `type="draft"` row: `line`/`suggest` jumps to the file (`<CR>`), `issue` focuses the lower pane (prefilled). Right upper: thread display (draft body preview for draft rows). Right lower: reply/edit/new comment input; `r` in the list or thread pane focuses it in the mode `update_right_panes` set for the selected entry (Reply, New PR Comment, or an Edit in progress), and on a line/suggest draft row only notifies that the draft is edited in the file. Supports reply, edit, delete, new PR comment, jump to file, refresh, and `o` (open on GitHub): in the list pane the pure `find_entry_open_target(entry, pr_url)` picks the thread's first comment, the PR for the PR-level entry, or refuses a draft row; in the thread pane the comment under the cursor, found through the `comment_ranges` of the formatted thread (stored with the pure `find_thread_comments(entry, all_issue_comments)` list on `browser.thread_comment_ranges`/`thread_comments` by `update_right_panes`); both panes judge with `browser.open_ctx` (`ui.capture_open_context()`, retaken by refresh together with the new data), not the live state. `close()` closes it from outside (no-op when closed), used by `ui.close_comment_ui` when the local commit scope is entered. Does not depend on Telescope.
  - **`ui/extmarks.lua`** — Extmark management: `flash_line`, `highlight_comment_lines`, `clear_comment_line_highlight`, `refresh_extmarks`, `refresh_visible_extmarks` (re-renders every window showing a normal buffer, used after a local scope switch), `clear_extmarks`, `clear_all_extmarks`. `refresh_extmarks` also colors the line numbers of every multi-line comment range (`number_hl_group` from `comment_range.number_hl`, both styles, clamped to the buffer by the module-local `highlight_range_numbers`), and `update_inline_hint` marks the ranges of the comments on the cursor line through the module-local `mark_cursor_ranges` (line numbers switched to `comment_range.cursor_number_hl` at a higher priority, plus a `build_range_start_marker` EOL text on each range's first line in `start_marker_hl`; both in the hint namespace, removed by `clear_inline_hint`) — a multi-line comment is drawn on its last line, so these show where it starts. No background (`line_hl_group`) or sign is used, so diff colors and gitsigns stay visible. Uses lazy `require("fude.comments")` to avoid circular dependencies. `refresh_extmarks` also renders the `draft` indicator from `drafts.file_markers(rel_path)` (EOL virt_text, both virtualText and inline modes), and clears the buffer instead of rendering while `local/session.in_commit_scope()` (the buffer is a checked-out past commit, so working-tree positions would land on unrelated lines); it maps the buffer with `local/session.relative_path`, which is relative to the local session's worktree root (falling back to `diff.to_repo_relative` outside local mode) so a `:cd` out of the worktree does not blank every reviewed buffer. A module-local `render_virt_text_indicators(buf, line, comments)` builds the EOL indicators (comment count, pending, resolved `resolved.label` at priority 43 when `util.all_comments_resolved`); it is used both for the virtualText style and, in the inline style, as the fallback for resolved comments whose box is hidden by `:FudeReviewToggleResolved` (so both paths show an identical indicator).
