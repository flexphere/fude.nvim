# lua/fude/chat.lua

AI chat core for review mode, no UI: one claude session and conversation per review target, and the `claude -p` process for a question. Facade re-exporting `chat/data.lua`. `is_available()` (`vim.fn.executable(config.opts.chat.cmd) == 1`), `current_key(st?)` (`drafts.build_draft_scope` + `drafts.make_draft_key(repo, id, "chat")`, so the unit is the one drafts use — GitHub: repo + PR number, local: worktree + branch — and a chat survives review stops and restarts; a local review on a detached HEAD is keyed `detached:<session.id>` like its drafts, so that chat is not continued by the next session and its file stays on disk). Storage: `load(key)` / `save(key, chat)` → `ok, err` read and write `stdpath("state")/fude/chat/<sha256(key)>.json` (`M._dir` overrides the base dir for tests; the key holds slashes and colons, hence the hash, and is kept inside the file; written to a temp file and renamed, like `local/store`'s pointer; no retention — only `discard` removes a chat), `discard(key?)` → `ok, err` (stops a running question for that key *without* storing its partial answer — the job is marked `abandoned` — then deletes the file). Running: `run(cmd, { cwd, stdin }, on_chunk, on_exit)` → `{ kill(signal?) }|nil, err` (`kill` sends `sigterm` unless told `sigkill`) is the mockable `vim.system` wrapper (callbacks through `vim.schedule`; a process ended by a signal reports code 0 from `vim.system`, turned into `128 + signal`); `send(prompt, handlers)` → `accepted, reason` (`ERR_BUSY`/`ERR_EMPTY`/`ERR_NO_TARGET`/`ERR_NO_ROOT`; one question at a time, kept in the module-local `running` rather than `config.state` so the process stays reachable after `reset_state()`) starts claude in the root of the review in progress — `current_root(st?)`, i.e. `data.find_chat_root(state.review_mode, state.repo_root, state.local_session)`: `state.repo_root`, which `init.start()` records, in a GitHub review and `local_session.worktree_root` in a local one; never `diff.get_repo_root()` at question time, which follows Neovim's cwd into another repository (vim-rooter, `:cd`), and never a directory stored with the conversation, which may be another worktree or clone of the same target. claude keeps sessions per directory, so the same target reviewed from another directory fails its `--resume` and takes the "new" retry there; `ERR_NO_ROOT` when the state has no root — with the argv from `build_claude_args` and, on stdin, `build_prompt_input(build_prompt_context(job.target), prompt)`, where `job.target` is the copy `send` takes of the state fields claude is told about (`review_mode`, `local_session`, `pr_number`, `pr_url`, `base_ref`, `head_ref`, `scope`, `scope_commit_sha`), so the pure builders in `chat/data.lua` get plain data and a retry describes the GitHub scope as it was when the question was asked (`local_session` is the session table itself, not a copy) — the question is never an argument (a variadic `--allowedTools` could swallow it, and a leading `-` would read as an option) and `job.prompt` stays the user's own text for the log, the store and the failure path. The first question of a target generates a UUID (`local/store.generate_uuid`), stores it before the run and passes `--session-id` (a failed `save` is kept as the job's `save_error` and reported through `on_done` whatever the outcome, by the module-local `save_for(job, chat)`; the process always gets the job's own `job.session_id`, never one read back from disk); `started` is set only when the `system`/`init` line arrives (a failed `result` line also carries the `session_id`, so that field proves nothing), and later questions pass `--resume`. stdout chunks go through `split_stream_chunk` (a chunk may end mid-line) and `parse_stream_line`; text of separate assistant messages (before/after a tool call) is separated by a blank line. `handlers`: `on_text(text)`, `on_tool(label)`, `on_retry("new"|"resume")`, `on_done({ status = "done"|"cancelled"|"error", text, error, prompt, stored, save_error })` — called only while `config.state` is still the table captured at `send` (a stopped or restarted session is never touched), whereas storing goes by the captured key and happens regardless. On exit, a successful `result` — its text delivered through `on_text` when nothing was streamed, so every shown character comes through the module-local `add_text(job, text)` and equals what is stored — or, without a `result` line, exit 0 with answer text, whatever was written to stderr (warnings are not failures) — is `done`; otherwise the error is the `result`'s, else stderr, else the exit code, and `find_session_retry` allows one retry per question with the other session argument: a resumed session claude no longer has starts over under a new id (`"new"`), and a new id "already in use" (the session exists only on claude's side) is resumed (`"resume"`); the retry keeps the text the first attempt streamed and, for `"new"`, appends `NEW_SESSION_NOTE` to the answer text before `on_retry`, so the note is stored with the answer and a reopened panel shows what the live one did; each process gets a token so output of a replaced or killed one is dropped. `done` and `cancelled` exchanges are stored as question + answer (`status` on the answer). An `error` exchange is stored only when claude had opened its session for the question (`job.recorded`, set by the `init` line): question + the partial answer with `status = "error"` and the message in `error` — to which `finish` appends `data.RECORDED_NOTE`, the line telling that the question is part of the conversation and the next question continues it, so the live log and the stored one both show it — and `on_done` reports `stored = true` so the caller does not hand the question back — claude's session holds it, and a resend would ask twice; an error before `init` stores nothing (`stored = false`) and the caller puts the question back in the input. `cancel()` kills the process (SIGTERM), stores what arrived as `cancelled` and runs `on_done` before returning, so a new `send` is accepted at once and late output is ignored; the killed process is remembered in the module-local `draining` until its exit callback runs, and a `send` meanwhile parks its `start_process` in `waiting`, started by that exit through the module-local `end_drain(token)` (a job cancelled while waiting never starts); `cancel` also arms a `vim.defer_fn`: a process still draining after `M.DRAIN_TIMEOUT_MS` (3 s) is sent SIGKILL, and when no exit is reported `M.KILL_TIMEOUT_MS` (1 s) after that, `end_drain` runs anyway, so two processes never write one claude session at once. `is_running(key?)`; `_reset()` for tests.
