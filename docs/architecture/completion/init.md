# `lua/fude/completion/init.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Completion source for comment inputs and PR bodies. `is_enabled(buf?)` accepts `b:fude_comment` or a body registered by `attach_pr(buf, { cwd, base?, pr_number? })`; the latter is deliberately not marked as a comment, since `ui.close_comment_ui` would close it. `pr.open_pr_float` registers only the body before setting its Markdown filetype, and `pr.edit` passes the resolved PR number. The module-local per-buffer context and cache are removed on `BufWipeout`. `fetch_mentions` / `fetch_issues` / `fetch_commits` accept an optional request buffer (forwarded by both blink/cmp adapters), so later focus changes do not retarget requests. Mentions/issues use a 5-minute TTL cache, separate for each PR body and shared by comments. PR editing lazily fetches the explicit PR's commits; creation captures HEAD at attachment and asynchronously reads local `base..tip` commits (retries `origin/<base>`, newest 100 when no base). `parse_git_commits(output)`, `build_commit_items(entries)` and `build_issue_items(issues)` (the `#` candidates, by number descending with `sortText` in that order, so the engines list them newest first whatever order `gh.get_repo_issues` — the 100 most recently updated — returned; entries without a numeric `number` skipped, JSON nulls defaulted) are pure helpers. PR-body commit requests coalesce while in flight and cache successful results, including empty lists, for the body's lifetime; failures are retried, and responses after wipe return empty candidates. All PR-body git/gh calls use the captured cwd; `gh.run` / `run_json` take an optional fourth `cwd` argument, forwarded by the collaborators, issues and PR commits wrappers. Comment commit completion still reads only `state.pr_commits`, invalidating its cache when that list changes. `get_context(line_before_cursor)` parses the `@` / `#` / `_` trigger.
