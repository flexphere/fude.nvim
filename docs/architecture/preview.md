# `lua/fude/preview.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Manages the side-by-side diff preview window. Creates a scratch buffer with base branch content, opens it in a vsplit, and enables `diffthis` on both windows. Uses `noautocmd` to prevent BufEnter cascades. The `opening` flag guards against re-entrant calls. `open_preview` maps the source buffer with `local/session.relative_path` and passes the local session's worktree root to `diff.get_base_content(ref, path, cwd?)`, so a `:cd` out of the worktree does not leave the preview closed after a scope switch (outside local mode both fall back to the cwd-based lookups). The ref it reads comes from the pure `find_base_ref(state, local_session)` → `ref, label`: the local session's `content_ref`, else `<sha>^` in the commit scope, else `state.merge_base_sha` in the full PR scope — the commit the PR branched off, the base gitsigns and GitHub's PR diff use, so commits that land on the base branch after the PR branched off never show up reversed in the base pane — falling back to the base branch tip only when no merge-base was computed; `label` (`main (merge-base abc1234)` for the merge-base) names it in the new-file placeholder. The base content is read from the path returned by the pure `find_base_path(rel_path, changed_files)` — the entry's `previous_path` for a renamed file (or a copied one in GitHub mode, when the API reports it), else `rel_path` — retrying `rel_path` when the old path is missing at the base ref (only the base branch tip fallback can have dropped it); the preview buffer is named `[base] <path read>`. It rejects a source window holding a nofile buffer (e.g. the side panel) — `to_repo_relative` cannot reject such buffer names when cwd is inside the repo, so without the guard `:FudeReviewDiff` from the panel would vsplit the panel itself and wedge `state.source_win` to it. `on_buf_enter` skips the rebuild when the preview already targets the same source window and buffer (`is_preview_current`, backed by `state.preview_source_buf`): rebuilding runs `diffoff!`/`diffthis`, which resets `foldenable`/`foldlevel` and the preview window's options, so re-entering the same file (closing a comment float, moving between the two panes) must not discard the user's fold/wrap changes. Explicit rebuild paths (`toggle_diff`, scope changes) call `close_preview` first and are unaffected. Rebuilds save the source view and fold options, run diffupdate before restoring them, and therefore do not undo file-opening positions. The default `diffopt` includes `followwrap` because `diffthis` otherwise forces `nowrap`, and `linematch:0` because the second-stage line alignment splits a heavily rewritten block into many small hunks with fillers scattered on both sides (a later duplicate key wins, so this also overrides Neovim 0.11+'s built-in `linematch:40`). It deliberately sets no `algorithm:`, leaving Neovim's default myers, which splits hunks the same way git and the GitHub web view do.
