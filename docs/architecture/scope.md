# lua/fude/scope.lua

Review scope selection and navigation. Provides a Telescope picker (or `vim.ui.select` fallback) for choosing between full PR scope and individual commit scope, with commit index display (`[1/10]`) and current scope marker (`▶`). Supports next/prev scope navigation (`next_scope`/`prev_scope`, which pass an `on_done` that calls `files.open_first_file()` only while focus is still in the triggering window — or in the rebuilt preview when triggered from the preview), marking commits as reviewed via `<Tab>` in the Telescope picker (tracked locally in `state.reviewed_commits`), and statusline integration (`statusline()`). On commit scope: checks out the commit, fetches commit-specific changed files, updates gitsigns base to `sha^` (global), and refreshes the diff preview. On full PR scope: restores the original HEAD, re-fetches PR-wide changed files, and computes merge-base (per-buffer gitsigns base is applied via `GitSignsUpdate` autocmd in init.lua). `apply_scope(entry, on_done)` / `apply_full_pr_scope(on_done)` / `apply_commit_scope(sha, on_done)` accept an optional completion callback invoked (after the sidepanel refresh) only when the scope switch succeeded — never on failure or no-op (both functions short-circuit when the requested scope is already active) — used by the sidepanel to auto-open the first file. Their gh callbacks are guarded by a captured `config.state` identity check plus a module-local request generation counter, so a stale response (session stopped/restarted, or a newer switch requested while in flight) touches neither state, UI, nor `on_done`. A module-local `pending_switch` tracks the in-flight target: while a switch is pending the no-op guards compare against it instead of the stale `state.scope`, so re-selecting the pending target dedupes into the in-flight request and selecting anything else supersedes it. `has_pending_commit_checkout()` reports an in-flight commit switch (its checkout already ran) and `cancel_pending_switch()` invalidates the pending switch — both used by `init.stop()` to restore HEAD correctly mid-switch. `refresh_preview()` restores the caller's focused window after rebuilding the preview (`open_preview` otherwise leaves focus on the source window), and is also used by `local/session.set_scope` for its preview rebuild. Exports `apply_reviewed_toggle(sha)` as a picker-agnostic state mutator that toggles `state.reviewed_commits[sha]` and returns the updated display fields `{ is_reviewed, reviewed_icon, reviewed_hl }`; both the Telescope adapter `toggle_reviewed_in_telescope` and the snacks adapter `toggle_reviewed_in_snacks(picker, item)` delegate to it. `select_scope()` routes to `show_telescope` / `show_snacks` / `show_vim_select` based on `config.opts.file_list_mode`; snacks falls back to `vim.ui.select` when snacks.nvim is missing. In local review mode the same three commands work through the local session: `select_scope()` delegates to `local/session.select_scope()`, and `next_scope`/`prev_scope` pick the neighbour of the current entry in `local/session.scope_specs` order with the pure `find_adjacent_local_scope(specs, direction)` (wraps at both ends like the GitHub helpers; first/last entry when none is flagged current; nil for an empty list), then call `local/session.set_scope`, running the same focus-guarded `open_first_file` callback only when it returns true — `set_scope` reports its own refusals (checkout blockers, unresolvable base), so nothing is notified twice; when the neighbour is the current entry itself (only one scope available) an INFO is shown and `set_scope` is not called.
