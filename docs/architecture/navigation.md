# Navigation: changed files, review scope, PR stack

Module details for `lua/fude/files.lua`, `scope.lua`, `stack.lua`. Moved verbatim from the former "Module Responsibilities" section of `CLAUDE.md`; update this file when these modules change.

Related details in other files: the "Sidepanel commit review marks" contract that binds `scope.build_local_scope_entries` / `scope.apply_reviewed_toggle` is in `sidepanel.md`; the local scopes `scope.lua` dispatches to (`local/session.lua`) are in `local-review.md`; `util.reset_selection_on_prompt_change`, which every Telescope picker here goes through, is in `core.md`.

- **`files.lua`** — Changed files display via Telescope picker, snacks.picker, or quickfix list. Shared file opening: `open_file(filename, entry?)` checks buffer existence before editing, updates an existing diff preview synchronously, then centers only new buffers via `center_first_hunk`/`parse_first_hunk_line` and `resolve_patch`. The parser skips leading context lines and returns the first changed new-file position; deletions use the surviving boundary (the header anchor for a zero-context deletion), clamped to the buffer by the caller. Other existing buffers restore the cursor/scroll/fold settings recorded by `save_view(buf)` in `state.file_views` on BufLeave (cleared on session reset); folds hiding previously visible rows are reopened. Sidepanel selection, scope auto-open, next/previous commands, and picker confirmation all use this path; explicit comment/draft line jumps do not. Quickfix has a list-context-guarded Enter mapping; native quickfix commands keep their usual behavior. Buffers newly registered by the quickfix list have a buffer-local `fude_quickfix_unopened` marker, consumed on the first BufReadPre/BufNewFile even outside fude; buffer-local one-shot autocmds expire on read or wipe. Buffer lookup prefers an exact absolute path before falling back to a resolved alias, and the post-edit guard compares the opened buffer's resolved path directly with the target. All pickers show diff preview and viewed state toggle via `<Tab>`. Shows GitHub viewed status for each file. Exports `apply_viewed_state(path, new_state, on_done)` as the picker-agnostic state mutator for the viewed state: it invokes gh GraphQL mark/unmark (or `local_sync.set_viewed` in local mode), updates `state.viewed_files`, refreshes the sidepanel (a no-op when closed — the single place every viewed mutation re-renders the panel, so `:FudeReviewViewed`/`Unviewed`, the picker `<Tab>` toggles and the panel's own `<Tab>` all keep the mark and the "Reviewed: n/m" header in sync without a reload), and calls `on_done` with the updated display fields; a backend error is notified and `on_done` is not called, and a callback arriving after `reset_state()` is dropped (captured-state identity check). `apply_viewed_toggle(path, on_done)` is the thin flip wrapper over it; the Telescope adapter `toggle_viewed_in_telescope`, the snacks adapter `toggle_viewed_in_snacks(picker, item)` and `ui/sidepanel.toggle_file_viewed` delegate to the toggle, while `init.mark_viewed`/`unmark_viewed` (via the module-local `set_current_file_viewed`, which maps the buffer with `local/session.relative_path`) call `apply_viewed_state` directly since they set rather than flip. `show()` routes to `show_telescope` / `show_snacks` / `show_quickfix` based on `config.opts.file_list_mode`; snacks falls back to quickfix when snacks.nvim is missing. `open_first_file()` opens the first non-removed file in navigation order (leaving the side panel, the preview, a floating window, or a non-empty-`buftype` buffer for a source window first, `pcall`-guarded, then `sidepanel.reveal_file`); used after `:FudeReviewScopeNext`/`Prev`. Also exports `next_file()` / `prev_file()` for jumping between changed files (used by `:FudeReviewNextFile` / `:FudeReviewPrevFile`); both wrap around at the edges and fall back to the first/last entry when the current buffer is not part of the PR. After a successful edit, they call `sidepanel.reveal_file` to expand the target file's collapsed ancestors, guarded by session identity in case edit autocmds stopped/restarted the session. Navigation order follows the sidepanel file list: when the sidepanel is in tree mode (panel open → its current `file_tree_mode`, panel closed → `config.opts.sidepanel.file_tree`) the full tree render order (including collapsed descendants) is used, otherwise the flat `changed_files` order. The pure helpers `find_adjacent_file_index(changed_files, current_path, direction)` computes the target index; `build_navigation_order(changed_files, tree_mode)` returns the navigation-ordered file list, reusing `ui/sidepanel/tree.lua` (`build_tree`/`collapse_singleton_chains`/`flatten_tree`) for tree order; `count_viewed(viewed_files, changed_files)` counts files with VIEWED state (used by sidepanel header). `next_unviewed_file()` / `prev_unviewed_file()` (`:FudeReviewNextUnviewedFile` / `:FudeReviewPrevUnviewedFile`, bound to `]F`/`[F`) walk the same navigation order but stop only on files that are neither marked `VIEWED` in `state.viewed_files` nor `status == "removed"` (a deleted file cannot be opened and is rarely viewed, so it would otherwise be hit on every wrap-around — `ui/sidepanel.find_first_file_entry` skips removed entries for the same reason). The pure helper `find_adjacent_unviewed_index(files, current_path, direction, viewed_files)` reaches the current file last, so it is returned only when it is the sole unviewed target, and returns nil when there is none; `has_unviewed_target(changed_files, viewed_files)` answers the same question without an ordering, and `goto_adjacent` calls it *before* switching away from the side panel so an empty result does not move the user out of the panel just to report it.
- **`scope.lua`** — Review scope selection and navigation. Provides a Telescope picker (or `vim.ui.select` fallback) for choosing between full PR scope and individual commit scope, with commit index display (`[1/10]`) and current scope marker (`▶`). Supports next/prev scope navigation (`next_scope`/`prev_scope`, which pass an `on_done` that calls `files.open_first_file()` only while focus is still in the triggering window — or in the rebuilt preview when triggered from the preview), marking commits as reviewed via `<Tab>` in the Telescope picker (tracked locally in `state.reviewed_commits`), and statusline integration (`statusline()`). On commit scope: checks out the commit, fetches commit-specific changed files, updates gitsigns base to `sha^` (global), and refreshes the diff preview. On full PR scope: restores the original HEAD, re-fetches PR-wide changed files, and computes merge-base (per-buffer gitsigns base is applied via `GitSignsUpdate` autocmd in init.lua). `apply_scope(entry, on_done)` / `apply_full_pr_scope(on_done)` / `apply_commit_scope(sha, on_done)` accept an optional completion callback invoked (after the sidepanel refresh) only when the scope switch succeeded — never on failure or no-op (both functions short-circuit when the requested scope is already active) — used by the sidepanel to auto-open the first file. Their gh callbacks are guarded by a captured `config.state` identity check plus a module-local request generation counter, so a stale response (session stopped/restarted, or a newer switch requested while in flight) touches neither state, UI, nor `on_done`. A module-local `pending_switch` tracks the in-flight target: while a switch is pending the no-op guards compare against it instead of the stale `state.scope`, so re-selecting the pending target dedupes into the in-flight request and selecting anything else supersedes it. `has_pending_commit_checkout()` reports an in-flight commit switch (its checkout already ran) and `cancel_pending_switch()` invalidates the pending switch — both used by `init.stop()` to restore HEAD correctly mid-switch. `refresh_preview()` restores the caller's focused window after rebuilding the preview (`open_preview` otherwise leaves focus on the source window), and is also used by `local/session.set_scope` for its preview rebuild. Exports `apply_reviewed_toggle(sha)` as a picker-agnostic state mutator that toggles `state.reviewed_commits[sha]` and returns the updated display fields `{ is_reviewed, reviewed_icon, reviewed_hl }`; both the Telescope adapter `toggle_reviewed_in_telescope` and the snacks adapter `toggle_reviewed_in_snacks(picker, item)` delegate to it. `select_scope()` routes to `show_telescope` / `show_snacks` / `show_vim_select` based on `config.opts.file_list_mode`; snacks falls back to `vim.ui.select` when snacks.nvim is missing. In local review mode the same three commands work through the local session: `select_scope()` delegates to `local/session.select_scope()`, and `next_scope`/`prev_scope` pick the neighbour of the current entry in `local/session.scope_specs` order with the pure `find_adjacent_local_scope(specs, direction)` (wraps at both ends like the GitHub helpers; first/last entry when none is flagged current; nil for an empty list), then call `local/session.set_scope`, running the same focus-guarded `open_first_file` callback only when it returns true — `set_scope` reports its own refusals (checkout blockers, unresolvable base), so nothing is notified twice; when the neighbour is the current entry itself (only one scope available) an INFO is shown and `set_scope` is not called.
- **`stack.lua`** — GitHub stacked PR navigation for review mode (`:FudeReviewStackSwitch`). `select_stack()` (GitHub review only) fetches the stack via `gh.get_pr_stack`, builds entries with the pure `build_stack_entries(prs, current_number)` (open PRs plus the current one, `[i/n] #num title (base ← head)` with `i/n` the position in the whole stack, current marked `▶`), and routes the picker by `config.opts.file_list_mode` like `scope.select_scope` (thin `show_telescope` compact dropdown / `show_snacks` select layout / `show_vim_select`; a missing plugin falls back to `vim.ui.select`). The gh callback and the picker selection are both guarded by a captured `config.state` identity check. `switch_to(entry)` decides the case with the pure `resolve_switch_target(worktrees, current_root, branch)` (paths compared after `vim.fn.resolve`): `current` (branch is HEAD here) is a no-op; `switch` (checked out nowhere) stops the review, runs `gh.checkout_pr`, `checktime`s buffers, and restarts the review — on checkout failure it first `git checkout`s the pre-stop `original_head_ref`/`original_head_sha` again, since gh may switch to an existing local branch before failing its `merge --ff-only`, and leaves the review stopped when that restore fails too (HEAD is on neither PR for sure). While the checkout runs, the module-local flag behind `is_switching()` makes `init.start()` and `local/session.start()` refuse with a WARN (shared `refuse_while_switching()`), so no review reads the branch mid-switch or races the callback's `start()`; `cd` (checked out in another worktree) stops the review, `:cd`s there (`pcall`; failure restarts in place), points windows showing old-worktree buffers at the same file in the new worktree (else `enew`) so the layout survives, wipes those buffers, and restarts the review. Old-worktree buffers are those whose deepest owning worktree root (`find_owning_root` over all worktree roots; `is_path_under` rejects sibling prefixes like `/repo-other`) is the current one, so buffers of a worktree nested inside it (e.g. `.claude/worktrees/x`) are neither wiped nor block the switch. Every refusal (modified buffer under the current worktree, tracked uncommitted changes via `git status --porcelain --untracked-files=no` for `switch`, missing target directory for `cd`) happens before `init.stop()`, and a `stop()` that keeps the session active (HEAD restore failure) aborts the switch.
