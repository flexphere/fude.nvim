# `lua/fude/comments/data.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Pure data functions with no state or side effects: `line_from_diff_hunk`, `build_comment_map`, `find_next_comment_line`, `find_prev_comment_line`, `find_comment_by_id`, `get_comment_thread`, `parse_draft_key`, `build_pending_comments_from_review`, `build_review_comment_object`, `build_submit_choices(has_pending_review)` (single/review submit choices, single first; review only while a pending review exists, since GitHub rejects single comments then), `merge_pending_into_comments`, `pending_comments_to_array`, `get_comment_line_range`, `get_multiline_ranges(comments)` (distinct `{ start_line, end_line }` of the multi-line comments in a list; single-line ones skipped), `get_reply_target_id`, `get_comments_at`, `get_comment_lines`, `build_comment_entries`, `build_comment_browser_entries` (one entry per review thread; see Comment browser thread identity below), `merge_draft_entries` (flags existing entries with `has_draft` for matching reply/edit/issue drafts or an unambiguous line range and appends `type="draft"` rows for new line/suggest/issue drafts, then re-sorts by `last_ts`), `build_pr_level_comments(issue_comments, reviews)` (issue comments plus non-PENDING reviews with a non-blank body — or with any body when the state is in `STATES_SHOWN_WITHOUT_BODY` (APPROVED / CHANGES_REQUESTED / DISMISSED), so an approval without a comment is listed while the empty COMMENTED review every standalone review comment creates is not — converted to issue-comment-shaped objects — `created_at` from `submitted_at`, `review_state`, `is_review_summary = true` — merged oldest first with id as the tie-break; type-checks nested fields since they may be JSON null), `find_thread_key(comment_id, comments, thread_map)` (the id `gh.get_review_threads` indexes the comment's thread under: the root, or the earliest reply keyed in `thread_map` when the root was deleted on GitHub), `find_editable_comment(comments, github_user)` (the user's most recent comment in a thread that is not a review summary — the target of the browser's `e`/`d`, since a review body is edited through another endpoint and cannot be deleted), `find_comment_url(comment, pending_review_id, is_local)` → `url|nil, reason` (the comment's `html_url` for the `o` keys; refused for local review comments and for comments of the viewer's pending review, which GitHub has not published). `build_pr_level_comments` also carries a review's `html_url` (`#pullrequestreview-<id>`) onto its review-summary comment so `o` can open it.
