# `lua/fude/comments/sync.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

GitHub API sync/submit operations: `load_comments`, `sync_pending_review`, `submit_as_review`, `create_single_comment` (immediately published line/range comment on HEAD via `gh.create_comment`/`gh.create_comment_range`; fails early while `has_pending_review()`), `toggle_resolved(comment_id, cb(err, resolved))` (fetches the threads fresh — `state.thread_map` is only kept while a pending review exists and `is_resolved` is absent when `resolved.show` is false — then flips the thread via `gh.set_review_thread_resolved` and refreshes silently so the result message stays visible; `state.resolving_thread` refuses a second toggle until the first one's mutation *and* refresh land, since both would read the same state and send the same mutation, and a later refresh finishing first would be overwritten by the older one; both gh callbacks drop a response that arrives after `reset_state()` before any error branch), `has_pending_review` (true when `pending_review_id` is set or `pending_comments` is non-empty — the latter covers the first `sync_pending_review` round-trip before the ID arrives), `reply_to_comment`, `edit_comment`, `delete_comment`. `load_comments` is the main entry point: it runs the module-local `fetch_comments` with `detect_pending`, which requests the reviews listing (`GET /pulls/{pr}/reviews`, the viewer's pending review), the submitted comments (`GET /pulls/{pr}/comments`) and — when `outdated.show` or `resolved.show` is on — the review threads in parallel, adds the pending review comments (`GET /reviews/{id}/comments`) and, for its `thread_map`, the threads as soon as the listing reports a pending review, and assembles everything once a barrier over the requests in flight settles (one extra count held while starting them, so a mock answering at once cannot finish early); every other refresh (`fetch_comments` without `detect_pending`) uses the same barrier with the pending state already known, converting `position` to `line` via `line_from_diff_hunk` and building both `comment_map` and `pending_comments`. Also fetches review threads via GraphQL (skipped when `outdated.show` and `resolved.show` are both false and no pending review exists) and applies `is_outdated` (root comments only, gated by `outdated.show`) and `is_resolved` (per-thread state, propagated to replies via `in_reply_to_id`, gated by `resolved.show`) to comment objects. `comment_map` always includes resolved comments (the resolved-visibility toggle acts only on inline-box rendering in `ui/extmarks.lua`). Internal `fetch_comments` is used by other functions for refreshing after mutations. `fetch_pr_level_comments(pr_number, cb)` requests `issues/{pr}/comments` and `pulls/{pr}/reviews` in parallel (barrier count derived from the operation list) and hands `data.build_pr_level_comments` the results, treating a failed listing as empty so the other is still shown; used by `overview.lua` and `ui/comment_browser.lua`. Uses lazy `require("fude.ui")` to avoid circular dependencies.
