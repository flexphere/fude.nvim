# PR overview

Module details for `lua/fude/overview.lua`. Moved verbatim from the former "Module Responsibilities" section of `CLAUDE.md`; update this file when these modules change.

Overview metadata contract: `gh.get_pr_overview()` requests PR-wide `changedFiles`/`additions`/`deletions` and `commits` (only its length is used: gh has no field for the count alone). gh's query is `commits(first: 100)` without paging, so a list of `format.COMMIT_LIST_LIMIT` (100) commits is shown as `commit_count: "100+"` (quoted, the quotes in `Normal`). `ui/format.build_overview_left_lines()` starts with YAML frontmatter (`state`, `author`, `base`, `head`, `url`, `commit_count: 6`, `file_changed: 10`, `line_changed: "+70 -6"`), using JSON-quoted strings as YAML scalars. Unknown commit and file counts are omitted (`commits` that is not a list, e.g. JSON null, is unknown); the line-count pair is omitted if either count is unknown. The commit count, file count and signed line counts use `ReviewCommitCount` (commits) and `ReviewFileCount` (files), both using the URL's `Underlined` foreground without underline, `DiagnosticOk` (additions), and `DiagnosticError` (deletions); `ui.show_overview_float()` honors optional `col_start`/`col_end` in left-pane highlight ranges. The quotes and space around the signed line counts use `Normal`. The frontmatter is followed by `# #<number> <title>` and the unmodified body (except newline normalization), without a synthetic DESCRIPTION heading. `sections.description` points to the first body line or the no-description placeholder, so `'d` and `]s`/`[s` follow the body start. Comment positions remain derived from the generated lines. Folding follows the remaining Markdown headings; there is no separate DESCRIPTION fold.

- **`overview.lua`** — PR overview display: fetches extended PR info and the PR-level conversation via `comments/sync.fetch_pr_level_comments` (issue comments plus submitted review bodies — GitHub shows a review's summary as a comment in the Conversation tab but serves it from `pulls/{pr}/reviews`, so `issues/{pr}/comments` alone misses every Approve / Request changes / bot-overview body), renders in a centered float with keymaps for the `C` menu, refreshing, and re-requesting a review (`r` selects a reviewer who already reviewed via `vim.ui.select` and posts to the `requested_reviewers` endpoint through `gh.re_request_review`). Prefetch: `prefetch(opts?)` (called by `init.start()` once the GitHub session is set up — with `opts.pr_info`, the body the PR lookup already fetched, which `fetch_overview` then uses without a body request, and `opts.on_ready`, run once the body is cached while the session is active — and by `init.reload()` outside the reload barrier; a no-op outside a GitHub review) runs the module-local `fetch_overview(state, cb, body?)`, whose waiters run as soon as the PR body arrives — `gh.get_pr_overview(cb, state.pr_number)` (the number is passed so `gh pr view` never infers the PR from a possibly detached HEAD), without the reviewers and the checks — with a bundle `{ pr_info, pr_comments }`. The parts that take longer are separate requests sent alongside (after the body only without a session PR number): `gh.get_pr_reviewers`, `sync.fetch_pr_level_comments` and `gh.get_pr_checks`. Each is kept on the fetch entry until the bundle exists (`entry.parts`, applied before the waiters run) and then handed by the module-local `deliver(bundle, kind, result)` to the bundle (the pure-ish `apply_part`: `reviewRequests`/`latestReviews` or `reviewers_failed`, clearing `pr_info.reviewers_loading`, which the body arrives with; `pr_comments`; `statusCheckRollup` or `checks_failed`) and to every open float in the module-local `waiting_floats` (`{ bundle, handle }`, registered by `open_overview` while `is_loading(bundle)`) built from that same bundle, through `handle.set_reviewers()` / `set_comments(comments)` / `set_checks(checks, failed)`; parts are delivered whichever session is active, since they describe that PR. The bundle is stored as `state.overview_cache` when `state` is still `config.state`, so the cache gains the parts as they land; a failure is silent. The reviewer flows (`edit_reviewers`, `re_request_review`) refuse through the module-local `reviewers_ready` while `reviewers_loading` (INFO) or after `reviewers_failed` (WARN). `fetch_overview` keeps the module-local `fetch_in_flight` (`{ state, waiters, stale }`): a call for the same session joins it as another waiter instead of sending a second request, a call for another session starts its own, every waiter runs once (also after a session change — each checks `config.state` itself), and a response arriving after a stop is not cached (nor are the old PR's comments fetched). `show(opts)` opens the overview at once from `state.overview_cache` unless `opts.fresh` (the overview's `R` and the reopen after `create_comment` posts pass it; `:FudeReviewOverview` and the menu's cancel reopen do not); otherwise it goes through `fetch_overview` (joining an in-flight prefetch) and the result refreshes the cache. The module-local `invalidate_cache()` — called after a successful reviewer/label toggle (`run_toggle`) and re-request — clears the cache and marks a fetch in flight `stale` so its pre-change data is not cached, since the editors do not reopen the overview and the next `:FudeReviewOverview` must show their result. Without cached data, `show()` first opens `ui.open_overview_loading()` (the overview's two panes at the overview's own position and size, the left one titled like it and holding the toggle picker's spinner plus `Loading PR overview…` centred in it; `q`/`<Esc>` close it) and closes it on every terminal path — a closed placeholder when the data arrives means the user gave up, so the overview is not shown; a `show()` while the module-local `loading_in_flight` placeholder (kept with the `config.state` it was opened for) is still open is dropped when it belongs to the same session, since it would stack a second placeholder and later a second overview, while another session's placeholder (stop → start during the fetch) is closed and replaced, since its callback would only close it anyway; `show()` keeps the `config.state` it was called in and drops a response that arrives after a stop; the float's `C`/`r` pass that state to `open_menu(pr_info, captured_state)`/`re_request_review(pr_info, captured_state)`, and every flow (menu open, menu choice, `edit_reviewers`, `edit_labels`, `re_request_review` and its choice) refuses with a WARN through the module-local `ensure_current` once that session is gone, since the float can stay open across stop → start and its `pr_info` belongs to the old PR. A nil `captured_state` ties the flow to no session (`is_current(nil)` is always true): that is how `:FudeEditReviewers` / `:FudeEditLabels` (`edit_current_reviewers()` / `edit_current_labels()`, through the module-local `edit_current_pr(what, open)`) open the same editors without the overview — refused in the local commit scope like `pr.change_state`, the PR resolved by `gh.get_pr_edit_info` (the review session's `pr_url` — a URL rather than the number, since gh resolves a bare number against the cwd's repository, which a `:cd` may have moved — else the current branch's / the commit's), "no PR" a WARN and any other failure an ERROR — since the fetched `pr_info` fixes the PR they edit and a later stop → start cannot make it stale. Every editor API call passes the PR's repository (`drafts.repo_slug(pr_info.url)`, module-local `pr_repo`) as the `repo` argument, so a `:cd` into another repository while a picker is open cannot retarget it. `C` runs `open_menu`, a `vim.ui.select` over `M.MENU_ITEMS` (Comment → `create_comment`, Reviewer → `edit_reviewers`, Label → `edit_labels`). `edit_reviewers` lists `gh.get_collaborators` (a failure — it needs push access — falls back to an empty list with a WARN, so requested/reviewed users stay editable) through `format.build_reviewer_entries`, and `edit_labels` lists `gh.get_repo_labels` (same fallback) through `format.build_label_entries`; both open `ui/toggle_picker`, whose `on_toggle` goes through the module-local `run_toggle` (refuses with a WARN once the captured session is gone, since the picker can outlive `:FudeReviewStop`; notifies success/failure) to `gh.re_request_review` (notified as a re-request when the user already reviewed)/`gh.remove_review_request` or `gh.add_labels`/`gh.remove_label`. The overview float is closed before every flow; only the menu's cancel reopens it, through the module-local `make_reopen` (captured `config.state` identity plus `active`), while the reviewer / label editors and `r` never do — closing their picker or select (or finding no rows / candidates) ends the flow, success or failure, and the user reruns `:FudeReviewOverview` to see the result.
