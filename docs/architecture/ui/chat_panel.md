# lua/fude/ui/chat_panel.lua

The chat panel: a top-level vertical split (`win = -1`, `chat.position`, `calculate_panel_width`) with the conversation log on top (nofile, not modifiable, filetype `markdown`) and the input below (nofile, `INPUT_HEIGHT` 8, less on a short screen; deliberately not `b:fude_comment`, so `ui.close_comment_ui` / `has_unsent_comment_input` ignore it). State: `state.chat_panel` (`{ log_win, log_buf, input_win, input_buf, augroup, prev_win, split, … }`), `state.chat_live` (the exchange being answered: `{ key, prompt, text, activity }`, apart from the panel so an answer keeps arriving while the panel is closed and a reopened panel shows it) and `state.chat_input` (the unsent input: a copy kept current while the panel is open — the module-local `sync_input(panel)` runs on the input buffer's `TextChanged`/`TextChangedI`/`TextChangedP`/`InsertLeave`/`BufUnload` and after every change the module makes — so it survives however the pane goes away, `:q`, `:bwipeout`, `:only`, `:tabclose` included, without a hand-over at close time when the `bufhidden=wipe` buffer may be gone already; `open()` fills the input from it; cleared by a submit and by `teardown()`). `toggle()` mirrors `sidepanel.toggle` (open → focus the input → close from either pane; another tabpage's panel is reopened here); `open()` renders `chat.load(key)` plus the live exchange; `close()` keeps the input, stops the spinner and leaves a running answer alone. Whenever a command moves focus to the input (`open`, `toggle`'s focus, `add_selection`) the module-local `focus_input` puts the cursor at the end of the input and runs `startinsert!`, so typing continues a restored or half-written question instead of landing in front of it; `close()` from a pane runs `stopinsert`. `submit()` (the `chat.keymaps.submit` key, normal mode, input pane) refuses with an INFO while `chat.is_running()`, ignores an empty input, appends `format_question_lines`, clears the input and calls `chat.send` with the module's handlers — which read `config.state` at call time instead of capturing a panel: `on_text` appends to the log's last line, `on_tool` sets the activity, `on_retry` only clears the replaced process's activity (the new-session note arrives as answer text), `on_done` writes `format_answer_end_lines`, on an error that was not stored (`result.stored` false) puts the question back in front of the input (or into `chat_input` when the panel is closed) — a stored failure's question stays out of the input — with an ERROR notification when the panel is not visible, and on success with the panel closed notifies INFO once that the answer is ready (a panel open in another tabpage counts as closed for both notifications, though its log is still written). Log changes go through the module-local `update_log`, which follows the end only when the log window's cursor was on the last line. Progress is one `virt_text` (eol) extmark on the last line in the `fude_chat_progress` namespace — spinner frame from `toggle_picker.format_loading_mark` plus `THINKING_TEXT` or the tool label — advanced by `ui.start_spinner`, so the buffer text never changes per frame (same reason as `draw_spinner_frames`). `cancel()` (`chat.keymaps.cancel`, both panes) calls `chat.cancel()`; `new_chat()` (`:FudeReviewChatNew`) calls `chat.discard` and re-renders; `add_selection(line1, line2)` (`:FudeReviewChatAdd`) appends `build_selection_text` for the current buffer to the input, opening the panel when needed — the path comes from the module-local `resolve_selection_path`: relative to `chat.current_root()`, the directory claude runs in (else the `~`-shortened full path — Neovim's cwd may be another worktree by then, and a path relative to it would name a different file to claude), `format_base_path` for the diff preview's base pane (`state.preview_buf`, named `[base] <path>`, whose lines and numbers are the base version's), a refusal (WARN) for any other special buffer, named or not (`buftype ~= ""` is checked before the name, so the comment browser, a comment input or the overview is never pasted as `[No Name]`) and for the chat panes themselves, and nil (`[No Name]`) only for an unnamed ordinary buffer. Every entry point checks `state.active` and `chat.is_available()` (WARN, nothing done). Window rules follow the side panel: both panes set `winfixbuf` (when the option exists), so `:edit` or another plugin's picker in a pane is refused (E1513) instead of replacing the pane and wiping the input buffer (`bufhidden=wipe`); fude's own open paths leave the pane first (`files.leave_panel_window`). A pane counts only while its window still shows its buffer (module-local `shows(win, buf)`, used by `get_panel` and `is_panel_window(win)`): after a forced `:buffer!` the window is the user's, `is_open()` is false, and `close()` — hence the next `toggle()` — leaves that window open, only resetting the pane options on it (`sidepanel.reset_window_options`). `is_panel_window(win)` lets `sidepanel` and `files` leave the panes alone; `tabpage()` is the open panel's tabpage. When the panes are the only windows left, the panel's WinClosed handler opens `sidepanel.open_editor_window` at the opposite edge — from inside a pane (`nvim_win_call`), because `win = -1` means the current tabpage, which need not be the panel's when the scheduled work runs; focus moves there only when a pane was the current window — and sets the panes back to `panel.width` (`restore_width()`, also called by the side panel when it reopens the editor window for both) (the new top-level split would otherwise leave them half the tabpage; `winfixwidth` only protects a size from later changes), and a `:quit` of the last editor window (tracked through `QuitPre`) closes the panel and quits too — both only while no side panel is open *in the same tabpage* (module-local `shares_tabpage_with_sidepanel`), since the side panel then owns that job, while a side panel in another tabpage looks after that tabpage only. Closing either pane closes both — at once, except when the current window is the remaining pane (`:only` from a pane) or shows a pane buffer (`<C-w>T` in a pane, which opens a new window on the buffer in a new tabpage and then closes the pane): closing the current window inside WinClosed aborts the command with E855, so that close is scheduled. The `:only` case passes `close({ keep_last_window = true })`: a pane that is the only window of its tabpage (module-local `is_last_in_tabpage`) is turned into an ordinary window rather than closed, so `:only` never closes the tabpage when others exist, while `<C-w>T` still closes the moved pane with its new tabpage. `close(opts)` closes every window on the two pane buffers (`win_findbuf`), not only the two the panel opened, so a pane moved to another tabpage or split does not stay behind untracked. When `close()` cannot close a pane because it is the last window, the pane is turned into an ordinary window (`reset_window_options`, then `enew`) instead of keeping the pane's options and size / buffer pins. `submit` also registers a one-shot `VimLeavePre` (`fude_chat_exit`) that cancels the answer so claude does not outlive Neovim. `teardown()` (called by `init.stop()` / `local/session.stop()` before `reset_state()`, in both only after the HEAD restore succeeded — a stop that keeps the session keeps the chat) cancels the running answer — stored as interrupted — and closes the panel.
