# `lua/fude/ui/sidepanel.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

## Commit review marks

`<Tab>` toggles a commit's reviewed state in both GitHub and local review, without switching scope or checking out HEAD. `scope.build_local_scope_entries(specs, reviewed_commits)` renders local marks from the same session-local `state.reviewed_commits` map as GitHub review. `sidepanel.toggle_scope_reviewed` delegates updates to `scope.apply_reviewed_toggle` and refreshes the panel. Non-commit local scope rows keep their `<Tab>` scope-switch behavior; `<CR>` switches all scope rows as before. Commit marks are not persisted across review stops or Neovim restarts.

Toggleable side panel (a split at a tabpage edge) showing Review Scope and Changed Files. Files default to a flat list (`sidepanel.file_tree = "flat"`); `"tree"` groups files by directory via `ui/sidepanel/tree.lua`. Formatting/navigation helpers: `format_scope_section`, `format_files_section(file_entries, width, format_path_fn, viewed_count, current_path, opts)`, `format_files_section_tree(tree_entries, total_file_count, width, viewed_count, current_path, opts)`, `build_sidepanel_content` (optional trailing `message_section` placed between scope and files, so the files offsets shift), `resolve_entry_at_cursor`, `find_first_file_entry(file_entries, tree_entries)` (first non-directory, non-removed entry in display order; tree entries take precedence), `build_selectable_lines(section_map)` (1-based panel lines `next_entry`/`prev_entry` stop on: scope/file entries including directories, plus the commit message rows from `section_map.message_start`/`message_end`; headers/separators/blanks excluded), `find_adjacent_selectable_line(cursor_line, selectable_lines, direction, count)` (the selectable line `count` steps away — `count` defaults to 1 — resolved by index in one scan, clamped at the edges, no wrap). **Commit Message section**: shown only in a commit scope (GitHub `state.scope == "commit"` reads the full message from the raw `state.pr_commits` via the pure, type-defensive `find_pr_commit_message(pr_commits, sha)`; local `session.in_commit_scope()` reads `diff.get_commit_message(sha, worktree_root)`, cached per sha on `panel.commit_messages` because render runs on every BufEnter; failures are not cached, so a transient git error is retried). The pure `format_commit_message_section(message, width, max_lines, expanded, toggle_lhs)` → `lines, highlights, foldable` wraps rows to the panel width (breaking at the last space) and, unless `expanded`, folds rows past `sidepanel.commit_message.max_lines` (default 8, min 1, counted after wrapping) into a `… N more lines (m: expand)` hint, itself wrapped rather than truncated so a narrow panel still shows the key (a row is broken at the last space, kept whole when it ends exactly at a word boundary, and the space it broke at never starts the next row); the section changes the rows above Files, so `refresh` restores the cursor through the pure `calculate_restored_cursor_row(row, old_map, new_map, line_count)`, which moves a cursor at or below the Files header by the `files_entry_offset` change so it stays on the same entry and keeps a cursor inside the message within the message's new last row (`follow_current_file` uses it too when there is no current file to follow); the `toggle_commit_message` keymap (`m`) flips `panel.commit_message_expanded` (panel-lifetime) only when render marked `panel.commit_message_foldable`, else notifies INFO. `j`/`k` stop on the section's rows (hint line included), while `<CR>`/`<Tab>` do nothing there since `resolve_entry_at_cursor` maps no entry to them. The Files section header displays viewed/total count (e.g., "Files (Reviewed: 3/10)"). Flat/tree rows share a formatter with fixed current/viewed/status columns, indented fold indicators/icons/names, and right-aligned additions/deletions. Status labels are M/A/D/R/C (sidepanel-only), using foreground highlight groups DiagnosticWarn/DiagnosticOk/DiagnosticError/DiagnosticInfo/DiagnosticInfo respectively (unknown status uses Comment), not the background-oriented Diff* groups. Viewed/unviewed marks use `signs.viewed`/`signs.unviewed` and their `_hl` settings (defaults ✓/○); expanded directories never show review marks; collapsed directories with files show the viewed mark only when all descendants are viewed, otherwise the unviewed mark. `panel.collapsed_dirs` stores directory-path fold state until panel close; `render` passes it to `flatten_tree`, and `<CR>` toggles it without moving the cursor. Folder icons switch between open () and closed (); directory arrows (▾/▸) render even without devicons. `render` resolves file marks and optional nvim-web-devicons icons (`sidepanel.icons`, default true) before formatting; the formatters receive these values as arguments (tree formatting also receives `opts.all_file_entries` to keep column widths stable across folds), use `vim.fn` display-cell widths and byte highlight offsets, and truncate names without altering entry paths. Narrow rows reduce indentation/omit icons, and hide stats when complete counts cannot fit beside the fixed columns and a name cell. The currently open file is marked with `▶` (`DiagnosticInfo` highlight), matching the Review Scope marker pattern; cursor follows the active file (or its collapsed ancestor) via `follow_current_file`. Side-effect functions: `open`, `close`, `toggle` (opens when closed, focuses the panel when open but unfocused, closes when the panel is the current window; a panel in another tabpage is reopened in the current one), `refresh`, `follow_current_file`, `reveal_file(path)` (expands all folded ancestors of a next/previous-file target, preserves unrelated folds and source-window focus, then follows the current file), `toggle_file_tree_mode`, `move_to_adjacent_entry(panel, direction, count)` (entry-wise cursor movement for the `next_entry`/`prev_entry` keymaps), `open_file`, `open_first_file()` (opens the Files section's first openable file, including hidden descendants via `files.build_navigation_order`, after a scope switch via the panel's `<CR>`; reads `state.sidepanel` at call time — not a captured table — and guards `state.active`, panel window validity, panel focus (staleness check for async completion), and target-window availability (silent no-op), wrapping `open_file` in `pcall` so an `:edit` failure inside a gh callback surfaces as a notify instead of a stack trace; both manual selection and auto-open delegate positioning to `files.open_file`). `close` restores focus to `panel.prev_win` (the window the panel was opened/focused from) only when the panel is the current window, without `noautocmd` so BufEnter re-syncs extmarks/keymaps/preview. Panel window options are set from `PANEL_WIN_OPTIONS` with `scope = "local"` because the panel is the current window in `open` and `vim.wo[win]` would also change the global values. When any other window closes, the WinClosed autocmd schedules `ensure_editor_window(panel)`, which opens a split opposite `panel.split` showing the most recently used listed buffer (or a new empty one) when `is_last_normal_window(panel.win)`, resets the `PANEL_WIN_OPTIONS`/winfix options to their global values, and sets `panel.prev_win` to it; otherwise the next file opened (e.g. from snacks.picker, which falls back to the last non-float window) would land in the panel window with its `nonumber`/`signcolumn=no`. A `:quit`/`:wq`/`:x`/`ZZ` is the exception: the panel's `QuitPre` autocmd records the quitting window in `panel.quitting_win` (cleared on the next tick, so a refused quit does not linger), and when that window's WinClosed fires, `quit_if_alone(panel)` runs `:quit` in the panel instead, so Neovim exits (or the tabpage closes) as it would without the panel; if that quit is refused it notifies and falls back to `ensure_editor_window`. `:bdelete`/`:close` fire no `QuitPre`, so they still reopen a window. Uses `nvim_open_win` with `split` and `win = -1` (top-level split) for panel creation, so the panel always opens at the tabpage edge regardless of the focused window; the pure `build_split_config(position, width, height, max_height)` maps `sidepanel.position` (`left`/`right` sized by `width` with `winfixwidth`, `top`/`bottom` → `above`/`below` sized by `height` with `winfixheight`, unknown → `left`); `open` passes half the editor rows as `max_height`, which wins over the 5-line minimum, because `winfixheight` keeps `equalalways` from giving a short screen's rows back to the source/preview windows. Uses dedicated `fude_sidepanel` namespace for highlights (avoids `refresh_extmarks` clearing them on BufEnter). Auto-refreshes on scope change, reload, BufEnter (to update the current-file marker), and panel width changes. The panel-owned WinResized autocmd compares actual window width with `panel.rendered_width` (rather than matching only the event's first window) and is removed with its augroup on close. Panel-local mappings are configurable with `sidepanel.keymaps` and registered with `nowait` unless `sidepanel.nowait = false` (so a global mapping such as `cs` does not delay a panel `c` by `timeoutlen`); defaults are `<CR>` select/open/fold (on a directory: toggle descendants; on a scope entry: switch scope, then auto-open the first file of the new scope — local mode keys off `set_scope`'s return value, GitHub mode passes an `on_done` callback to `scope.apply_scope`; nothing opens on failure/no-op), `<Tab>` toggle reviewed/viewed, `j`/`k` move to the next/previous selectable entry (count-aware, no wrap; includes directories; skips headers, separators, and blanks; when two actions resolve to the same key, the first-registered action wins so an explicit user mapping is not overwritten by a newer default), `t` toggle flat/tree, `R` reload, `q` close, `m` (`toggle_commit_message`) expand/collapse a folded commit message, `y` (`copy_path`) runs `pick_path_to_copy(panel)`: on a file or tree-mode directory it offers the choices of the pure `build_copy_choices(rel_path, root)` (`filename:` / `relative_path:` / `absolute_path:` keys padded so the values start in one column, root from `panel.repo_root` — the root the panel renders and opens files with, so a `:cd` after opening it does not change the path — falling back to `diff.get_repo_root()`) through `vim.ui.select` with `kind = "fude_copy_path"` (so dressing/snacks users can configure that picker, e.g. open it in normal mode) and copies the pick with `util.copy_to_clipboard`; on a Review Scope commit row (GitHub or local) it offers the pure `build_commit_copy_choices(sha, short_sha, subject)` instead (`hash:` / `short_hash:` / `commit_subject:` / `commit_message:` — a multi-line message is labeled, and notified, as its first line plus `… (N lines)` while the whole text is copied — with the message from the module-local `commit_message_for(panel, sha)`, shared with the Commit Message section: GitHub reads `state.pr_commits`, local reads `diff.get_commit_message` cached on `panel.commit_messages`; the title and short hash come from the scope entry's `short_sha`/`subject`, which `scope.build_scope_entries` and `build_local_scope_entries` — via `local/session.build_commit_specs` — carry so the title is not parsed back out of `display_text`) with `kind = "fude_copy_commit"`; on a local base/unpushed row it offers the entry's `branch:` (`kind = "fude_copy_branch"`) (the base branch, or the upstream ref without its remote via the pure `local/session.strip_remote` — remote names are taken to contain no `/` — set by `local/session.scope_specs` and carried by `scope.build_local_scope_entries`); every row — and any other line, alone with prompt `Copy PR info` and `kind = "fude_copy_pr"` — also gets the PR-wide choices of the pure `build_pr_copy_choices(info)` (`head_branch:` / `pr_number:` / `pr_url:` / `pr_title:` from `state.head_ref`/`pr_number`/`pr_url`/`pr_title`; local review offers only `head_branch` from `local_session.branch`; missing values and a detached `HEAD` are left out), appended after the entry's by the pure `merge_copy_choices(entry_choices, pr_choices)`, which drops `head_branch` when the entry's `branch` has the same name and pads every key to one column; in local review the fallback prompt is `Copy branch` with `kind = "fude_copy_branch"`; with no choice at all it notifies INFO, `o` (`open_in_browser`, registered only outside local review mode, the reverse of `change_base`) opening the GitHub page from the pure `build_scope_url(entry_info, pr_url, review_mode)` → `url|nil, reason` (Entire PR → the PR, commit row → `<pr_url>/commits/<sha>`, the commit inside the PR; local review scopes, file rows and a missing PR URL are refused with the reason) through `util.open_url`, and — registered only in local review mode, since a PR's base belongs to GitHub — `b` (`change_base`) opening `local/session.select_base()`.

## Sidepanel quick help

`sidepanel.keymaps.help` defaults to `?` and is registered last. `setup_keymaps` stores successfully registered `{ action, lhs, desc }` entries in `panel.help_mappings`; key collision checks normalize termcodes (e.g. `<Tab>` / `<C-i>`), preserving first-registration priority. The footer below Files advertises only an effective help key. `build_help_lines(mappings, review_mode)` reuses these entries, describing the local scope action separately; it centers keys in a display-cell-width column sized to the longest configured key and aligns descriptions, including the help-only close row. `toggle_help(panel)` opens a read-only float with `float.border` and twice-content dimensions clamped to the screen, tracked by `panel.help_win`; `q` in that float calls `close_help(panel)` independently of the panel's close mapping. Open/close suppress autocmds so the review `BufEnter` handler does not move the panel cursor; no fold state is changed. Direct help closure clears its handle through the panel's WinClosed handler; panel close and review teardown also close the help.
