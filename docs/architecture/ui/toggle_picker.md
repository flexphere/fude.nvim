# `lua/fude/ui/toggle_picker.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Picker whose rows are toggled in place (the overview's reviewer/label editors). `open({ title, items, on_toggle(item, done), on_close })` with items `{ text, on, detail, value }` routes by `file_list_mode` to `show_telescope` (dropdown; `<Tab>` toggles, the display function re-reads `item.on`, and `selection_strategy = "follow"` keeps the selected entry across refreshes, while `tiebreak` returning false keeps the given order among rows of the same score — every row with an empty prompt — so applied labels / requested reviewers stay on top and toggling never reorders the list (Telescope's default sorts ties by ordinal length); close is detected by the prompt buffer's `BufWipeout`) / `show_snacks` (`select` layout; `sort.fields = { "score:desc", "idx" }` for the same reason — snacks breaks ties by text length first by default; `<Tab>` action `fude_toggle`, re-render via `picker.list:update({ force = true })`, close via `on_close`) / `show_vim_select` (no `<Tab>`: choosing a row toggles it and the select reopens; cancel closes); a missing plugin falls back to `vim.ui.select`. `new_session(opts)` holds the in-flight items and the close request; `session.close()` runs `on_close` once, and only after every in-flight request settled (`finish()` re-checks on each settle), so whatever it does sees GitHub after the last toggle (the overview's editors pass no `on_close`: closing the picker ends the flow). `toggle_item(item, opts, session, on_done)` flips `item.on` and `run_extra_action(item, opts, session, on_done)` sets it to `opts.extra_action.result_on`, both through the module-local `run_item`: the change applies only when the request reports success, a request for an item whose previous one is in flight is ignored, and it settles once. While a request is in flight `session.pending[item]` is set, and `resolve_mark(item, session)` then returns the loading mark of the session's current frame (`format_loading_mark(frame, width)`: `LOADING_FRAMES`, the gh CLI's braille spinner `⣾⣽⣻⢿⡿⣟⣯⣷`, padded with spaces to the display width of the mark it replaces — so the name does not move whatever the mark's width; `LOADING_HL` = `DiagnosticInfo`) in place of the item's mark, keeping the item's name highlight; Telescope and snacks re-render when a request starts (`started` from `toggle_item`/`run_extra_action`) and again once it settled, success or failure, so the old mark comes back after a failure. The spinner is a `vim.uv` timer on the session (`start_spinner`/`stop_spinner`/`tick`, every `LOADING_INTERVAL_MS`): started by the first in-flight request, it advances `session.frame` and calls `session.rerender` — set by the Telescope adapter (refresh through the picker current at tick time) and the snacks adapter (`list:update`) before they run a request — and stops with the last request or when the picker closes (the `vim.ui.select` fallback sets no `rerender`, since its select is closed while a request runs, so no timer starts and it never shows the loading mark). `opts.images(item, cb)` (Telescope / snacks only) is asked once per item by `session.load_images()` — scheduled after the picker is on screen; the first `IMAGE_FIRST` (10) rows at once, the rest alongside them at most `IMAGE_CONCURRENCY` (4) at a time, each answer releasing the next on the next tick, none once the picker is closing — for the file of an image drawn between the row's mark and its name (`IMAGE_HEIGHT` 1 by `IMAGE_WIDTH` 2 cells through snacks.nvim's image module, which draws it `IMAGE_CELLS` = `IMAGE_WIDTH + 2` cells wide inline); answers land in `session.images[item]` (false for none) and `session.request_rerender()` re-renders once per batch. With `opts.images` every row holds `image_slot(opts)` (`IMAGE_CELLS` spaces) between the mark and the name, so the name never moves whether the image is drawn, loading or missing; the placement conceals the slot (`conceal = true` over the `range` found by the pure `find_image_slot(line, text)` in the row as the picker wrote it — Telescope's results window gets `conceallevel=2`/`concealcursor=nvic`, the snacks list window has them already — only as many cells as the image takes, via `on_update_pre`). `place_row_image(buf, row, item, session)` runs right after the picker writes a row — Telescope wraps `entry_adder` (row from `get_row(index)`) and `set_selection` (the caret rewrite), snacks wraps `list._render(item, row)`, both before the screen is redrawn (snacks' dirty render flushes a redraw itself) — and keeps one placement per buffer and item in `session.placed`: rewriting a row hides its extmark (`invalidate`), so the same placement is drawn again at once through `render_grid(_state.loc)` (moved when the item changed rows), skipped while its extmark is still shown in place, and made anew only for a new file; creating placements anew on every refresh left the rows blank until snacks' debounced update and made the spinner flicker. `prune_row_images(buf, keep, session)` closes the placements of items no longer shown — Telescope from a `register_completion_callback` (rows mapped through `get_index` / `manager:get_entry`, also re-placing rows Telescope moved without rewriting), snacks after a dirty `list.render` (its `visible` items). The reviewer editor passes `avatars.fetch` when `avatars.is_enabled()`. `opts.on_confirm(item)` (Telescope / snacks only) turns `<CR>` from close into close-then-`on_confirm` (scheduled) with the row, and `opts.confirm_label` names it in the title through the pure `build_title(opts)` (`<title> (<Tab> toggle, <CR> <label>)`; `(<Tab> toggle)` alone otherwise) — the reaction picker uses it for the people list. `opts.extra_action` (`{ key, label, available(item), unavailable_reason(item), run(item, done), result_on }`, Telescope / snacks only) is a second key: `resolve_action_hint(item, opts)` appends `<key>: <label>` to the rows it applies to (`Special`, or `extra_action.hint_hl(item)` when given — the reviewer picker greys it for an approver, who is rarely re-requested), and on any other row the key only notifies `unavailable_reason` at INFO. The overview's reviewer picker uses it for `<C-e>` re-request (users who reviewed and have no pending request), since nothing on screen says that `<Tab>` on such a row also re-requests. Telescope's default `reset` strategy moves the cursor back to the first row on every refresh; `follow` instead finds the entry selected when the refresh completes (`finders.new_table` builds the entries once, so it is the same table), which also keeps a row the user moved to while a request was in flight. Restoring a remembered row from a completion callback does not work here: the spinner makes refreshes overlap, and the first completion would consume the row the later one needs. In `vim.ui.select` mode the select reopens after a toggle only while `opts.is_alive()` holds (the overview passes its session check), so a stopped session does not loop on refusals. `item.detail` and `item.mark` may be functions, re-evaluated by `resolve_detail(item)` / `resolve_mark(item)` (`mark, mark_hl, text_hl`; default `format_toggle_mark(item.on)`) on every render so they follow `item.on`; Telescope and snacks colour the mark, the name with `text_hl`, and the detail in `Comment`. Rows are formatted by `format.format_toggle_entry` (`● name  (detail)`).
