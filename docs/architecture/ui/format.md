# lua/fude/ui/format.lua

Pure format/calculation functions with no state or vim API side effects: `calculate_float_dimensions`, `format_line_range(start_line, end_line)` (`L20-L29`, nil for a single line), `build_range_start_marker(start_line, end_line)` (`↓ comment L20-L29`, "" for a single line), `build_comment_separator(width?)` (the `---` line between comments; `format_comments_for_display`, `format_reply_comments_for_display` and `format_comment_browser_thread` take an optional trailing `separator_width` that callers set to the window width so the line spans it, falling back to `DEFAULT_SEPARATOR_WIDTH` (40)), `format_comments_for_display`, `build_comments_float_title`, `normalize_check`, `format_check_status`, `deduplicate_checks`, `sort_checks`, `build_checks_summary`, `format_review_status`, `build_reviewers_list`, `build_re_request_candidates` (the `r` candidates, Copilot included under its REST login), `build_reviewer_entries(collaborators, review_requests, latest_reviews, author_login)` (overview reviewer picker rows `{ login, requested, review_state }`: ordered approved, changes requested, commented, dismissed, requested, then the rest, each by the name shown; author, bots, teams, non-collaborator reviewers and PENDING reviews excluded — except Copilot (`COPILOT_REVIEWER`: GraphQL login `copilot-pull-request-reviewer`, REST `api_login` `copilot-pull-request-reviewer[bot]`, shown as `@copilot` via `reviewer_display_name(login)`; `is_copilot_login` accepts both forms), which can be requested unlike other bots and is always listed, since nothing tells in advance whether Copilot code review is enabled (GitHub refuses the request otherwise); entry `login` is the REST form, which `edit_reviewers` sends and shows through the display name — as are collaborators whose `permissions.push` is false, indexed before either list is read so a read-only member who reviewed is excluded too, while a requested user is always kept so the request can be removed), `format_reviewer_detail(requested, review_state)` (`review requested, last review: dismissed` — the request and the latest review stated separately), `format_review_state_label(state)` (`CHANGES_REQUESTED` → `changes requested`), `build_label_entries(repo_labels, pr_labels)` (`{ name, description, applied }`, applied first; a PR label missing from the repository listing is kept so it can be removed), `format_toggle_mark(on)` (label rows: `●`/`○`), `format_reviewer_mark(requested, review_state)` (reviewer rows, GitHub web UI marks: requested `●` DiagnosticWarn — wins over the previous review —, approved `✓` with the name in DiagnosticOk, changes requested `✗`, commented `COMMENTED_MARK` (the Nerd Font `nf-oct-comment` glyph, one cell like the other marks), dismissed `↻`, else `○`; every other user without a pending request except a dismissed one gets a `Comment` (grey) name; returns `mark, mark_hl, text_hl`), `format_toggle_entry(text, mark, detail)`, `build_reviewers_summary`, `build_centered_lines(text, text_width, width, height)` (one line of text in the middle of a window; returns the lines plus the 0-based row and byte column of the text), `calculate_overview_layout`, `calculate_overview_full_width(layout)` (the left pane's width with the right pane hidden), `calculate_comments_height`, `calculate_reply_window_dimensions`, `format_reply_comments_for_display` (also returns 0-indexed `comment_ranges`, like `format_comments_for_display`), `find_comment_index_at_line(comment_ranges, line)` (the comment a 0-indexed line belongs to; separators/headings/footers belong to none — used by the `o` keys), `build_overview_left_lines` (also returns 0-indexed `comment_ranges` over the issue comments, and `avatar_positions` — the `author:` line and the byte column after `author: `, kind `author`, and each comment heading after `### `, kind `comments`; `set_comments` re-places the left pane's avatars after `ui/avatars.clear`), `build_overview_right_lines(pr_info, opts)` (also `avatar_positions`: each reviewer line, after its status symbol, kind `reviewers`, and each assignee line at column 0, kind `assignees`; each label is a one-line pill from `build_label_pill(name, name_hl, cap_hl, display_width)` (`LABEL_PILL_LEFT .. pad .. name .. pad .. LABEL_PILL_RIGHT` — Nerd Font round ends, `LABEL_PILL_PADDING` inside — with `width` in display cells by `opts.display_width`, `strdisplaywidth` from `ui.show_overview_float`), laid out side by side, in the PR page order (the reverse of gh's), by `pack_label_pills(pills, width)` (`LABEL_PILL_GAP` between them, a new row once `opts.labels_width` — the right pane's width — would be exceeded); a label with a valid `color` is highlighted with the `build_label_hl_names(hex)` groups `ReviewLabel_<rrggbb>` (the padded name: text on the fill, bold) / `ReviewLabelCap_<rrggbb>` (the ends: the fill colour as foreground), and `label_colors` lists those colours once each so `ui.show_overview_float` can define the groups (module-local `define_label_hls`, also on `set_reviewers`) from `calculate_label_colors(hex, base_bg, background)` → `{ fg, bg }`: dark fills with the label colour at `LABEL_FILL_ALPHA` (0.6) over `base_bg` (`NormalFloat`, else `Normal`, else black/white) via `blend_colors` and takes Primer's label text colour (HSL lightness raised by `(0.6 - perceived) * 100` points below perceived lightness 0.6) mixed `LABEL_TEXT_WHITEN` (0.5) toward white; light fills with the label colour and uses black/white text by perceived lightness 0.453, as GitHub's light theme; `parse_hex_color` parses `rrggbb`/`#rrggbb`; a label without a valid colour gets a pill without highlights; `ci_start`/`loading_row` of the CI STATUS section, built by `build_overview_ci_lines(checks, start_line, opts)` — nil `checks` gives the spinner row (`opts.loading_mark`/`loading_hl`, `CHECKS_LOADING_TEXT`) or, with `opts.checks_failed`, `CHECKS_FAILED_TEXT`; line numbers absolute), `calculate_comment_browser_layout`, `format_comment_browser_list`, `format_comment_browser_thread`, `parse_markdown_line`, `build_highlighted_chunks`, `apply_markdown_highlight_to_line`, `normalize_newlines`. Purity is enforced by `scripts/check_purity.lua` (`make check-purity`).
