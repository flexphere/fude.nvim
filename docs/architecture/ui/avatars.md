# lua/fude/ui/avatars.lua

Author / reviewer / assignee / comment author avatars in the overview, drawn inline through snacks.nvim's image module (`require("snacks").image.placement.new(buf, file, { pos, inline = true, height = CELL_HEIGHT, width = CELL_WIDTH })`). Pure: `parse_login(login)` → `name, is_bot` (REST `<name>[bot]` and gh's `app/<name>` are bots; GraphQL's bare bot name cannot be told from a user's login), `build_avatar_url(login)` (`https://github.com/<name>.png?size=SIZE` for a user; `COPILOT_AVATAR_URL` — the Copilot code review App's icon, `avatars.githubusercontent.com/in/946600` — for either Copilot login via `format.is_copilot_login`; nil for other bots, whose image is looked up, and for anything but a login), `bot_api_path(login)` (`users/<name>%5Bbot%5D`), `sized_avatar_url(url)` (adds `s=SIZE`), `cache_name(login)` (the account name, so every spelling of one account shares one file and no brackets or slashes reach the file system; `copilot` for Copilot; also the in-flight key of `fetch`), `build_round_cmd(exe, src, dst, size, canvas)` (the ImageMagick command centering the `size` px circle on a transparent `canvas` px square — `SIZE` 64 on `CANVAS` 80, so the circle takes 80% of the cell; the canvas is extended before the mask, since ImageMagick 6 drops the colour the other way round). `KINDS` (`author`, `reviewers`, `assignees`, `comments` — group `overview` — and `comment_threads` — group `comment` — mapped by `KIND_GROUPS`; the last one is outside the overview: the comment viewer, the reply/edit window and the comment browser's thread pane, which place the `avatar_positions` of `format_comments_for_display` / `format_reply_comments_for_display` from the pure `format.build_comment_avatar_position(line, login)` — column 0 of each header, nil for an unknown login — plus, for an `APPROVED` review summary, the `{ line, col, image = "approved", kind }` of the pure `format.build_review_state_image_position(line, header, review_state, kind)`: right before the `[approved]` badge that ends the header (`REVIEW_STATE_IMAGES`), also added by `build_overview_left_lines` under kind `comments`; the browser clears its upper pane's placements before each entry), pure `resolve_setting(opts)` (the top-level `images` option, with `overview = true` added when the earlier `overview.avatars = true` is set), pure `should_draw(setting, kind)` (`images` is `true` — every kind — or a table whose group key (`overview` / `comment`) for the kind is `true`; without `kind`, whether any group is on; the default table has both `false`), `is_enabled(kind?)` (`should_draw` on `resolve_setting(config.opts)`, snacks loadable, `snacks.image.supports_terminal()`; the reviewer picker asks `is_enabled("reviewers")`), `find_magick()` (`magick`, else `convert`), `cache_path(login, round)` (`<cache_name>.png` / `<cache_name>.round<CANVAS>.png`) under `cache_dir()` (`stdpath("cache")/fude/avatars`, `M._dir` for tests), `lookup_bot_avatar(login, cb)` (`gh api <bot_api_path> --jq .avatar_url`, sized; mockable) and `fetch(login, cb)` (a bot's image is downloaded from the looked-up URL, and a bare name whose `github.com/<name>.png` download fails falls back to that lookup, since GraphQL review authors spell bots that way; an account found without an image is remembered for the session (module-local `missing`, `_reset_missing` for tests) so it is not looked up on every overview; cached round file — or the square one without ImageMagick — else curl into `<login>.png.part` renamed on success, then the round cut; callbacks for a login already in flight are queued so one image is fetched once; `run(cmd, cb)` is the mockable `vim.system` wrapper) and `place(buf, positions)` (one placement per `{ line, col, login, kind }` — or `{ line, col, image, kind }` for a shipped image: `asset_path(name)` resolves `ASSET_FILES` (`approved` → `assets/review-approved.png`, a 64 px green circle with a white check on an 80 px transparent canvas like the round avatars) from the plugin root, drawn at the same size without a download from the overview line builders — skipped when `kind` is off — once its file arrives, skipped for a buffer gone meanwhile; snacks cleans its placements on the buffer's wipeout). `fetch` is also the reviewer picker's `images` source (`overview.edit_reviewers`), so a login's avatar is downloaded once for the overview and the picker.
