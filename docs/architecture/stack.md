# `lua/fude/stack.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

GitHub stacked PR navigation for review mode (`:FudeReviewStackSwitch`). `select_stack()` (GitHub review only) fetches the stack via `gh.get_pr_stack`, builds entries with the pure `build_stack_entries(prs, current_number)` (open PRs plus the current one, `[i/n] #num title (base ← head)` with `i/n` the position in the whole stack, current marked `▶`), and routes the picker by `config.opts.file_list_mode` like `scope.select_scope` (thin `show_telescope` compact dropdown / `show_snacks` select layout / `show_vim_select`; a missing plugin falls back to `vim.ui.select`). The gh callback and the picker selection are both guarded by a captured `config.state` identity check. `switch_to(entry)` decides the case with the pure `resolve_switch_target(worktrees, current_root, branch)` (paths compared after `vim.fn.resolve`): `current` (branch is HEAD here) is a no-op; `switch` (checked out nowhere) stops the review, runs `gh.checkout_pr`, `checktime`s buffers, and restarts the review — on checkout failure it first `git checkout`s the pre-stop `original_head_ref`/`original_head_sha` again, since gh may switch to an existing local branch before failing its `merge --ff-only`, and leaves the review stopped when that restore fails too (HEAD is on neither PR for sure). While the checkout runs, the module-local flag behind `is_switching()` makes `init.start()` and `local/session.start()` refuse with a WARN (shared `refuse_while_switching()`), so no review reads the branch mid-switch or races the callback's `start()`; `cd` (checked out in another worktree) stops the review, `:cd`s there (`pcall`; failure restarts in place), points windows showing old-worktree buffers at the same file in the new worktree (else `enew`) so the layout survives, wipes those buffers, and restarts the review. Old-worktree buffers are those whose deepest owning worktree root (`find_owning_root` over all worktree roots; `is_path_under` rejects sibling prefixes like `/repo-other`) is the current one, so buffers of a worktree nested inside it (e.g. `.claude/worktrees/x`) are neither wiped nor block the switch. Every refusal (modified buffer under the current worktree, tracked uncommitted changes via `git status --porcelain --untracked-files=no` for `switch`, missing target directory for `cd`) happens before `init.stop()`, and a `stop()` that keeps the session active (HEAD restore failure) aborts the switch.
