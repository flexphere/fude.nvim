# `lua/fude/diff.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

Local git operations (sync). Gets repo root (`get_repo_root()` answers the local session's `worktree_root` while one is active, since the commit scope can delete the directory Neovim's cwd points at and a `:cd` elsewhere must not stop every file operation), converts paths to repo-relative (`make_relative(filepath, root)` is boundary-aware: `/repo-other/x.lua` is not under `/repo`), retrieves base branch file content via `git show`, generates file diffs, and computes merge-base for gitsigns (avoids merge commit noise). Falls back to `origin/<ref>` when local ref isn't available. Also provides local-session helpers: `get_current_branch`, `get_head_sha`, `is_ancestor(ancestor, descendant, cwd?)` (`git merge-base --is-ancestor`), `get_empty_tree(cwd?)` (empty-tree hash, diff base for zero-commit repos and root commits; `cwd` matters because the hash depends on the repo's object format, SHA-1 vs SHA-256), `get_head_sha(cwd?)`, `get_upstream_ref(cwd, branch?)` (`@{upstream}`, diff base for the unpushed scope; `branch` resolves `<branch>@{upstream}` instead, needed while the local commit scope holds HEAD detached), `get_push_target(cwd?)` (`{ branch, remote }` for `pr.lua`'s push, nil on a detached HEAD; read only after gh reported the branch unpushed, so its git calls — `git config` for `branch.<b>.pushRemote`/`remote.pushDefault`, `git for-each-ref` for the upstream parsed by the pure `parse_upstream`, `git remote` — never run on an ordinary PR creation; `remote` comes from the pure `resolve_push_remote(branch, { push_remote, push_default, upstream_remote, upstream_ref, remotes })`: explicit pushRemote, then pushDefault, then the remote of a *same-named* upstream, then `origin`, then the only remote, never `.` — a differently named upstream's remote is skipped because in a fork clone a branch created from `upstream/main` tracks the canonical repository), `push_branch(remote, branch, cb, cwd?)` (the one *asynchronous* helper here, since it goes over the network: `git push --set-upstream <remote> HEAD:refs/heads/<branch>` — always the branch's own name, so a branch tracking `origin/main` never lands on main — with `GIT_TERMINAL_PROMPT=0` and `detach = true` (no controlling terminal, so neither git nor ssh can prompt over the Neovim screen and hang); after `M.PUSH_TIMEOUT_MS` (120 s) a timer sends SIGTERM to the whole process group (`vim.uv.kill(-pid)`; `detach` made git its leader) and reports "timed out" — vim.system's own `timeout` signals only git, and a hook or transport helper still holding git's stderr would keep the exit callback from running; never forces; the error is stderr without git's `hint:` lines via the pure `format_push_error`), `get_default_branch(cwd?)`, `get_remote_branches(cwd?)` (`origin` remote-tracking branch names via `git for-each-ref`, most recently committed first, `HEAD` excluded by the pure `parse_remote_branches`; used by `pr.lua`'s base branch picker), `get_git_common_dir()` (absolute common git dir shared by every worktree, symlinks resolved; used for `pr.lua`'s creation draft key), `get_gh_stack_parent(branch)` (reads gh-stack's local `.git/gh-stack` JSON from the common git dir — not `gh stack view`, which hits the network — parsed by the pure, type-defensive `parse_gh_stack_parent`: previous branch in the stack, or its trunk for the bottom branch), `get_ancestor_branches(default_branch, cwd?)` (`origin` branch tips in `<default>..HEAD`, nearest first, from a single `git log --format=%H%x00%P%x00%D --decorate-refs=refs/remotes/origin/` walk parsed by the pure `parse_ancestor_log`, which orders tips by the number of in-range commits each cannot reach (`rev-list --count <tip>..HEAD` limited to the range) computed from the parent links, since log order — even `--topo-order` — does not follow the distance across merges; one process regardless of the branch count; empty when the default ref is unresolvable, since otherwise every branch in HEAD's history would match), `get_worktree_roots(cwd)` (every non-bare worktree directory, detached ones included, parsed by the pure `parse_worktree_roots`; the repo root is passed explicitly so the answer survives a mid-session `:cd` — used by `local/session` for buffer ownership), `get_worktrees()` (`git worktree list --porcelain` parsed by the pure `parse_worktree_list`, which keeps `{ path, branch }` and skips bare/detached entries — prunable ones are kept because git still reserves their branch until `git worktree prune`, so `stack.switch_to` refuses them via its missing-directory check instead of failing in `gh pr checkout`; nil + err when git fails, so a failure is not mistaken for "no worktree has the branch"), `get_commit_message(sha, cwd)` (`git log -1 --no-show-signature --format=%B` — `log.showSignature` would otherwise print GPG output ahead of the message — trailing whitespace removed, nil on failure; used by the side panel's Commit Message section in local review), `get_git_user`, `get_name_status`, `get_numstat`, `get_untracked`, `get_review_patch` (the last four take a `cwd` repo root so paths resolve from a subdirectory), `get_review_patches(base_sha, cwd)` (every tracked file's patch in one `git diff -M`, split per file by the pure `parse_patches_by_path` — keyed by the new path, the old one for a deletion, `""` for a file listed without hunks (pure rename, mode change, binary) so it is not looked up again; `--src-prefix=a/ --dst-prefix=b/` keeps a user's `diff.noprefix`/`diff.mnemonicPrefix` from breaking the parse, `-c diff.suppressBlankEmpty=false` keeps an empty context line's leading space (the parser would drop the line and shift every later line number), and the TAB git appends to a name with a space is dropped; untracked files are not included; used by `all_diffs.lua` so the view does not start one git process per file). Commit-scope helpers: `parse_commit_log` (pure; `%H%x1f%h%x1f%s` lines → `{ sha, short_sha, subject }`, the `\31` separator keeping subjects with tabs/pipes intact), `get_commit_log(base_ref, tip, cwd, limit?)` (takes the tip explicitly so the list survives a detached checkout; retries `origin/<base_ref>` when the base exists only on the remote, like `get_merge_base`; a nil base lists every commit of `tip`, `limit` keeps the newest N of the range, still oldest first), `is_worktree_dirty(cwd)` (`git status --porcelain -uno`; true on git failure so no checkout runs over unknown state), `get_untracked_conflicts(ref, cwd)` (every path the target tracks that is not tracked here yet already exists on disk — ignored files included, since git overwrites those silently — plus a file sitting where the target needs a directory, via the pure `find_checkout_collisions(target_paths, tracked_here, kind_of)`; defined from the target's side so the worktree's possibly huge ignored set is never listed; nil + err on git failure; other untracked files are carried across and never block), `checkout(ref, cwd, opts?)` (runs `git checkout --no-overwrite-ignore` so git refuses to overwrite ignored untracked files instead of doing so silently — the backstop behind `get_untracked_conflicts` — and verifies where HEAD landed in both directions: a non-zero exit with HEAD already on `ref` — a failed post-checkout hook — counts as done and returns the hook output as a warning, while a zero exit that left HEAD elsewhere — `git checkout <name>` detaching onto a same-named tag once the branch is gone — is a failure; `opts.branch = true`, used by every branch restore in `local/session`, demands symbolic HEAD on `ref` via `head_branch(cwd)`; `opts.detach = true`, used when entering a commit, runs `checkout --detach` and demands a detached HEAD on the commit, since a target equal to the branch tip would otherwise be indistinguishable from "still on the branch"; otherwise `head_is(ref, cwd)` accepts the resolved commit), `is_reachable_from_branch(sha, cwd)` (`git for-each-ref --contains` over `refs/heads/`; whether leaving a detached HEAD on `sha` would orphan it), and `get_parent(sha, cwd)` → `parent_sha|nil, "parent"|"root"|"missing"|"error"` (reads the raw object header via the pure `parse_commit_parents` and then checks the parent object exists, because `rev-parse <sha>^` fails for both a true root and a shallow clone's boundary commit, and only the former may diff against the empty tree).
