# lua/fude/local/session.lua

Local review session lifecycle, parallel in shape to `init.lua` start/stop/reload. `start(base)` resolves the base ref (arg → `current.json` → default branch), computes the diff base from the scope, synthesizes `changed_files` from `git diff --name-status/--numstat` + untracked files, sorted by `util.path_less` so untracked files sit among tracked ones in the GitHub PR file order (pure helpers: `status_word`, `resolve_rename_path`, `parse_name_status` (keeps the old path of an `R`/`C` line as `previous_path`; `diff.get_name_status` passes only `-M`, so local review detects renames and a copy shows up as `added`), `parse_numstat`, `build_changed_files`), creates or resumes the session for the current branch (`.fude/current.json` is keyed by branch, so different branches in one worktree get separate sessions), sets state (`review_mode = "local"`, `local_session`), reuses `init.setup_review_autocmds`, registers local-only autocmds (BufWritePost re-anchor, BufEnter/BufReadPost tracker sync — mapped with `relative_path`, so a buffer opened after a `:cd` out of the worktree is still tracked), and starts the auto-reload timer. `stop()` tears down (the chat via `ui/chat_panel.teardown()`, like `init.stop()`) and clears `current.json` (the JSONL file is kept); when the pointer cannot be removed it still tears down but reports a WARN naming the entry to delete by hand, since the next start on that branch would otherwise resume the stopped session. `toggle(base)` stops an active local session or starts one (refuses while a GitHub review is active). `reload(silent)` re-reads git state and the JSONL synchronously. **Scope**: `local_session.scope` is `"base"` (merge-base with the base branch — whole branch diff), `"unpushed"` (the `@{upstream}` tracking ref — changes not yet pushed), `"uncommitted"` (HEAD — staged + unstaged only), or `"commit"` (one commit of the branch, `<sha>^` vs `<sha>`, identified by `scope_commit_sha`/`scope_commit_index`). The first three compare the working tree against a ref, so comments stay anchored. The commit scope instead *checks the commit out* (module-local `enter_commit_scope`: persists the pending destination to `current.json` via `persist_current(session, overrides)` *before* the checkout — with `pending_from_sha`, the commit HEAD still sits on during a commit-to-commit switch, so a crash before the checkout lands is matched too — so a crash in between still leaves a pointer `start()` can match against HEAD, rewrites the previous pointer on failure, and records `original_branch` on the session only after the checkout succeeded so a failed first attempt leaves nothing for `restore_head` to undo), exactly like the GitHub flow's commit scope, so changed files, preview, gitsigns and `files.open_file` work through the existing paths; two consequences follow. (1) HEAD moves: every checkout — not only the first — is refused by `checkout_blocker` when a comment input holds unsent text (`ui.has_unsent_comment_input`: a `b:fude_comment` float shown in a window, the reply/edit window's lower pane, or the comment browser's lower pane — the scope's teardown would wipe it), when the worktree has staged/unstaged changes (`diff.is_worktree_dirty`), when files exist, ignored or not, where the checkout target would write (`diff.get_untracked_conflicts`; git refuses or would silently overwrite, so this one is not forced over on quit either), or when a loaded buffer owned by the worktree is modified (`has_unsaved_buffers_under` over `file_buffers_under`, which resolves ownership as the deepest worktree root containing the file via `stack.find_owning_root` and `diff.get_worktree_roots(session.worktree_root)` — detached worktrees included, listed from the session root rather than Neovim's cwd — so a worktree nested inside this one, `.claude/worktrees/x`, neither blocks nor gets reloaded), since `git status` cannot see unsaved buffers and `reload_open_buffers` must skip them, or — on a commit-to-commit switch and on every restore — when HEAD is no longer `scope_commit_sha` (the user committed on the detached HEAD; checking out away from it would orphan that commit, so the blocker asks for `git branch <name> <sha>` first and lifts once `diff.is_reachable_from_branch` finds a local branch holding the new HEAD — `git branch` does not move HEAD, so matching the SHA alone would block forever; the dirty-tree message says "stash or discard" rather than "commit", and not even `VimLeavePre`'s `force` overrides an orphaned HEAD — or a HEAD git cannot report at all, which might be one — since a detached HEAD on the user's own commit is the state they chose); entering is also refused when the pending pointer write fails, since a crash could then never find the way back; the branch is recorded in `session.original_branch` on entry (with `scope_before_commit`, the scope to write back later) and put back by `restore_head` on scope switch, `stop()` and `VimLeavePre`; `restore_head` applies the same `checkout_blocker` and refuses on a scope switch or `stop()` — unsaved buffers cannot be carried back by git and the reload skips them, so they would overwrite the branch on the next save — while `VimLeavePre` passes `force = true` (a dirty tree is the lesser evil than a detached HEAD the user did not ask for, so it warns and continues) and `reload_buffers = false` (re-reading buffers only slows the exit); after a successful restore it rewrites the pointer with `scope_before_commit` so a later deliberate detach onto the same SHA is not mistaken for a crash (`persist_non_commit_or_clear`: when that write fails the pointer is removed instead via `store.clear_current`, whose `ok, err` result is checked — if even the removal fails the ERROR names the stale entry and how to delete it by hand — losing a resume beats leaving a stale commit entry — and the same helper rolls back the pending pointer after a failed checkout); `stop()` runs the restore *first* and aborts — session kept, like `init.stop()` on a failed HEAD restore — when it fails, so `original_branch` and `current.json` survive for a retry; a persisted `commit` scope is never resumed by `start()`. `persist_current` also stores `scope_commit_sha`/`original_branch`, so when `start()` finds no branch and HEAD equals a persisted commit-scope entry's commit (`store.read_stranded_commit_session`: a crash while a commit was checked out), it returns to that `original_branch` first — refusing with an ERROR and a manual `git checkout` hint when `checkout_blocker` reports a dirty tree — rewrites the pointer to a non-commit state right after the checkout (before buffers reload; `persist_non_commit_or_clear`), takes the branch name from the pointer when `get_current_branch` cannot re-detect it (the checkout may have removed Neovim's cwd), and then resumes the branch's session normally; any other detached HEAD is treated as the user's own. Buffer reloads after a checkout (`reload_open_buffers`) touch only unmodified file buffers under the worktree (`file_buffers_under`, shared with the unsaved check). `scope_specs` asks `diff.get_upstream_ref(root, session.original_branch)` so the unpushed entry stays available as a way back while HEAD is detached. (2) The right side is a past snapshot, not the working tree comments anchor to, so the whole comment layer is disabled while the scope is active: `in_commit_scope()` gates `comments.lua` (create/suggest/reply/edit/delete/resolve/view/next/prev/list), the `local_sync` mutations (so the comment browser's direct backend calls are refused too), `local/tracker`, `ui/extmarks`, and the re-anchor/outdated passes in `local_sync.load_comments`. `resolve_scope_base(scope, base_ref, cwd, commit_sha)` returns the `git diff` base and the `git show` content ref (nil when the scope is unavailable), running every git lookup — merge-base, upstream, parent, empty tree, HEAD — in `cwd`, the session's worktree root, so a `:cd` elsewhere does not break a switch; every scope returns the same ref for both, on `base` that is the merge-base rather than the base branch tip, so the changed-files list, the per-file patches, the gitsigns base and the preview's base pane all stay on the same commit even after the base branch moves on (matching the three-dot semantics the GitHub flow gets from `merge_base_sha`), and on `commit` it is the parent SHA from `diff.get_parent`, the empty tree for a true root commit, and nil (switch refused) when the parent is recorded but unreachable, as at a shallow clone's boundary. The commit list is cached on `session.commits` by `refresh_commits` (called from `start`/`reload`, skipped while a commit is checked out) because `scope_specs` runs on every side panel render; its range comes from the pure `resolve_commit_range_base(base_ref, branch, upstream)` — the base branch on a feature branch, else the upstream (unpushed commits on the base branch itself), else every commit (remote-less fresh repo, the one path on which a root commit appears), capped at the newest `COMMIT_LIST_LIMIT` (100) in that unbounded case so a long-lived remote-less repo does not pour its history into the side panel — with the tip being the branch name so the list survives a detached HEAD. `scope_specs(session)` builds the adaptive list of available scopes with labels (base only on a non-base branch; unpushed only with an upstream; uncommitted always; one `commit` entry per cached commit via the pure `build_commit_specs`, flagged current by SHA). `set_scope(scope, opts)` (`opts.commit_sha` for the commit scope) orders HEAD move and base resolution by direction: into a commit it resolves first (`<sha>^`/empty tree need no checkout) and moves HEAD only on success, so a failure leaves everything untouched; out of a commit it restores HEAD *before* resolving — `unpushed` reads `@{upstream}`, which does not resolve while detached — and on an unresolvable base re-enters the previous commit, restoring the `scope_before_commit` the restore had cleared so the pointer keeps the scope the user came from (or, when that second checkout fails, lands on `uncommitted` rather than claiming a commit scope it no longer shows); the module-local `apply_scope` then records the scope, reloads changed files/comments, re-applies the gitsigns base and preview, and updates the statusline (`Local: <i>/<n>` for commits). It returns true only when the scope actually changed (false on no session / unknown scope / same scope / unresolvable base — the sidepanel uses this to decide whether to auto-open the first file); `select_scope()` is the `vim.ui.select` picker (its callback checks that `state.local_session` is still the session the picker was built for, since a picker left open across stop → start would otherwise check out the old branch's commit from the new session). **Base branch**: `set_base(base_ref)` (`:FudeReviewLocalBase <ref>`) changes `session.base_ref`/`state.base_ref` without restarting — comments anchor to the working tree, so they are kept — by first checking that the ref itself has a merge-base with HEAD (`diff.get_merge_base` in the worktree root — `uncommitted`/`unpushed` never read the base, so resolving only the current scope would let a typo through) and then resolving the current scope against it (`resolve_scope_base`; either failure → ERROR, nothing changed), then `refresh_commits` and `apply_scope`, which also rewrites the pointer so a resume keeps the new base (`start()` prefers the pointer's `base_ref`); the pure `resolve_scope_after_base_change(scope, base_ref, branch)` drops `base` to `uncommitted` when the new base is the reviewed branch itself; refused in the commit scope (HEAD detached, and the commit list depends on the base) and a no-op for the current base. `select_base()` (`:FudeReviewLocalBase` without an argument, the side panel's `change_base` key) reuses `pr.build_base_branch_entries` over `diff.get_remote_branches(root)`/`get_default_branch(root)`, with `diff.get_ancestor_branches(default_branch, root)` as `ancestors` so the branches HEAD was built on follow the default branch as `(ancestor)` like in `:FudeCreatePR` — the session's worktree root, as is the command's completion, so a `:cd` elsewhere does not list another repo's branches — and `pr.select_base_branch`, marking the current base with the pure `mark_current_base(entries, base_ref)`; its callback has the same stale-session guard as `select_scope`.
