# Diff views: preview and all-diffs

Module details for `lua/fude/preview.lua`, `all_diffs.lua`. Moved verbatim from the former "Module Responsibilities" section of `CLAUDE.md`; update this file when these modules change.

Related details in other files: `diff.lua` is in `git.md`; `local/session.lua` (`relative_path`, `content_ref`) is in `local-review.md`; `files.lua` and `scope.lua` are in `navigation.md`.

- **`preview.lua`** — Manages the side-by-side diff preview window. Creates a scratch buffer with base branch content, opens it in a vsplit, and enables `diffthis` on both windows. Uses `noautocmd` to prevent BufEnter cascades. The `opening` flag guards against re-entrant calls. `open_preview` maps the source buffer with `local/session.relative_path` and passes the local session's worktree root to `diff.get_base_content(ref, path, cwd?)`, so a `:cd` out of the worktree does not leave the preview closed after a scope switch (outside local mode both fall back to the cwd-based lookups). The ref it reads comes from the pure `find_base_ref(state, local_session)` → `ref, label`: the local session's `content_ref`, else `<sha>^` in the commit scope, else `state.merge_base_sha` in the full PR scope — the commit the PR branched off, the base gitsigns and GitHub's PR diff use, so commits that land on the base branch after the PR branched off never show up reversed in the base pane — falling back to the base branch tip only when no merge-base was computed; `label` (`main (merge-base abc1234)` for the merge-base) names it in the new-file placeholder. The base content is read from the path returned by the pure `find_base_path(rel_path, changed_files)` — the entry's `previous_path` for a renamed file (or a copied one in GitHub mode, when the API reports it), else `rel_path` — retrying `rel_path` when the old path is missing at the base ref (only the base branch tip fallback can have dropped it); the preview buffer is named `[base] <path read>`. It rejects a source window holding a nofile buffer (e.g. the side panel) — `to_repo_relative` cannot reject such buffer names when cwd is inside the repo, so without the guard `:FudeReviewDiff` from the panel would vsplit the panel itself and wedge `state.source_win` to it. `on_buf_enter` skips the rebuild when the preview already targets the same source window and buffer (`is_preview_current`, backed by `state.preview_source_buf`): rebuilding runs `diffoff!`/`diffthis`, which resets `foldenable`/`foldlevel` and the preview window's options, so re-entering the same file (closing a comment float, moving between the two panes) must not discard the user's fold/wrap changes. Explicit rebuild paths (`toggle_diff`, scope changes) call `close_preview` first and are unaffected. Rebuilds save the source view and fold options, run diffupdate before restoring them, and therefore do not undo file-opening positions. The default `diffopt` includes `followwrap` because `diffthis` otherwise forces `nowrap`, and `linematch:0` because the second-stage line alignment splits a heavily rewritten block into many small hunks with fillers scattered on both sides (a later duplicate key wins, so this also overrides Neovim 0.11+'s built-in `linematch:40`). It deliberately sets no `algorithm:`, leaving Neovim's default myers, which splits hunks the same way git and the GitHub web view do.
- **`all_diffs.lua`** — `:FudeReviewAllDiffs`: every changed file of the current scope in one new tabpage, base (left) / head (right), like GitHub's split "Files changed" view. The rows of both sides are aligned here from the unified patches (GitHub: the entries' `patch`; local review: one `diff.get_review_patches` call, with `files.resolve_patch` only for the files it does not cover, i.e. untracked ones), not by diff mode, so both windows carry `scrollbind`/`cursorbind` and any scroll key moves both. Pure: `calculate_diffstat(additions, deletions)` (GitHub's five squares: one per line up to 5 lines, else in proportion), `build_file_header(file)` (`  M   path    +a -d ■■■■■  ` plus 0-based ranges of the badges on the bar — the status letter via `STATUS_HL`, the counts and the diffstat squares, touching ranges of one group merged; `format_file_header` returns only its text; the header row keeps the ranges as `header_ranges`), `find_sticky_rows(rows, index)` (the file header row and the hunk row above the row at a window's top; a header that is the top row itself is on screen already and is not returned — nothing for a file header, no hunk for a hunk header — and nothing for the separator, which sits right above the next file's header). Not pure, since it measures display width with `vim.fn`: `compose_winbar(side_label, file_row, hunk_row, width)` (the window-local `winbar` expression `M.winbar()` reads `line("w0")`, so the header of the file being read stays on screen; `%<` after the side label lets a long path lose its start, and the hunk header is cut with `…` to the width left), `parse_patch_rows(patch)` (rows `{ kind = hunk|context|change, left?, right?, old_lnum?, new_lnum?, lnum }`; a removed block is paired row by row with the added block that follows, the shorter side nil — a filler drawn as a `FILLER_CHAR` overlay; a removal after additions starts a new pair; `\ No newline` skipped; `lnum` is the head line `<CR>` opens — for a deletion the new line after it), `build_rows(files)` (per file a header row from `format_file_header` — `M path  +a -d`, `old → new` for a rename — then its rows or a note — `NO_CHANGES_TEXT` for a renamed/modified file without hunks or counted lines (a pure rename, a mode change), else `NO_DIFF_TEXT` (GitHub left the patch out: too large or binary) —, files separated by a blank row; also returns each file's row range), `build_buffer_lines`, `row_highlights`, `tokenize`/`find_inline_ranges(old, new)` (changed tokens of a paired line via `vim.text.diff` over one token per line, nothing when the lines share no token), `build_syntax_source(rows, range, side)` (one side's code lines of a file joined for a treesitter string parser, with the buffer row of each), `find_jump_target(rows, files, index)` (refuses a removed file), `format_line_number`/`calculate_number_width` (each side's own numbers through a window-local `statuscolumn`). Syntax highlighting parses only the diff lines of a file (`vim.treesitter.get_string_parser` + the `highlights` query, `@capture.lang` extmarks in `fude_all_diffs_syntax`) and runs lazily for the files on screen (`WinScrolled`/`WinResized`). Priorities: line background 50 < syntax 100 < changed words 150. The file header is a solid bar of the Title colour (falling back to Directory / Function / Normal, since e.g. habamax gives Title no colour) with `FudeAllDiffsFile` text in the Normal background colour, and its badges (`FudeAllDiffsHeader*`, Normal / Diagnostic / NonText fg) on the Normal background — also in the winbar, where a group without a background would show a gap. A `line_hl_group` wins over every other highlight on its line, background included, so the bar is not a line group: it is a `FudeAllDiffsFile` extmark from the header to the start of the next line with `hl_eol`, which fills the rest of the screen line while the badges set their own background over it. The hunk header keeps a bg-only line group (`FudeAllDiffsHunkLine`: DiagnosticInfo mixed into the Normal background at `HUNK_BG_ALPHA` with `ui/format.blend_colors`) with its text coloured by a separate `FudeAllDiffsHunk` extmark. Groups are all `default` so a user definition wins, and redefined on `ColorScheme`. The module-local `view` keeps the `config.state` it was opened in: `<CR>` (`jump`, opens the file through `files.open_file` in a source window of the tab the view was opened from) and `R` (`refresh`) refuse with a WARN once that session ended; `open()` on an open view of the same session focuses and rebuilds it, and replaces one of another session. Closing either window closes the view (`WinClosed`). The view counts as open only while its tab and both buffers exist (`bufhidden=wipe`: opening another buffer in a view window wipes the view buffer without a `WinClosed`), so `open()` then replaces the broken view. `close()` closes the tab only while every window of it shows a view buffer; otherwise it closes the windows still showing one and gives the remaining windows (another buffer, or the last tab) the global values of the options the view set — the same reset `jump` applies to the split it opens when the review tab has no source window, since the split copies e.g. the side panel's options, and `statuscolumn()` shows `%l` for any other buffer opened in a view window; and `init.stop()`/`local/session.stop()` call `close()`. The view does not follow scope switches or reloads; `R` rebuilds it.
