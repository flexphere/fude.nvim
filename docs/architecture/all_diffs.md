# `lua/fude/all_diffs.lua`

Detailed design notes for this module. `CLAUDE.md` keeps only a short summary; read this file before changing the module.

`:FudeReviewAllDiffs`: every changed file of the current scope in one new tabpage, base (left) / head (right), like GitHub's split "Files changed" view. The rows of both sides are aligned here from the unified patches (GitHub: the entries' `patch`; local review: one `diff.get_review_patches` call, with `files.resolve_patch` only for the files it does not cover, i.e. untracked ones), not by diff mode, so both windows carry `scrollbind`/`cursorbind` and any scroll key moves both. Pure: `calculate_diffstat(additions, deletions)` (GitHub's five squares: one per line up to 5 lines, else in proportion), `build_file_header(file)` (`  M   path    +a -d ■■■■■  ` plus 0-based ranges of the badges on the bar — the status letter via `STATUS_HL`, the counts and the diffstat squares, touching ranges of one group merged; `format_file_header` returns only its text; the header row keeps the ranges as `header_ranges`), `find_sticky_rows(rows, index)` (the file header row and the hunk row above the row at a window's top; a header that is the top row itself is on screen already and is not returned — nothing for a file header, no hunk for a hunk header — and nothing for the separator, which sits right above the next file's header). Not pure, since it measures display width with `vim.fn`: `compose_winbar(side_label, file_row, hunk_row, width)` (the window-local `winbar` expression `M.winbar()` reads `line("w0")`, so the header of the file being read stays on screen; `%<` after the side label lets a long path lose its start, and the hunk header is cut with `…` to the width left), `parse_patch_rows(patch)` (rows `{ kind = hunk|context|change, left?, right?, old_lnum?, new_lnum?, lnum }`; a removed block is paired row by row with the added block that follows, the shorter side nil — a filler drawn as a `FILLER_CHAR` overlay; a removal after additions starts a new pair; `\ No newline` skipped; `lnum` is the head line `<CR>` opens — for a deletion the new line after it), `build_rows(files)` (per file a header row from `format_file_header` — `M path  +a -d`, `old → new` for a rename — then its rows or a note — `NO_CHANGES_TEXT` for a renamed/modified file without hunks or counted lines (a pure rename, a mode change), else `NO_DIFF_TEXT` (GitHub left the patch out: too large or binary) —, files separated by a blank row; also returns each file's row range), `build_buffer_lines`, `row_highlights`, `tokenize`/`find_inline_ranges(old, new)` (changed tokens of a paired line via `vim.text.diff` over one token per line, nothing when the lines share no token), `build_syntax_source(rows, range, side)` (one side's code lines of a file joined for a treesitter string parser, with the buffer row of each), `find_jump_target(rows, files, index)` (refuses a removed file), `format_line_number`/`calculate_number_width` (each side's own numbers through a window-local `statuscolumn`). Syntax highlighting parses only the diff lines of a file (`vim.treesitter.get_string_parser` + the `highlights` query, `@capture.lang` extmarks in `fude_all_diffs_syntax`) and runs lazily for the files on screen (`WinScrolled`/`WinResized`). Priorities: line background 50 < syntax 100 < changed words 150. The file header is a solid bar of the Title colour (falling back to Directory / Function / Normal, since e.g. habamax gives Title no colour) with `FudeAllDiffsFile` text in the Normal background colour, and its badges (`FudeAllDiffsHeader*`, Normal / Diagnostic / NonText fg) on the Normal background — also in the winbar, where a group without a background would show a gap. A `line_hl_group` wins over every other highlight on its line, background included, so the bar is not a line group: it is a `FudeAllDiffsFile` extmark from the header to the start of the next line with `hl_eol`, which fills the rest of the screen line while the badges set their own background over it. The hunk header keeps a bg-only line group (`FudeAllDiffsHunkLine`: DiagnosticInfo mixed into the Normal background at `HUNK_BG_ALPHA` with `ui/format.blend_colors`) with its text coloured by a separate `FudeAllDiffsHunk` extmark. Groups are all `default` so a user definition wins, and redefined on `ColorScheme`. The module-local `view` keeps the `config.state` it was opened in: `<CR>` (`jump`, opens the file through `files.open_file` in a source window of the tab the view was opened from) and `R` (`refresh`) refuse with a WARN once that session ended; `open()` on an open view of the same session focuses and rebuilds it, and replaces one of another session. Closing either window closes the view (`WinClosed`). The view counts as open only while its tab and both buffers exist (`bufhidden=wipe`: opening another buffer in a view window wipes the view buffer without a `WinClosed`), so `open()` then replaces the broken view. `close()` closes the tab only while every window of it shows a view buffer; otherwise it closes the windows still showing one and gives the remaining windows (another buffer, or the last tab) the global values of the options the view set — the same reset `jump` applies to the split it opens when the review tab has no source window, since the split copies e.g. the side panel's options, and `statuscolumn()` shows `%l` for any other buffer opened in a view window; and `init.stop()`/`local/session.stop()` call `close()`. The view does not follow scope switches or reloads; `R` rebuilds it.
