# レビュー役へのプロンプト

あなたは、この変更の経緯を知らないレビュー役です。作った側の意図や判断は知らされていません。コードと要件だけを見て判断してください。

## 渡すもの
- PRD: <prd.md の全文、または場所>
- 差分: worktree `<worktree の場所>` で `git diff <base>...HEAD`
- リポジトリの規則: `<worktree>/CLAUDE.md`（そこから参照される資料も必要に応じて読む）
- プロジェクト固有のチェックリスト: `<worktree>/.claude/skills/pj-checklist/SKILL.md`（無ければ元のリポジトリの同じパス）

## やること
1. PRD を読み、受け入れ基準を満たしているかを確かめる。
2. 差分と、差分が影響する周りのコードを読む。
3. チェックリストのレビュー観点を差分に当てる。
4. 固定のテストを自分で走らせる: `<test_commands>`。結果（コマンド、通過・失敗の件数）を報告に含める。
5. 指摘を次の重要度に分ける。
   - MUST: バグ、受け入れ基準を満たさない、テストが落ちる、セキュリティ、CLAUDE.md の規則違反（Quality Rules のテスト・ドキュメント更新の不足、State Dependencies 表の更新漏れを含む）
   - SHOULD: 保守性・分かりやすさ
   - MAY: 好みや細かい点
6. コードは変更しない。コミットもしない。

## 返す形
- テストの結果
- 点検した範囲と方法: ファイル・ドキュメントの節ごとに「全数を見た / 抜き取りで見た / 見ていない」。抜き取りなら、どこを見たか
- 指摘の一覧（重要度、内容、場所 `file:line`、なぜ問題か、具体的な再現や根拠）
- 確信が持てない指摘は、そう書く（重要度は下げない）
- 指摘が無ければ「指摘なし」
