### コード品質: 近似パーサに記法を足すときは暗黙の制約と開閉の非対称を個別に確認する (PR #173, 2026-09-04)
- **問題**: (1) angle-bracket入力形式（`](<file://...>)`）を後から追加した際、bare形式ではパターン構文上通らない`)`がangle形式では通るようになり、出力正規化と組み合わさって「ghが書き換えられない参照」を生んだ。(2) フェンスの開き判定（info string可）をそのまま閉じ判定にも使ったため、フェンス内の`` ```lua ``のような行で誤って閉じた
- **対策**: 同じデータに対する記法を追加するとき、既存形式が構文上（暗黙に）排除していた文字・ケースを列挙し、新形式でも同じ制約が成立するかを確認する（「パターンが通さないから安全」は形式追加で崩れる）。開始と終了で許される構文が異なる構造（fence、heredoc等）は閉じ判定を仕様に沿って別に書く
- **該当箇所**: lua/fude/pr.lua

### ドキュメント: 非nilデフォルトのオプションを「nilで無効化」と案内していた (PR #176, 2026-09-09)
- **問題**: `diffopt`のコメントとhelpで「nil to keep user's default」と案内していたが、`setup()`は`vim.tbl_deep_extend("force", defaults, user_opts)`でマージするため、`setup({ diffopt = nil })`はキー自体が落ちてデフォルトが適用される。デフォルトが非nilのオプションではnilによる無効化は不可能で、案内どおりに設定したユーザーは無効化できない
- **対策**: 「無効化の方法」を書くときは、デフォルト値がnilか非nilかを確認する。非nilデフォルト（table/文字列/数値）のオプションでは`{}`/`false`など実際にマージ後に残る値で案内し、実装側の分岐（`if opts.x then` / `ipairs(opts.x)`）がその値で意図どおりスキップされることを確認する。同じ既定値ブロックがREADME/doc/config.luaに複製されているので、文言変更時は3箇所をgrepする
- **該当箇所**: lua/fude/config.lua, doc/fude.txt, README.md

### コード品質: プラグイン内部のフォーカス移動をユーザー操作と誤認する (PR #180, 2026-09-16)
- **問題**: 自動オープンに「カーソルがパネルを離れていたら実行しない」というstalenessガードを入れたが、同じ処理内で呼ぶ`refresh_preview`（`open_preview`がsource windowへフォーカスを移す）が先に走るため、ユーザーが何もしていなくてもガードに引っかかり機能が常に沈黙した。さらに復元処理側も、`close_preview`で破棄済みのwindow handleと比較していたため、preview内にいたユーザーを別windowへ落とした
- **対策**: 「ユーザーが離れたか」を判定するガードを入れるときは、同じフローでプラグイン自身がフォーカスを移していないかを確認する。内部でフォーカスを移す関数は呼び出し元のフォーカスを復元して閉じる（破棄されるwindowが呼び出し元の場合は再生成後の対応windowへ移す）
- **該当箇所**: lua/fude/scope.lua, lua/fude/preview.lua, lua/fude/ui/sidepanel.lua

### コード品質: 後から追加したデフォルトが既存ユーザーの明示設定を上書きする (PR #181, 2026-09-16)
- **問題**: sidepanelに`next_entry = "j"` / `prev_entry = "k"`のデフォルトを追加したが、キーマップ登録が後勝ちだったため、既に`select = "j"`等を設定していたユーザーの明示設定が新デフォルトに黙って奪われる状態だった。さらに先勝ちに変えた後は、登録順が優先順位の仕様になったにもかかわらず、実際の登録順がドキュメントの列挙順と一致していなかった
- **対策**: 既存の設定キー集合に新しいデフォルト値を追加するときは、既存設定との衝突時にどちらが勝つかを決めて明示する（原則は既存設定優先）。優先順位がコードの実行順で決まる設計にしたら、その順序をドキュメントの列挙順と一致させ、衝突ケースのテストで固定する
- **該当箇所**: lua/fude/ui/sidepanel.lua, doc/fude.txt

### コード品質: 自由形式の文字列から識別子を「走査」して照合する (PR #206, 2026-10-03)
- **問題**: keymapのrhsからユーザーコマンド名を探す際、(1) rhs全体を小文字化して比較したため実行時にE492になる`<cmd>fudereviewdiff<cr>`まで一致し、(2) rhs中のどこに現れても直前が`:`/`>`/`|`なら一致としたため`echo ':FudeReviewDiff'`や`lua print(">FudeReviewDiff")`のような文字列中の出現まで一致した。「直前の記号を見る」を広げるほど引用文字列・コメントの除外（＝Exパーサ）が必要になり収束しなかった
- **対策**: 大小文字を区別して解釈される識別子（コマンド名・パス等）は完全一致で探し、case-insensitiveは記法（`<Cmd>`等）に限定する。文字列中の出現を排除したいときは「どこかに現れる」走査ではなく、構文上の決まった位置（rhs先頭のラッパー直後など）にアンカーして照合し、対象外になる形（`|`連結後など）はdocとテストで明示する。テストには小文字化した識別子・引用文字列中の出現が一致しないケースを含める
- **該当箇所**: lua/fude/palette.lua

### エッジケース: prunableなworktreeもgitはブランチを予約している (PR #203, 2026-10-01)
- **問題**: `git worktree list --porcelain`の`prunable`エントリ（ディレクトリが消えたworktree）をパース時に捨てていたため、そのブランチは「どこにもcheckoutされていない」と判定され`gh pr checkout`に進んだが、gitはmetadataが残る限りそのブランチを別worktreeでcheckout済みとして予約するためcheckoutは失敗した。「ディレクトリ不在ならstop前に拒否」という設計も、エントリを捨てた時点で到達不能になっていた
- **対策**: 外部ツールの一覧出力を「使えないものを除外」する形でパースするときは、除外した要素が後続の操作で別の失敗（予約・ロック等）を引き起こさないかを確認する。失敗するなら除外せず保持し、事前検査で明示的に拒否して復旧手順（`git worktree prune`）を案内する
- **該当箇所**: lua/fude/diff.lua, lua/fude/stack.lua

### コード品質: 数値IDの文字列比較は桁数の境界で順序が逆転する (PR #210, 2026-10-03)
- **問題**: 同じ`created_at`を持つコメントのタイブレークをid同士の文字列比較で行っていたため、`999999999`と`1000000000`のように桁数が変わる境界で後者が先に並んだ。ブラウザはこの順序を保持し、`find_editable_comment`が末尾から探すため、`e`/`d`が最新ではなく古いコメントを対象にした
- **対策**: gh APIのidは`number`で届くので、ソートキーに使うときは数値として比較する（文字列と数値が混在し得るなら両方数値のときだけ数値比較し、それ以外は文字列比較にフォールバックする）。同時刻・異なる桁数のidを並べる回帰テストを置き、順序だけでなくそれに依存する選択結果（編集対象）まで固定する
- **該当箇所**: lua/fude/comments/data.lua

### ドキュメント: 既存コードを「先例」として挙げるときはgrep結果ではなく構造を読んで確認する (PR #213, 2026-10-04)
- **問題**: 「同一性ガードはコールバック先頭に置く」というルールの先例として`init.reload`を挙げたが、実際には各取得コールバックの更新条件内と完了バリア後で確認する構造で、ルールの参照先と説明が食い違っていた。`captured_state`をgrepしてヒットしたファイルを、構造を読まずに先例として列挙していた
- **対策**: ルールの根拠として既存コードを名指しするときは、そのコードがルールの要件（位置・順序・条件）を本当に満たしているかを該当関数を読んで確認する。grepで「同じ識別子を使っている」ことと「同じ規則に従っている」ことは別で、満たさない例を挙げるとルール自体の信頼性を下げる
- **該当箇所**: .claude/review-lessons.md

### エッジケース: カーソル連動の表示が「同じ行ならskip」のキャッシュで再描画に追従しない (PR #237, 2026-10-10)
- **問題**: 複数行コメントの範囲強調を`update_inline_hint`（CursorMovedで呼ばれ、同じbuffer/lineなら早期return）に載せたため、カーソルを動かさないままreloadや再anchorで`comment_map`が変わると、削除・移動された範囲の強調と開始マーカーが次のカーソル移動まで残った
- **対策**: カーソル位置をキーに「表示済みならskip」するextmarkを足すときは、そのデータを書き換える描画経路（`refresh_extmarks`等）からも無効化・再構築する。他windowを`nvim_win_call`で描画する経路があるので、再構築は表示中のバッファに限り、カーソルのあるwindowから表示を移さない
- **該当箇所**: lua/fude/ui/extmarks.lua

### エッジケース: 入力の検証を現在のモードの処理に任せた (PR #244, 2026-10-13)
- **問題**: `set_base`は「現在のscopeで解決できるか」で新baseを検証していたが、`uncommitted`/`unpushed` scopeはbaseを読まないため、存在しないrefが保存され成功通知まで出た
- **対策**: 永続化する入力は、現在のモードがその値を使うかどうかとは別に、値そのものを検証してから保存する
- **該当箇所**: lua/fude/local/session.lua
