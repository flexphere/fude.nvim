## Project Overview

fude.nvim is a Neovim plugin for GitHub PR code review. It shows base branch diffs in a side pane, lets users create/view/reply to review comments with virtual text indicators, browse changed files via Telescope or quickfix, and view PR overviews. Requires Neovim >= 0.10 and GitHub CLI (`gh`).

## Architecture

All plugin code lives under `lua/fude/`. The plugin entry point is `plugin/fude.lua`, which registers every `:FudeXxx` user command from the `commands.lua` registry (`register_all()`) plus the `:FudeCommandPalette` palette command. Add new commands to the registry, not to `plugin/fude.lua`.

### Module Responsibilities

One short entry per module: what it owns and the invariants that are easy to break from elsewhere. The function-by-function design notes (behavior, edge cases, and why) live in `docs/architecture/<path>.md`, mirroring the module path under `lua/fude/` (e.g. `lua/fude/local/session.lua` → `docs/architecture/local/session.md`). **Read a module's notes file before changing that module.**

- **`commands.lua`** — Command registry, the single source of truth for every `:FudeXxx` user command (`M.list` entries: `name`, `desc`, `category`, `available(state)`, `run`, optional `range`/`nargs`/`complete`/`palette`/`repeatable`); `register_all()` registers them and records the last command (except `repeatable = false` entries) for `:FudeCommandRepeat` in a module-local `last_command` (not `config.state`, so it survives stop/start). Add new commands here, not to `plugin/fude.lua`; `scripts/check_docs.lua` extracts names from this file. Details: [docs/architecture/commands.md](docs/architecture/commands.md)
- **`palette.lua`** — `:FudeCommandPalette`: lists registry entries filtered by `available(state)` and `palette ~= false`, shows the first keymap whose rhs runs the command, and runs the pick via `vim.cmd` from the original window, forwarding a range only to `range = true` commands; routes by `file_list_mode` to Telescope / snacks / `vim.ui.select` with missing-plugin fallbacks. Details: [docs/architecture/palette.md](docs/architecture/palette.md)
- **`init.lua`** — GitHub review lifecycle (`start`/`stop`/`toggle`/`reload`): detects the PR, fetches files/comments/commits/user, sets autocmds, gitsigns base, diffopt and buffer-local keymaps, and prefetches the overview. Invariants: comments load outside the start barrier; `reload` runs `overview.prefetch()` outside its barrier; keymap teardown deletes only mappings whose callback is a `BUF_KEYMAPS` function; `stop()` restores the original HEAD when in commit scope (also mid commit-switch via `scope.has_pending_commit_checkout()`/`cancel_pending_switch()`); `start()` refuses while a `:FudeReviewStackSwitch` checkout (`gh pr checkout`) is in flight. Also owns `compute_merge_base` (`merge_base_sha`) and gitsigns base helpers. Details: [docs/architecture/init.md](docs/architecture/init.md)
- **`config.lua`** — Holds `defaults`, merged `opts`, and the shared mutable `state`; `reset_state()` preserves the namespace ID. Details: [docs/architecture/config.md](docs/architecture/config.md)
- **`gh.lua`** — Async wrapper around the `gh` CLI (`vim.system()`); every GitHub REST/GraphQL call goes through `run()`/`run_json()` (optional `cwd`). Invariants: REST listings pass `--paginate` (except `get_repo_issues`, `get_pr_by_commit`); on a detached HEAD `get_pr_info` uses `get_pr_by_commit` instead of `gh pr view`, and the `view_pr` helpers resolve the PR number from the commit first (`resolve_pr_number`), so `gh pr view` never runs there without an explicit PR, while the overview fetchers rely on the caller passing the PR number; every GitHub-flow writer of `state.changed_files` goes through `build_changed_files` (local review uses `local/session.build_changed_files`); the review-thread/viewed-file queries take an optional `owner/repo` slug (nil falls back to a `gh repo view` lookup of the cwd's repository) and the overview editors an optional `repo` (nil falls back to gh's cwd-resolved `repos/{owner}/{repo}` template); `get_reviews` joins an in-flight listing of the same PR and cwd. Details: [docs/architecture/gh.md](docs/architecture/gh.md)
- **`util.lua`** — Shared helpers: JSON-null handling (`is_null`/`null_to`), git path order (`path_less`), the single "all resolved" rule (`all_comments_resolved`), clipboard writes that never read `+`, the Telescope selection reset used by fude's pickers (`reset_selection_on_prompt_change`), and `open_url`. Details: [docs/architecture/util.md](docs/architecture/util.md)
- **`drafts.lua`** — On-disk storage (`stdpath("state")/fude/drafts.json`) for unsubmitted comment/PR input, distinct from the GitHub pending review; the file is the source of truth (no `config.state` field). Keys come from `make_draft_key`/`build_draft_scope` (e.g. GitHub: repo + PR; local: worktree + branch). `remove_if_unchanged` with a `revision` snapshot guards submit-success cleanup where a draft may be re-saved while the request is in flight. `list_drafts` exposes only `BROWSER_KINDS` (`pr_edit`/`pr_create`/`review` excluded). Details: [docs/architecture/drafts.md](docs/architecture/drafts.md)
- **`diff.lua`** — Local git operations (sync, except the network-bound `push_branch`): repo root, repo-relative paths, base content, merge-base, branches/worktrees, commit lists and checkout safety helpers. Invariants: `get_repo_root()` answers the local session's `worktree_root` while one is active; most helpers take an optional `cwd` that the local session fills with its worktree root (not `get_current_branch`/`get_git_user`); base content, file diff, merge-base and commit-log lookups fall back to `origin/<ref>` when the local ref is missing; `checkout` uses `--no-overwrite-ignore` and verifies where HEAD landed (`opts.branch`/`opts.detach`); `is_worktree_dirty` returns true on git failure; `get_parent` distinguishes root from a shallow boundary; `push_branch` never forces, cannot prompt on the terminal (`GIT_TERMINAL_PROMPT=0`, `detach`) and kills its process group on timeout. Details: [docs/architecture/diff.md](docs/architecture/diff.md)
- **`local/store.lua`** — Append-only JSONL event store for local review sessions (`.fude/reviews/<session-id>.jsonl`) plus the branch-keyed `.fude/current.json` pointer. Pure `materialize`/`apply_outdated`/`reanchor`/`build_*_event` (action events stamp `author_type`; deleted comments stay on disk). Pointer writes are atomic (temp + rename) and report failure, since `session.enter_commit_scope` decides whether HEAD may move on them; `read_stranded_commit_session` finds a HEAD left detached by a crash. Details: [docs/architecture/local/store.md](docs/architecture/local/store.md)
- **`local/session.lua`** — Local (pre-PR) review lifecycle parallel to `init.lua`, with scopes `base`/`unpushed`/`uncommitted`/`commit` and base switching; sets `review_mode = "local"`. The `commit` scope checks the commit out: every checkout and restore goes through `checkout_blocker`, the pending pointer is persisted before HEAD moves, the branch is restored on scope switch/`stop()`/`VimLeavePre`, and `stop()` aborts if that restore fails (`VimLeavePre` forces past a dirty tree, never past an orphaned HEAD). While `in_commit_scope()` the whole comment layer is disabled. Scope and base resolution (`resolve_scope_base`, `set_base`, `select_base`, `scope_specs`) runs its git lookups in the session's worktree root and buffers are mapped with `relative_path`, so a `:cd` out of the worktree does not break a scope switch or buffer mapping (`start()` still reads the branch and git user from Neovim's cwd). Details: [docs/architecture/local/session.md](docs/architecture/local/session.md)
- **`local/tracker.lua`** — Extmark-based line tracking of local root comments (own `fude_local_track` namespace, module-local registry); persists drift as `move` events on write. `sync_buffer`/`sync_all` and `on_buf_write` are no-ops (marks cleared) while `session.in_commit_scope()`; `teardown()` on stop and on entering that scope. Details: [docs/architecture/local/tracker.md](docs/architecture/local/tracker.md)
- **`comments/local_sync.lua`** — Local comment backend mirroring `comments/sync.lua`'s callback shape (plus `create_comment`, `move_comments`, `toggle_resolved`, `set_viewed`); synchronous JSONL appends then one re-materialize into `state.comments`/`comment_map`/`viewed_files`. Normalizes local `resolved` onto `is_resolved` (gated by `resolved.show`). In the commit scope every mutation except `set_viewed` fails with `COMMIT_SCOPE_ERROR` (enforced here because the comment browser calls it directly) and `load_comments` empties comments and clears all comment UI. Details: [docs/architecture/comments/local_sync.md](docs/architecture/comments/local_sync.md)
- **`preview.lua`** — Side-by-side diff preview: a scratch buffer with base content in a vsplit, `diffthis` on both windows, `noautocmd` for its window switches/split to prevent BufEnter cascades, and the `opening` flag guards against re-entrant `open_preview` calls. The base ref comes from the pure `find_base_ref` (local `content_ref`, else `<sha>^` in commit scope, else `state.merge_base_sha` in the full PR scope, base branch tip only as fallback) and a renamed file is read from its `previous_path` via `find_base_path` (retrying `rel_path` when that path is missing at the base ref). `open_preview` maps the source buffer with `local/session.relative_path` and reads the base content in the local session's worktree root, so in local review a `:cd` out of the worktree does not leave the preview closed (outside local mode both fall back to the cwd-based lookups); rejects nofile source windows (e.g. the side panel); `on_buf_enter` skips the rebuild for the same source window and buffer (`is_preview_current`) so fold/wrap changes survive. Details: [docs/architecture/preview.md](docs/architecture/preview.md)
- **`all_diffs.lua`** — `:FudeReviewAllDiffs`: every changed file of the current scope in one new tabpage, base/head side by side, rows aligned from the unified patches (not diff mode) so both windows use `scrollbind`/`cursorbind`. The module-local `view` keeps the `config.state` it was opened in: `jump`/`refresh` refuse once that session ended; `init.stop()`/`local/session.stop()` call `close()`. The view does not follow scope switches or reloads. Details: [docs/architecture/all_diffs.md](docs/architecture/all_diffs.md)
- **`comments.lua`** — Facade and public interface (`require("fude.comments")`) re-exporting `comments/data`, `comments/sync`, `comments/pickers`; owns navigation, create/suggest/view/reply/edit/delete and `toggle_resolve`. Dispatches mutations to `comments/local_sync.lua` when `state.review_mode == "local"`, else `comments/sync.lua`. Comment create/suggest/reply/edit/delete/resolve, the viewer, navigation and the list are refused in the local commit scope (`local/session.in_commit_scope()`). The resolved-visibility toggle affects only inline boxes; `comment_map` always keeps resolved comments. Details: [docs/architecture/comments.md](docs/architecture/comments.md)
  - **`comments/data.lua`** — Pure data functions for comments (comment map, thread lookup, pending/draft merging, browser entries, PR-level comments, comment URLs) with no state or side effects: no `config.state` and no side-effectful vim API (`vim.api`/`vim.fn`/`vim.cmd`; pure helpers like `vim.tbl_*` are allowed), enforced by `make check-purity`. Details: [docs/architecture/comments/data.md](docs/architecture/comments/data.md)
  - **`comments/sync.lua`** — GitHub comment sync/submit: `load_comments` (reviews and comments in parallel behind a barrier, plus the pending review's comments once a pending review is reported, and review threads only when `outdated.show`/`resolved.show` or a pending review needs them), pending review handling, single comments, reply/edit/delete, `toggle_resolved`, `fetch_pr_level_comments`. Applies `is_outdated`/`is_resolved` only when `outdated.show`/`resolved.show` are on; `state.resolving_thread` refuses a second resolve toggle while one is in flight; `toggle_resolved`'s gh callbacks drop responses after `reset_state()` (not every callback here checks the session). Lazy-requires `fude.ui` to avoid a cycle. Details: [docs/architecture/comments/sync.md](docs/architecture/comments/sync.md)
  - **`comments/pickers.lua`** — Entry point for `list_comments`; delegates to `ui/comment_browser.open()`. Details: [docs/architecture/comments/pickers.md](docs/architecture/comments/pickers.md)
- **`ui.lua`** — Facade and public interface (`require("fude.ui")`) re-exporting `ui/format` and `ui/extmarks`; owns the floating UIs (comment input, viewer, overview and its loading placeholder, reply/edit window, review event selector) and the draft close prompts. The `o` keys that open a comment (viewer, overview; also the comment browser) judge with the `capture_open_context()` taken when the comments were rendered, not live state, since the viewer, browser and overview can stay open across `:FudeReviewStop`. The overview's spinners draw overlay extmarks rather than rewriting buffer lines. `has_unsent_comment_input()` backs `local/session.checkout_blocker` (the commit scope is refused while unsent comment text exists), and `close_comment_ui()` closes the comment UIs when the local commit scope is entered. Details: [docs/architecture/ui.md](docs/architecture/ui.md)
  - **`ui/avatars.lua`** — Inline avatars (overview, comment UIs, reviewer picker) via snacks.nvim's image module, downloaded with curl into `stdpath("cache")/fude/avatars` (rounded when ImageMagick is available); gated by the `images` option (or the legacy `overview.avatars = true`), snacks being loadable and terminal support (`is_enabled(kind?)`). `fetch` queues callbacks per login so one image is fetched once. Details: [docs/architecture/ui/avatars.md](docs/architecture/ui/avatars.md)
  - **`ui/format.lua`** — Pure format/calculation functions (float sizes, comment display, overview lines, checks, reviewers, labels, browser layout, markdown) with no state or vim API side effects: no `vim.api`/`vim.fn`, no `config.state` (enforced by `make check-purity`; pure `vim.*` utilities such as `vim.split` are allowed). Details: [docs/architecture/ui/format.md](docs/architecture/ui/format.md)
  - **`ui/inline.lua`** — Builds bordered inline comment boxes as `virt_lines`; `[resolved thread]` and range titles go on the thread head only. Not pure (reads window text width). Details: [docs/architecture/ui/inline.md](docs/architecture/ui/inline.md)

- **`reactions.lua`** — Comment and PR reactions through `ui/toggle_picker` (`pick`, `pick_pr`, `react_at_cursor` for `:FudeReviewReact`). - **`completion/init.lua`** — Completion core for comment inputs (`b:fude_comment`) and PR bodies registered by `attach_pr` (not marked as comments, so `ui.close_comment_ui` leaves them alone): `@` mentions, `#` issues, `_` commits via `get_context`. Fetchers accept an optional request buffer (both adapters pass it) so focus changes do not retarget them; PR-body git/gh calls use the captured cwd; per-buffer context and cache are dropped on `BufWipeout`. - **`completion/blink.lua`** — blink.cmp source adapter: delegates enablement, `@`/`#`/`_` context and fetching (with `ctx.bufnr`) to `fude.completion`, ranking commits in list order. Details: [docs/architecture/completion/blink.md](docs/architecture/completion/blink.md)
- **`completion/cmp.lua`** — nvim-cmp source adapter: delegates availability, `@`/`#`/`_` context and fetching (with the request bufnr) to `fude.completion`. Details: [docs/architecture/completion/cmp.md](docs/architecture/completion/cmp.md)
- **`pr.lua`** — PR creation, editing and state changes (`create`/`edit`/`change_state`), usable without an active review (`state.active`). Details: [docs/architecture/pr.md](docs/architecture/pr.md)

### Key Patterns

- **Async flow**: GitHub API calls use `vim.system()` callbacks with `vim.schedule()` for safe UI updates.
- **State management**: All mutable state lives in `config.state`. Modules read/write this shared table directly.
- **Namespace**: The main Neovim namespace `"fude"` (created in `config.setup()`) is used for comment extmarks. Dedicated namespaces are used where isolation is needed: `"fude_sidepanel"` (sidepanel highlights, avoids `refresh_extmarks` clearing), `"fude_inline_hint"` (cursor-following hints), `"fude_refs"` (clickable references), `"fude_scope_preview"` (Telescope scope preview), `"fude_all_diffs"` / `"fude_all_diffs_syntax"` (`:FudeReviewAllDiffs` line/word and syntax highlights).
- **Window management**: Preview uses `noautocmd` commands to avoid triggering the plugin's own `BufEnter` handler during window operations.
- **Pure function extraction**: Each module exports testable pure functions separately from side-effect code. Naming convention: `build_*`, `find_*`, `parse_*`, `format_*`, `should_*`, `make_*`, `calculate_*`. These functions take all inputs as parameters and return data without reading `config.state` or calling vim API.
- **Picker-agnostic state mutators (`apply_*`)**: Functions that mutate `config.state` and interact with external APIs (e.g. `apply_viewed_state`/`apply_viewed_toggle`, `apply_reviewed_toggle`) but are independent of any specific picker implementation. They take inputs as parameters and either return the updated display fields (sync) or invoke a callback with them (async). Picker-specific adapters (`toggle_*_in_<picker>`) delegate to these mutators and handle only selection retrieval and picker refresh.

### Writing CLAUDE.md

`CLAUDE.md` is loaded into every Claude Code session, so it must stay small: `make check-claude-size` fails above 40,000 characters.

- **Put in `CLAUDE.md`**: a module's responsibility, cross-module invariants that a change elsewhere could break, the State Dependencies table, project-wide patterns and rules.
- **Put in `docs/architecture/<path>.md`**: function lists and signatures, per-function behavior, edge cases, UI wording, key bindings, and the reasons behind them. Create the file when adding a module.
- When a change only alters behavior inside a module, update its notes file, not `CLAUDE.md`. Touch the `CLAUDE.md` entry only when the responsibility or an invariant changes, and keep it to a few lines.

### State Dependencies

`config.state` の各フィールドを書き込む(W)モジュールと読み取る(R)モジュールの一覧。変更時は W/R 両方のモジュールへの影響を確認すること。

| Field | W (Write) | R (Read) |
|-------|-----------|----------|
| `active` | init, local/session | comments, comments/sync, comments/local_sync, ui/extmarks, files, scope, preview, overview, ui/sidepanel, init, pr, ui/comment_browser, local/session, local/tracker, stack, commands, reactions, all_diffs |
| `review_mode` | init, local/session | init, scope, comments, overview, files, preview, ui, ui/comment_browser, ui/sidepanel, local/session, local/tracker, stack, commands, drafts, pr, all_diffs |
| `local_session` | local/session | comments, comments/local_sync, files, scope, preview, ui/sidepanel, local/session, drafts, all_diffs |
| `pr_number` | init | init, comments, comments/sync, files, scope, pr, ui/comment_browser, drafts, stack, overview, ui/sidepanel |
| `base_ref` | init, local/session | init, preview, scope, ui/sidepanel |
| `head_ref` | init, local/session | init, scope, ui/sidepanel, local/session |

## Quality Rules (MUST follow)

1. **Before committing**: Always run `make all` and confirm lint, format-check, and tests all pass. Do NOT commit if any check fails.
2. **Tests required for new code**: When adding or modifying a function that contains testable logic (pure functions, data access, parsing, etc.), add or update corresponding tests in `tests/fude/`. Skip tests only for thin wrappers around vim API or external commands. For functions that interact with vim API (buffers, windows, extmarks) or async callbacks, write integration tests using `tests/helpers.lua`:
   - `helpers.mock_gh(responses)` — Mock `gh.run`/`gh.run_json` with pattern-keyed responses (`"args[1]:args[2]"`)
   - `helpers.mock_diff(path_map)` — Mock `diff.to_repo_relative` for test buffer names
   - `helpers.wait_for(fn, ms)` — Poll with `vim.wait()` for async callback completion
   - `helpers.cleanup()` — Restore all mocks, delete test buffers, reset state (call in `after_each`)
3. **Test coverage check**: After writing code, review whether the changed/added functions have test coverage. If not, write tests before committing.
4. **Formatting**: Run `stylua lua/ plugin/ tests/` after editing any Lua file to ensure consistent formatting.
5. **Documentation**: When adding or changing features, commands, keymaps, or configuration options, update the corresponding documentation (`README.md`, `doc/fude.txt`, the module's `docs/architecture/<path>.md`, and — only when a responsibility or invariant changes — the `CLAUDE.md` Architecture entry; see "Writing CLAUDE.md") before committing.
