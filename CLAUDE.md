## Project Overview

fude.nvim is a Neovim plugin for GitHub PR code review. It shows base branch diffs in a side pane, lets users create/view/reply to review comments with virtual text indicators, browse changed files via Telescope or quickfix, and view PR overviews. Requires Neovim >= 0.10 and GitHub CLI (`gh`).

## Architecture

All plugin code lives under `lua/fude/`. The plugin entry point is `plugin/fude.lua`, which registers every `:FudeXxx` user command from the `commands.lua` registry (`register_all()`) plus the `:FudeCommandPalette` palette command. Add new commands to the registry, not to `plugin/fude.lua`.

### Module Responsibilities

- **`commands.lua`** — Command registry, the single source of truth for every `:FudeXxx` user command. `M.list` holds one entry per command: `name`, `desc` (used as the command `desc` and the palette text), `category` (one of `M.CATEGORIES`: Session / Comments / Files / Scope / Review / View / PR), `available(state)` (whether the palette lists it for the given `config.state`: inactive → Start/Local/PR helpers, GitHub mode → also Scope*/StackSwitch/Submit/Overview, local mode → also LocalScope/Resolve; `FudeReviewStop` covers both modes since `init.stop()` delegates to the local session, so there is no separate local stop command), `run(opts)` (the user-command callback), and optional `range`/`nargs`/`complete`/`palette` (`palette = false` hides an entry from `:FudeCommandPalette` while keeping it registered — used for the two Toggle commands, which Start/Stop already cover). Command bodies that were inlined in `plugin/fude.lua` (`FudeReviewSubmit` flow, `get_pr_url`, the two display toggles) live here as local functions. `register_all()` registers every entry with `nvim_create_user_command`. `scripts/check_docs.lua` extracts command names from this file (`name = "FudeXxx"`) in addition to `plugin/fude.lua`.
- **`palette.lua`** — `:FudeCommandPalette` command palette. Pure helpers: `rhs_invokes_command(rhs, name)` (does a mapping rhs run the command as its *first* Ex command — the rhs must start with an optional `<Esc>`, then `<Cmd>` or `:`, optional `<C-u>` / `'<,'>`, then the name followed by a non-identifier character; the wrapper is matched case-insensitively but the name exactly, since user commands are case-sensitive. Anchoring at the start, rather than scanning the rhs, is what rules out names inside string literals or after a `|` separator without an Ex parser; a mapping that runs the command only after `|` is deliberately not reported), `find_keymap_for_command(keymaps, name)` (first matching lhs; Lua-callback mappings have no rhs and are skipped), `build_palette_entries(cmds, state, keymaps, category_order?)` (filters by `available(state)` and `palette ~= false`, attaches the key, orders by category then registry order), `calculate_palette_widths(entries)` / `format_palette_entry(entry, widths)` (aligned `[Category]  desc  :Name  key` line for `vim.ui.select`; in Telescope/snacks the category is `Title`, the description normal, the name `Comment`, the key `Special`), `calculate_palette_layout(widths, count, columns, lines)` (absolute window size: widest row + padding, `count + 5` rows, clamped to the editor — Telescope uses it through `themes.get_dropdown`, snacks through the `select` preset, both without a preview pane so the palette stays a compact centered menu regardless of the user's picker defaults), `format_key_lhs(lhs, mapleader)` (restores the `<leader>` token that `nvim_get_keymap` expands). Side effects: `collect_keymaps(modes, buf)` (buffer-local then global mappings with lhs passed through `format_key_lhs`, skipping a global mapping whose lhs is shadowed by a buffer-local one; `x` mode is included when the palette was opened with a range), `execute(entry, ctx)` (runs the command via `vim.cmd({ cmd = name, range = ... })` from the window the palette was opened in, forwarding `ctx.range` only to `range = true` commands), `resolve_visual_range()` (when visual mode is still active — a `<Cmd>FudeCommandPalette<CR>` mapping passes no range — leaves visual mode and returns the `'<`/`'>` line range), `open(opts)` (`opts.range = { line1, line2 }` from `:'<,'>FudeCommandPalette`, else derived via `resolve_visual_range`; routes to `show_telescope` / `show_snacks` / `show_vim_select` by `file_list_mode`, with the same missing-plugin fallbacks as `scope.lua`).
- **`init.lua`** — Plugin lifecycle (`start`/`stop`/`toggle`/`reload`). On start: detects PR via `gh`, fetches changed files, comments, PR commits (for scope selection), and authenticated user (for edit/delete ownership), saves original HEAD SHA, sets up `BufLeave` (saves source views through `files.save_view`)/`BufEnter`/`WinClosed`/`GitSignsUpdate` autocmds, integrates with gitsigns (per-buffer base selection), applies diffopt settings, sets buffer-local keymaps (`]c`/`[c` for comment navigation, `]F`/`[F` for unviewed-file navigation — declared together in the module-local `BUF_KEYMAPS` table so `setup_buf_keymaps`/`clear_buf_keymaps` stay in step, each one skipped when its `config.opts.keymaps` entry is `false`; teardown deletes a mapping only when its callback is one of the `BUF_KEYMAPS` functions, not by the configured lhs or by `desc`, so a same-key mapping owned by an ftplugin in a buffer review mode never entered survives even if it copies fude's description text), and starts auto-reload timer if configured. `reload` re-fetches comments, changed files, viewed states, and PR commits in parallel with a completion barrier. On stop: stops auto-reload timer, restores original HEAD if in commit scope — including a commit switch whose checkout ran but whose gh callback is still in flight (`scope.has_pending_commit_checkout()`), cancelling that switch via `scope.cancel_pending_switch()` so its late callback cannot act — tears everything down, removes buffer-local keymaps, and restores original state. `start()` refuses via `stack.refuse_while_switching()` while a `:FudeReviewStackSwitch` checkout is in flight. Exports helpers: `is_new_file(rel_path, changed_files)` checks if a file is newly added in the PR; `apply_gitsigns_base_for_buffer()` sets per-buffer gitsigns base (new files use `base_ref`, existing files use `merge_base_sha` to exclude merge commit noise, skipped when `gitsigns_reset` is true; in local review mode every file uses `merge_base_sha`, since each local scope resolves to one SHA and `base_ref` is the base *branch*, which may be nil or hold a same-named file; the buffer is mapped with `local/session.relative_path`, so a `:cd` out of the worktree does not skip every buffer); `compute_merge_base(base_ref)` computes and caches the merge-base SHA; `update_gitsigns_base(base_ref)` sets global gitsigns base (used for commit scope); `toggle_gitsigns()` toggles gitsigns between PR base and HEAD; `restore_gitsigns_base()` restores gitsigns to PR base display.
- **`config.lua`** — Holds `defaults`, merged `opts`, and mutable `state` (active flag, PR metadata, window/buffer handles, comments, pending_comments, pending_review_id, pr_node_id, viewed_files, github_user, namespace ID). `reset_state()` preserves the namespace ID.
- **`gh.lua`** — Async wrapper around `gh` CLI using `vim.system()`. All GitHub API calls go through `run()`/`run_json()` with callback-based async pattern. Uses `repos/{owner}/{repo}` path templates for REST API (resolved by `gh` automatically) and `gh api graphql` for GraphQL API (used by viewed file management and review thread info: `get_review_threads` returns a `thread_info_map` with per-thread `is_outdated`/`is_resolved` flags plus a comment→thread node ID map). Supports stdin for JSON payloads (used by `create_review()`). `get_pr_info` detects detached HEAD synchronously via `git symbolic-ref` and uses `get_pr_by_commit` (via `commits/{sha}/pulls` API) directly, avoiding `gh pr view` which may hang without a branch. `parse_pr_from_commit_api` converts the commits API response to the standard PR info format. `get_pr_stack(pr_number, cb)` fetches every PR of the PR's GitHub stack in one GraphQL query (`pullRequest.stack.entries(first: 100)`), parsed bottom-first by the pure, type-defensive `parse_pr_stack` (nil when the PR is in no stack); `checkout_pr(pr_number, cb)` wraps `gh pr checkout`.
- **`util.lua`** — Shared utility functions. `is_null(v)` checks for both `nil` and `vim.NIL` (JSON null compatibility across Neovim 0.11/0.12). `null_to(v, default)` replaces a JSON null with `default` (use it instead of the `and-or` idiom, which cannot map null to nil). `all_comments_resolved(comments)` checks whether every comment in a list is resolved (false for empty lists); shared by `comments/data.lua`, `ui/format.lua`, and `ui/extmarks.lua` so the "all resolved" rule stays consistent.
- **`drafts.lua`** — Local on-disk storage for *unsubmitted* comment input ("drafts"), distinct from the in-session GitHub pending review (`state.pending_comments`). Persists to `stdpath("state")/fude/drafts.json` so input can be paused (jump back to the diff) and resumed later, across PR switches and Neovim restarts. Pure functions (no state/IO): `make_draft_key(repo, pr_number, kind, ...)` builds opaque keys (kind = `line`/`suggest`/`issue`/`reply`/`edit`/`pr_edit`), `repo_slug(pr_url)`, `serialize`/`deserialize` (corrupt JSON → `{}`), `prune(drafts, now, retention_days)`. IO/state helpers: `current_key(kind, ...)` (derives repo/PR from `config.state`), `enabled()` (reads `config.opts.drafts.enabled`), `load`/`save`/`get`/`set`/`remove`/`remove_if_unchanged` (file is the source of truth — no `config.state` field; `set` with empty body removes, `load` prunes by `config.opts.drafts.retention_days`; `remove_if_unchanged(key, snapshot)` guards async submit-success cleanup so a draft re-saved while the request was in flight survives), `file_markers(rel_path)` (one load → `{ lines, comment_ids }` used by `ui/extmarks.lua` to render the `draft` indicator: `line`/`suggest` drafts mark their own line, `reply`/`edit` drafts mark the targeted comment's line via the comment map), and `list_drafts()` (one load → array of `{ key, kind, body, saved_at (normalized to ISO), path?, start_line?, end_line?, comment_id? }` for the active PR, used by the comment browser; browser-facing kinds only via the `BROWSER_KINDS` whitelist — `pr_edit` is excluded; skips non-string bodies). `M._dir` overrides the storage dir for tests. Wired into comment creation/reply/edit in `comments.lua`, PR-level comments in `overview.lua`, and the `comment_browser` lower pane (prefill on entry navigation via `lower_key_for_entry`, save/discard on close, snapshot-guarded remove on submit success via `remove_if_unchanged`) and list (draft rows + markers via `merge_draft_entries`). Comment input UIs receive `opts.allow_draft`/`initial_lines`/`on_save_draft`/`on_discard_draft` and report the close action (`submit`/`draft`/`discard`/`cancel`). `pr.lua`'s edit float also persists here (kind `pr_edit`, one entry per repo + PR, title on line 1) — the key is built via `make_draft_key` with the repo slug from the PR url (not `current_key`, which needs an active session); `pr_edit` entries are deliberately absent from the comment browser (excluded by `list_drafts`'s browser-kind whitelist `BROWSER_KINDS`) and from `file_markers` (prefix mismatch).
- **`diff.lua`** — Local git operations (sync). Gets repo root, converts paths to repo-relative (`make_relative(filepath, root)` is boundary-aware: `/repo-other/x.lua` is not under `/repo`), retrieves base branch file content via `git show`, generates file diffs, and computes merge-base for gitsigns (avoids merge commit noise). Falls back to `origin/<ref>` when local ref isn't available. Also provides local-session helpers: `get_current_branch`, `get_head_sha`, `get_empty_tree(cwd?)` (empty-tree hash, diff base for zero-commit repos and root commits; `cwd` matters because the hash depends on the repo's object format, SHA-1 vs SHA-256), `get_head_sha(cwd?)`, `get_upstream_ref(cwd, branch?)` (`@{upstream}`, diff base for the unpushed scope; `branch` resolves `<branch>@{upstream}` instead, needed while the local commit scope holds HEAD detached), `get_remote_branches` (`origin` remote-tracking branch names via `git for-each-ref`, most recently committed first, `HEAD` excluded by the pure `parse_remote_branches`; used by `pr.lua`'s base branch picker), `get_gh_stack_parent(branch)` (reads gh-stack's local `.git/gh-stack` JSON from the common git dir — not `gh stack view`, which hits the network — parsed by the pure, type-defensive `parse_gh_stack_parent`: previous branch in the stack, or its trunk for the bottom branch), `get_ancestor_branches(default_branch)` (`origin` branch tips in `<default>..HEAD`, nearest first, from a single `git log --format=%H%x00%P%x00%D --decorate-refs=refs/remotes/origin/` walk parsed by the pure `parse_ancestor_log`, which orders tips by the number of in-range commits each cannot reach (`rev-list --count <tip>..HEAD` limited to the range) computed from the parent links, since log order — even `--topo-order` — does not follow the distance across merges; one process regardless of the branch count; empty when the default ref is unresolvable, since otherwise every branch in HEAD's history would match), `get_worktree_roots(cwd)` (every non-bare worktree directory, detached ones included, parsed by the pure `parse_worktree_roots`; the repo root is passed explicitly so the answer survives a mid-session `:cd` — used by `local/session` for buffer ownership), `get_worktrees()` (`git worktree list --porcelain` parsed by the pure `parse_worktree_list`, which keeps `{ path, branch }` and skips bare/detached entries — prunable ones are kept because git still reserves their branch until `git worktree prune`, so `stack.switch_to` refuses them via its missing-directory check instead of failing in `gh pr checkout`; nil + err when git fails, so a failure is not mistaken for "no worktree has the branch"), `get_git_user`, `get_name_status`, `get_numstat`, `get_untracked`, `get_review_patch` (the last four take a `cwd` repo root so paths resolve from a subdirectory). Commit-scope helpers: `parse_commit_log` (pure; `%H%x1f%h%x1f%s` lines → `{ sha, short_sha, subject }`, the `\31` separator keeping subjects with tabs/pipes intact), `get_commit_log(base_ref, tip, cwd, limit?)` (takes the tip explicitly so the list survives a detached checkout; retries `origin/<base_ref>` when the base exists only on the remote, like `get_merge_base`; a nil base lists every commit of `tip`, `limit` keeps the newest N of the range, still oldest first), `is_worktree_dirty(cwd)` (`git status --porcelain -uno`; true on git failure so no checkout runs over unknown state), `checkout(ref, cwd)`, and `get_parent(sha, cwd)` → `parent_sha|nil, "parent"|"root"|"missing"|"error"` (reads the raw object header via the pure `parse_commit_parents` and then checks the parent object exists, because `rev-parse <sha>^` fails for both a true root and a shallow clone's boundary commit, and only the former may diff against the empty tree).
- **`local/store.lua`** — Append-only JSONL event store for local (pre-PR) review sessions, persisted inside the worktree (`.fude/reviews/<session-id>.jsonl` + `.fude/current.json` pointer; `M._dir` overrides the base dir for tests). One JSON event per line; kinds: `session`/`comment`/`reply`/`edit`/`move`/`resolve`/`reopen`/`delete`/`viewed`. Pure functions: `generate_uuid`, `make_session_id`, `serialize_event`, `parse_event_line`/`parse_events` (corrupt lines skipped), `materialize(events)` (rebuilds GitHub-compatible comment objects + thread resolved state + a per-path viewed map; replies inherit the root's path/line including moves; deleted comments are hidden but stay on disk as audit trail), `apply_outdated(comments, line_counts)` (file gone or line > EOF → `is_outdated`), `reanchor(comments, file_lines_map)` (context-based re-anchor: moves a comment to the unique location of its saved `context` block, re-propagates to replies, returns the moves to persist), and `build_*_event` constructors — every action-event constructor (`build_comment_event`/`build_reply_event`/`build_edit_event`/`build_move_event`/`build_status_event`/`build_delete_event`/`build_viewed_event`) stamps `author_type` (`opts.author_type or "human"`); `build_session_event` intentionally does not, since the session header is metadata, not a user action. IO: `append_event`, `read_events`, and the current-session pointer helpers `write_current(root, branch, session)`/`read_current(root, branch)`/`clear_current(root, branch)` (returns `ok, err`; a no-op success when the entry is absent; both pointer writes go through `write_json_lines`, which treats `writefile`'s `-1` as a failure, not only a thrown error, since `session.enter_commit_scope` decides whether HEAD may move on this result), plus `read_stranded_commit_session(root, head_sha)` over the pure `find_stranded_commit_session(map, root, head_sha)` (the commit-scope entry whose persisted `scope_commit_sha` — or `pending_from_sha`, the commit HEAD was still on while a commit-to-commit checkout was pending — equals HEAD and that carries an `original_branch` — how `session.start()` recognises a HEAD left detached by a crash, since the branch-keyed lookup with a nil branch would miss it). `.fude/current.json` is a **branch-keyed map** (`{ [branch] = session }`) so reviewing several branches in the same worktree doesn't collide; a legacy flat single-session pointer is migrated on read.
- **`local/session.lua`** — Local review session lifecycle, parallel in shape to `init.lua` start/stop/reload. `start(base)` resolves the base ref (arg → `current.json` → default branch), computes the diff base from the scope, synthesizes `changed_files` from `git diff --name-status/--numstat` + untracked files (pure helpers: `status_word`, `resolve_rename_path`, `parse_name_status`, `parse_numstat`, `build_changed_files`), creates or resumes the session for the current branch (`.fude/current.json` is keyed by branch, so different branches in one worktree get separate sessions), sets state (`review_mode = "local"`, `local_session`), reuses `init.setup_review_autocmds`, registers local-only autocmds (BufWritePost re-anchor, BufEnter/BufReadPost tracker sync — mapped with `relative_path`, so a buffer opened after a `:cd` out of the worktree is still tracked), and starts the auto-reload timer. `stop()` tears down and clears `current.json` (the JSONL file is kept); when the pointer cannot be removed it still tears down but reports a WARN naming the entry to delete by hand, since the next start on that branch would otherwise resume the stopped session. `toggle(base)` stops an active local session or starts one (refuses while a GitHub review is active). `reload(silent)` re-reads git state and the JSONL synchronously. **Scope**: `local_session.scope` is `"base"` (merge-base with the base branch — whole branch diff), `"unpushed"` (the `@{upstream}` tracking ref — changes not yet pushed), `"uncommitted"` (HEAD — staged + unstaged only), or `"commit"` (one commit of the branch, `<sha>^` vs `<sha>`, identified by `scope_commit_sha`/`scope_commit_index`). The first three compare the working tree against a ref, so comments stay anchored. The commit scope instead *checks the commit out* (module-local `enter_commit_scope`: persists the pending destination to `current.json` via `persist_current(session, overrides)` *before* the checkout — with `pending_from_sha`, the commit HEAD still sits on during a commit-to-commit switch, so a crash before the checkout lands is matched too — so a crash in between still leaves a pointer `start()` can match against HEAD, rewrites the previous pointer on failure, and records `original_branch` on the session only after the checkout succeeded so a failed first attempt leaves nothing for `restore_head` to undo), exactly like the GitHub flow's commit scope, so changed files, preview, gitsigns and `files.open_file` work through the existing paths; two consequences follow. (1) HEAD moves: every checkout — not only the first — is refused by `checkout_blocker` when a comment input holds unsent text (`ui.has_unsent_comment_input`: a `b:fude_comment` float shown in a window, the reply/edit window's lower pane, or the comment browser's lower pane — the scope's teardown would wipe it), when the worktree has staged/unstaged changes (`diff.is_worktree_dirty`), or when a loaded buffer owned by the worktree is modified (`has_unsaved_buffers_under` over `file_buffers_under`, which resolves ownership as the deepest worktree root containing the file via `stack.find_owning_root` and `diff.get_worktree_roots(session.worktree_root)` — detached worktrees included, listed from the session root rather than Neovim's cwd — so a worktree nested inside this one, `.claude/worktrees/x`, neither blocks nor gets reloaded), since `git status` cannot see unsaved buffers and `reload_open_buffers` must skip them, or — on a commit-to-commit switch and on every restore — when HEAD is no longer `scope_commit_sha` (the user committed on the detached HEAD; checking out away from it would orphan that commit, so the blocker asks for `git branch <name>` first, the dirty-tree message says "stash or discard" rather than "commit", and not even `VimLeavePre`'s `force` overrides this one, since a detached HEAD on the user's own commit is the state they chose); entering is also refused when the pending pointer write fails, since a crash could then never find the way back; the branch is recorded in `session.original_branch` on entry (with `scope_before_commit`, the scope to write back later) and put back by `restore_head` on scope switch, `stop()` and `VimLeavePre`; `restore_head` applies the same `checkout_blocker` and refuses on a scope switch or `stop()` — unsaved buffers cannot be carried back by git and the reload skips them, so they would overwrite the branch on the next save — while `VimLeavePre` passes `force = true` (a dirty tree is the lesser evil than a detached HEAD the user did not ask for, so it warns and continues) and `reload_buffers = false` (re-reading buffers only slows the exit); after a successful restore it rewrites the pointer with `scope_before_commit` so a later deliberate detach onto the same SHA is not mistaken for a crash (`persist_non_commit_or_clear`: when that write fails the pointer is removed instead via `store.clear_current`, whose `ok, err` result is checked — if even the removal fails the ERROR names the stale entry and how to delete it by hand — losing a resume beats leaving a stale commit entry — and the same helper rolls back the pending pointer after a failed checkout); `stop()` runs the restore *first* and aborts — session kept, like `init.stop()` on a failed HEAD restore — when it fails, so `original_branch` and `current.json` survive for a retry; a persisted `commit` scope is never resumed by `start()`. `persist_current` also stores `scope_commit_sha`/`original_branch`, so when `start()` finds no branch and HEAD equals a persisted commit-scope entry's commit (`store.read_stranded_commit_session`: a crash while a commit was checked out), it returns to that `original_branch` first — refusing with an ERROR and a manual `git checkout` hint when `checkout_blocker` reports a dirty tree — rewrites the pointer to a non-commit state right after the checkout (before buffers reload; `persist_non_commit_or_clear`), and then resumes the branch's session normally; any other detached HEAD is treated as the user's own. Buffer reloads after a checkout (`reload_open_buffers`) touch only unmodified file buffers under the worktree (`file_buffers_under`, shared with the unsaved check). `scope_specs` asks `diff.get_upstream_ref(root, session.original_branch)` so the unpushed entry stays available as a way back while HEAD is detached. (2) The right side is a past snapshot, not the working tree comments anchor to, so the whole comment layer is disabled while the scope is active: `in_commit_scope()` gates `comments.lua` (create/suggest/reply/edit/delete/resolve/view/next/prev/list), the `local_sync` mutations (so the comment browser's direct backend calls are refused too), `local/tracker`, `ui/extmarks`, and the re-anchor/outdated passes in `local_sync.load_comments`. `resolve_scope_base(scope, base_ref, cwd, commit_sha)` returns the `git diff` base and the `git show` content ref (nil when the scope is unavailable); every scope returns the same ref for both, on `base` that is the merge-base rather than the base branch tip, so the changed-files list, the per-file patches, the gitsigns base and the preview's base pane all stay on the same commit even after the base branch moves on (matching the three-dot semantics the GitHub flow gets from `merge_base_sha`), and on `commit` it is the parent SHA from `diff.get_parent`, the empty tree for a true root commit, and nil (switch refused) when the parent is recorded but unreachable, as at a shallow clone's boundary. The commit list is cached on `session.commits` by `refresh_commits` (called from `start`/`reload`, skipped while a commit is checked out) because `scope_specs` runs on every side panel render; its range comes from the pure `resolve_commit_range_base(base_ref, branch, upstream)` — the base branch on a feature branch, else the upstream (unpushed commits on the base branch itself), else every commit (remote-less fresh repo, the one path on which a root commit appears), capped at the newest `COMMIT_LIST_LIMIT` (100) in that unbounded case so a long-lived remote-less repo does not pour its history into the side panel — with the tip being the branch name so the list survives a detached HEAD. `scope_specs(session)` builds the adaptive list of available scopes with labels (base only on a non-base branch; unpushed only with an upstream; uncommitted always; one `commit` entry per cached commit via the pure `build_commit_specs`, flagged current by SHA). `set_scope(scope, opts)` (`opts.commit_sha` for the commit scope) orders HEAD move and base resolution by direction: into a commit it resolves first (`<sha>^`/empty tree need no checkout) and moves HEAD only on success, so a failure leaves everything untouched; out of a commit it restores HEAD *before* resolving — `unpushed` reads `@{upstream}`, which does not resolve while detached — and on an unresolvable base re-enters the previous commit, restoring the `scope_before_commit` the restore had cleared so the pointer keeps the scope the user came from (or, when that second checkout fails, lands on `uncommitted` rather than claiming a commit scope it no longer shows); the module-local `apply_scope` then records the scope, reloads changed files/comments, re-applies the gitsigns base and preview, and updates the statusline (`Local: <i>/<n>` for commits). It returns true only when the scope actually changed (false on no session / unknown scope / same scope / unresolvable base — the sidepanel uses this to decide whether to auto-open the first file); `select_scope()` is the `vim.ui.select` picker (its callback checks that `state.local_session` is still the session the picker was built for, since a picker left open across stop → start would otherwise check out the old branch's commit from the new session).
- **`local/tracker.lua`** — Extmark-based line tracking for local review comments (dedicated `fude_local_track` namespace so `refresh_extmarks` never clears it). `sync_buffer`/`sync_all` place invisible extmarks for root comments; `collect_moves(buf)` computes drifted positions from extmark rows; `on_buf_write(buf)` persists drift as `move` events via `local_sync.move_comments`. Both are no-ops (marks cleared) while `session.in_commit_scope()`, since the buffer then shows a checked-out past commit, not the lines the comments anchor to; entering that scope calls `teardown()` outright, since `sync_all` only reaches buffers it can map to the repo. `sync_all` maps buffers with `session.relative_path` (the session's worktree root, not Neovim's cwd). `teardown()` clears marks on session stop. Module-local registry, not `config.state`.

- **`overview.lua`** — PR overview display: fetches extended PR info and issue-level comments, renders in a centered float with keymaps for commenting, refreshing, and re-requesting a review (`r` selects a reviewer who already reviewed via `vim.ui.select` and posts to the `requested_reviewers` endpoint through `gh.re_request_review`).
- **`completion/init.lua`** — Completion source for comment input buffers. Provides mention (`@user`), issue/PR (`#nnn`), and commit SHA completion candidates via `fetch_mentions`, `fetch_issues`, `fetch_commits`, with a 5-minute TTL cache. `build_commit_items(commit_entries)` is a pure helper that formats commit entries into completion items; `get_context(line_before_cursor)` parses the trigger character (`@`/`#`/sha prefix). Reads `state.pr_commits` (only) for commit completion freshness invalidation.
- **`pr.lua`** — PR creation and editing. `M.create()` creates draft PRs from templates: first shows a base branch picker (`select_base_branch`, entries from the pure `build_base_branch_entries(branches, default_branch, { current_branch, stack_parent, ancestors })` — default branch first with a `(default)` marker so a fresh `<CR>` accepts it (only when it is on the remote, or when there are no remote branches at all — `diff.get_default_branch` may fall back to a local-only `main`/`master`), then related branches (`(stack parent)` from `diff.get_gh_stack_parent`, then `(ancestor)` from `diff.get_ancestor_branches`; only those present on the remote, deduplicated), then the rest of `diff.get_remote_branches()` (newest commit first); the current branch is never listed; skipped with `base = nil` when there are no candidates, cancel aborts), then searches for `PULL_REQUEST_TEMPLATE` files in standard GitHub locations, shows Telescope picker when multiple templates exist (`select_template`; all pickers share the module-local `pick_entry`, Telescope when available else `vim.ui.select`, with the template preview passed lazily via `make_previewer`; the base branch and stack pickers pass `compact = true` for a dropdown sized by the pure `calculate_compact_picker_height`), and opens a two-pane float (title + body) for composing the PR. The chosen base decides the default title (`diff.get_first_commit_subject(base)`, which tries `origin/<base>` before the local ref so a stale local branch of the same name does not shift the commit range), is shown in the footer built by the pure `build_footer_text(mode, from_draft, base, stack)` (`<CR> create draft → main | q cancel`), and is forwarded as `opts.base` to `gh.create_draft_pr(title, body, attachments, base, cb)` (`--base` only when non-nil). Picking the default base asks nothing; any other base asks `confirm_stack(base, cb)` (a Yes/No picker through the shared `pick_entry`, entries from the pure `build_stack_choices()` with Yes first so a bare `<CR>` accepts it; cancel aborts); a Yes runs the module-local `resolve_stack` before the float opens: `gh.get_open_pr_stack(base)` (one GraphQL query for the open PRs of the branch ref, `repository.ref("refs/heads/<base>").associatedPullRequests` — the repo's own ref, so fork PRs sharing the branch name never appear and no result limit can hide the parent — and its `stack`, parsed by the pure `gh.parse_open_pr_stack`; "no PR" is an empty result, not an error string) — a parent PR at the top of a stack is stacked directly (below the top — decided from `stackEntry.position` vs `stack.size`, since a stack only grows at its top — asks `confirm_non_top_stack(base, top_branch, stack_number, cb)`, a compact picker from the pure `build_non_top_choices`: an ordinary PR on `base`, or a stacked PR on the stack's top branch from `gh.parse_stack_top`, which replaces `base`; cancel aborts), one in no stack starts a new stack without asking again (the user already answered Yes), and no open parent PR or a failed lookup (reported with gh's error) is a WARN that continues as an ordinary PR. Stacking sets `opts.stack = { parent_url, new_stack }`, which adds `(stacked)` or `(new stack)` to the footer and, after a successful create, runs the module-local `link_to_stack`: `gh.link_stack(refs, base, cb)` (`gh stack link`, independent of gh-stack's local tracking) with `{ <stack number>, new_url }` for an existing stack (append mode — without a stack number gh-stack's update mode requires every PR already in the stack and fails otherwise) or `{ parent_url, new_url }` plus `--base <parent's baseRefName>` for a new stack (gh-stack otherwise retargets the bottom PR to the default branch). The parent is passed as its PR URL, never a branch name, because `gh stack link` would push a branch argument and open a PR for it; a link failure is a WARN that leaves the created PR unstacked. Submits via `gh pr create --draft`. `M.edit()` edits existing PR title/body: uses `state.pr_number` when review mode is active, otherwise detects via `gh pr view`. Both functions are independent of review mode (`state.active`). Cancel confirmation: pressing `q` with unsaved title/body changes (dirty = `ui.should_confirm_discard` on either pane against the lines the float opened with) shows `ui.prompt_close_decision` with PR wording ("Unsaved PR:" / "Discard changes?"); create mode saves to the session-local draft (`save_draft`/`get_draft`/`clear_draft`, surfaced as the `(draft)` picker entry), edit mode persists to `drafts.json` via kind `pr_edit` (key from `drafts.make_draft_key` + `repo_slug` of the PR url fetched by `gh.get_pr_title_body` — state-independent; no slug → Yes/No fallback), serialized by the pure helpers `serialize_edit_draft(title_lines, body_lines)` (title on line 1, space-joined like `parse_pr_buffer`) / `parse_edit_draft(text)`, prefilled on the next `M.edit()` (footer shows "draft restored", dirty baseline = the restored draft) and removed on successful `gh.edit_pr` — unless a draft was explicitly saved while the request was in flight (the float stays open during the request; a flag, not content comparison, so re-saving identical content also survives). The create success path guards `clear_draft` the same way (table-reference compare of the session draft). Closing a float window directly (`:q` etc.) still discards without confirmation (WinClosed path). Body attachments: on submit, `parse_body_attachments(body, expand_fn)` (pure) extracts `file://`-scheme paths from inline markdown link/image destinations — bare or angle-bracket form (skipping ```/~~~ fenced code blocks via a fence-marker tracker that closes only on a bare same-marker line; paths may contain spaces and parentheses, while a path containing `#` — gh's alt-text separator — or `<`/`>` is left untouched), strips the `file://` prefix from the body, rewrites paths with spaces or parentheses in the CommonMark `<...>` destination form (gh's CommonMark parser cannot match a bare destination with those characters and would append instead of rewrite), rewrites different spellings of the same file to the first-seen spelling, and the resulting deduplicated paths are passed to `gh` as repeated `--attach` flags (gh >= 2.99.0; gh rewrites matching body references to uploaded URLs). A local `expand_home` expands a leading `~/` via `vim.uv.os_homedir()` (deliberately not `vim.fn.expand`, which executes backticks/globs) so the body reference and `--attach` argument stay identical. `format_attach_error(err)` replaces `unknown flag: --attach` usage dumps with a concise gh-upgrade hint; `format_attach_suffix(count)` builds the "(N files attached)" suffix for success notifications. Paste conversion: while the float is open, `vim.paste` is wrapped (restored in `close_all`; there is no paste autocmd event) so a local media path pasted into the body pane becomes `![](file://path)` — pure helpers `clean_pasted_path` (strips quotes/escaped spaces), `is_local_media_path` (prefix + extension check), and `transform_media_paste(lines, before_cursor)` (context-aware: bare path after `file://`, `file://`+path after `](`); streamed paste phases are accumulated before deciding.

### Key Patterns

- **Async flow**: GitHub API calls use `vim.system()` callbacks with `vim.schedule()` for safe UI updates.
- **State management**: All mutable state lives in `config.state`. Modules read/write this shared table directly.
- **Namespace**: The main Neovim namespace `"fude"` (created in `config.setup()`) is used for comment extmarks. Dedicated namespaces are used where isolation is needed: `"fude_sidepanel"` (sidepanel highlights, avoids `refresh_extmarks` clearing), `"fude_inline_hint"` (cursor-following hints), `"fude_refs"` (clickable references), `"fude_scope_preview"` (Telescope scope preview).
- **Window management**: Preview uses `noautocmd` commands to avoid triggering the plugin's own `BufEnter` handler during window operations.
- **Pure function extraction**: Each module exports testable pure functions separately from side-effect code. Naming convention: `build_*`, `find_*`, `parse_*`, `format_*`, `should_*`, `make_*`, `calculate_*`. These functions take all inputs as parameters and return data without reading `config.state` or calling vim API.
- **Picker-agnostic state mutators (`apply_*`)**: Functions that mutate `config.state` and interact with external APIs (e.g. `apply_viewed_toggle`, `apply_reviewed_toggle`) but are independent of any specific picker implementation. They take inputs as parameters and either return the updated display fields (sync) or invoke a callback with them (async). Picker-specific adapters (`toggle_*_in_<picker>`) delegate to these mutators and handle only selection retrieval and picker refresh.

## Quality Rules (MUST follow)

1. **Before committing**: Always run `make all` and confirm lint, format-check, and tests all pass. Do NOT commit if any check fails.
2. **Tests required for new code**: When adding or modifying a function that contains testable logic (pure functions, data access, parsing, etc.), add or update corresponding tests in `tests/fude/`. Skip tests only for thin wrappers around vim API or external commands. For functions that interact with vim API (buffers, windows, extmarks) or async callbacks, write integration tests using `tests/helpers.lua`:
   - `helpers.mock_gh(responses)` — Mock `gh.run`/`gh.run_json` with pattern-keyed responses (`"args[1]:args[2]"`)
   - `helpers.mock_diff(path_map)` — Mock `diff.to_repo_relative` for test buffer names
   - `helpers.wait_for(fn, ms)` — Poll with `vim.wait()` for async callback completion
   - `helpers.cleanup()` — Restore all mocks, delete test buffers, reset state (call in `after_each`)
3. **Test coverage check**: After writing code, review whether the changed/added functions have test coverage. If not, write tests before committing.
4. **Formatting**: Run `stylua lua/ plugin/ tests/` after editing any Lua file to ensure consistent formatting.
5. **Documentation**: When adding or changing features, commands, keymaps, or configuration options, update the corresponding documentation (`README.md`, `doc/fude.txt`, `CLAUDE.md` Architecture section) before committing.
